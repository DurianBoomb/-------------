## 需求

修改文档 `docs/问卷置顶系统/问卷置顶系统（草稿）.md`，将广告回调流程从"服务端回调接口"模式全面改写为"客户端 wx.onRewarded() 触发后调云对象"模式。2.3 节已在上一轮修改中正确描述了广告回调流程，不需改动。

## 技术方案

### 修改策略

基于微信小程序激励视频广告的 actual API 约束，替换文档中所有"服务端回调端点"、"广告平台二次验证凭证"等不存在的假设。

### 各章节具体修改方案

#### 1. 4.5 入池逻辑（current line 256）

**原文**："该接口由广告回调触发，执行完整的入池判断流程"
**改为**："该接口由前端在用户看完激励视频广告后调用。前端确认广告播放完毕（onRewarded 事件触发）后，调云对象方法发起入池请求"

#### 2. 5.4 候场区接口·接口二：执行加速（current line 376）

**原文**："调用时机：用户在候场终端界面看完激励视频广告后，由广告回调触发。"
**改为**："调用时机：用户在候场终端界面看完激励视频广告后，前端确认广告播放完毕（onRewarded 事件触发），调云对象执行加速。"

#### 3. 8.4 广告回调接口通用设计（current lines 661-681）-- 完全重写

整节改为"广告观看流程"章节，描述：

- **客户端组件声明**：前端在页面中声明 `wx.createRewardedVideoAd()` 组件
- **播放与回调**：广告播放完毕后通过 `onRewarded()` 事件触发，前端在此回调中确认观看有效
- **调用云对象**：前端在 `onRewarded()` 中调云对象方法，传入 userId + 场景编码 + 关联业务数据
- **防伪机制**：**无广告平台二次验证 API 可用**，云对象仅接收前端请求，靠服务端频率限制（单用户 N 次/分钟）兜底，客户端侧记录广告播放时长辅助判伪
- **入参精简**：去掉"广告平台返回的校验凭证"字段，改为"客户端记录的广告播放时长（毫秒，防秒关用）"
- **返回结构**：与原来一致

#### 4. 8.5 防刷与风控（current line 691）

**原文**："服务端二次校验广告平台回调凭证（优先依赖广告平台能力）"
**改为**："客户端侧广告播放时长校验（低于 N 秒视为无效观看）+ 服务端请求频率限制（单用户每分钟/每小时最多 N 次置顶请求）"

#### 5. 9 附录待办

原待办 6 "全局配置（8.5）广告观看次数的防刷与风控具体策略" 保留。8.4 标题改名后，附录中无需改（因为附录引用的是 8.5，不是 8.4）。
