## 需求概述

为工作台（workbench.vue）中的每个问卷卡片实现分享功能，用户通过分享链接进入后可以作答该问卷。同时将现有的测试答题页（editor-quztest）改造为通用答题页，通过 mode 参数区分「测试模式」和「作答模式」。

## 核心功能

1. **问卷分享**：workbench 中已同步的问卷卡片点击分享按钮，调用微信小程序原生分享（onShareAppMessage），分享卡片携带问卷ID
2. **通用答题页**：创建 answer-quiz 页面，支持两种进入模式：

- `mode=test`：从 editor-overview 进入，通过 URL 参数传递数据，不保存结果（兼容现有测试功能）
- `mode=answer`：从分享链接进入，通过 surveyId 从云函数加载数据，答题完成后保存结果到数据库

3. **结果保存**：作答模式下，答题完成后将用户答案、维度得分、匹配结果保存到 survey-answers 集合
4. **分享结果**：作答完成后，结果页底部显示「分享结果」按钮，可再次分享到微信

## 技术栈

- 前端：Vue2 + uni-app（微信小程序）
- 云服务：uniCloud（支付宝云，云对象模式）
- 数据库：uniCloud DB（带 schema 校验）
- 分享：微信小程序原生分享（onShareAppMessage）

## 实现方案

### 架构设计

采用「同一页面 + mode 参数」策略，创建新的 answer-quiz 页面（基于 editor-quztest 改造），保留旧的 editor-quztest 不动以保证向后兼容。

```
                   ┌─ mode=test ──→ 从URL参数加载数据（兼容旧逻辑）
                   │
answer-quiz ───────┤
                   │
                   └─ mode=answer ──→ 从云函数 getSurveyDetail 加载
                                      答题完毕 → submitAnswer 保存到数据库
```

### 数据流设计

**作答模式（mode=answer）：**

```
分享链接 → answer-quiz?surveyId=xxx&mode=answer
    → onLoad 解析参数
    → mode==='answer' → 调用 tools.getSurveyDetail({ id: surveyId })
    → 加载问卷数据（questions, dimensions, resultTypes）
    → 答题流程（intro → questions → result）同现有
    → 调用 tools.submitAnswer({ surveyId, answers, duration })
    → 结果保存到 survey-answers 集合
    → 展示结果，底部显示「分享结果」「返回首页」
```

**测试模式（mode=test）：**

```
editor-overview 的「测试」按钮 → answer-quiz?mode=test&title=xxx&questions=xxx&...
    → onLoad 解析 URL 参数（与现有 editor-quztest 完全一致）
    → 答题流程同上
    → 不保存结果，底部显示「重新测试」「返回总览」
```

### 关键设计决策

**1. 新建 answer-quiz 页面而非直接修改 editor-quztest**

- 原因：保证现有测试功能零风险，旧页面保留作为 reference
- 核心代码从 editor-quztest 复制并改造，UI 样式保持一致

**2. 分享功能实现方式**

- workbench 的分享按钮改为 `<button open-type="share">` 包裹
- 点击前将 surveyId 和问卷标题存入全局变量（`uni.$u.mpShare`）
- `onShareAppMessage` 生命周期钩子中返回分享路径和标题
- 分享路径格式：`/pages-tools/answer-quiz/answer-quiz?surveyId=xxx&mode=answer`

**3. 作答结果保存机制**

- 客户端提交原始答案（每道题选的选项 index）
- 云函数 submitAnswer 中独立计算维度得分和匹配结果（复用 editor-quztest 中的计算逻辑）
- 数据写入 survey-answers 集合，同时更新 surveys.stats.submissionCount + 1

## Implementation Notes

### 性能考量

- getSurveyDetail 通过 doc(id) 主键查询，O(1) 复杂度
- 作答结果计算逻辑从客户端迁移到服务端，避免客户端大量计算导致卡顿
- 分享使用微信小程序原生能力，零额外开销

### 向后兼容

- editor-overview.vue 的 handleTest 方法改为跳转 answer-quiz?mode=test，参数格式完全一致
- 旧的 editor-quztest.vue 文件保留不动，防止破坏现有功能

### 微信小程序分享注意事项

- workbench 的分享按钮需要改为 `<button open-type="share">` 才能触发 onShareAppMessage
- 点击前通过 uni.$u.mpShare 或 uni.setStorageSync 传递当前要分享的问卷ID
- onShareAppMessage 中返回：title=问卷标题，path=路径含 surveyId
