## 阶段二：置顶池权重与抽取

基于阶段一已实现的入池逻辑，实现完整的权重算法和加权随机抽取接口，使置顶池具备按权重排序和随机采样的能力。这是置顶栏展示的数据源头。

### 核心功能

1. **权重算法（四层叠加）**：

- 登场光环：haloActive=true 的问卷权重设为极高固定值 10000
- 归属分层：自己的问卷权重落在 [300, 500] 区间，他人的落在 [1, 200] 区间，两区间不重叠
- 内部排序（自己问卷间）：按入池时间 createdAt 升序排列，越晚入池的权重越高，在 [300, 500] 区间内线性插值
- 反向补偿（他人问卷间）：按入池时记录的 senioritySnapshot 映射到 Lv.0~Lv.3，乘以对应系数 2.5/1.5/1.0/0.6

2. **抽取接口 draw**：查询 pin-pool 中所有未过期问卷，对每条执行权重计算，内存加权随机采样（不重复抽取）5 份，按 weight 降序排列返回

3. **权重重算机制**：用户新问卷入池后，遍历该用户在池中已有非光环问卷，重新计算权重并更新到数据库，确保多人入池时内部排序保持一致

4. **入池初始权重修正**：阶段一用随机值占位，阶段二改为写入真实权重（光环问卷写入 10000）

## Implementation Approach

### 整体策略

在现有云对象中追加 3 个顶层函数 + 修改 2 个现有函数的权重写入部分 + 替换 draw 空壳。

### 新增顶层函数

**getSeniorityLevel(exposureCount)**：
遍历 PIN_CONFIG.seniority.levels，返回匹配的档位编号（0~3）。与 getSeniority 中的匹配逻辑重复，但因为是纯计算无 IO，抽成独立工具函数避免重复代码。被 calculateWeightImpl 调用。

**calculateWeightImpl(pinDoc, currentUserId, ownPinsSorted)**：
接收一条 pin-pool 文档、当前用户 uid、该用户所有在池问卷（按 createdAt 升序排序），返回综合权重值。

- pinDoc.haloActive === true → 直接返回 PIN_CONFIG.weight.haloWeight（10000）
- pinDoc.userId === currentUserId → 在 [300, 500] 区间内根据 recency 插值
- 否则 → 查 senioritySnapshot 的档位，乘系数，基准取 [1,200] 中间值

**recalcOwnWeights(uid)**：

- 查询 pin-pool 中该用户所有未过期问卷
- 按 createdAt 升序排序
- 过滤掉 haloActive=true 的（光环问卷权重为固定值 10000，不应被覆盖）
- 对非光环问卷逐条调用 calculateWeightImpl 计算新权重
- 逐条 update 到数据库（db.collection('pin-pool').doc(id).update({ weight: newWeight })）

**drawImpl(uid, count = 5)**：

- 查询 pin-pool 有效问卷：db.collection('pin-pool').where({ expireAt: { $gt: Date.now() } }).get()
- 提取当前用户自己的问卷，按 createdAt 升序排序传给 weight 计算
- 对每条问卷调用 calculateWeightImpl 获取 weight（保存在临时字段 _weight）
- 加权随机采样（标准蓄水池算法，每次累减总权重后 random pick，选中后剔除候选数组）
- 执行 Math.min(count, 候选数量) 次，确保不重复
- 按 _weight 降序排列
- 组装返回 items：每条含 surveyId、surveyTitle、surveyCover、weight、isMine、haloActive、expireAt
- 空池时返回空列表 items: []

### 修改现有函数

**enterPoolImpl** 和 **queueToPoolImpl** 中直接入池分支的 weight 写入：

- 原：`const weight = Math.floor(Math.random() * 200) + 300`
- 改：`const weight = PIN_CONFIG.weight.haloWeight`（光环入池永远是最高权重 10000）
- 写入 pin-pool 后调用 `await recalcOwnWeights(uid)` 触发权重重算

### 关键技术决策

1. **weight 存储 vs 实时计算**：采用设计文档的策略，入池时计算 weight 一次性写入 MongoDB 的 weight 字段。抽取时直接读取 weight 做加权采样，不触发全量重算。权重重算仅在新文档入池后触发，更新该用户自己的非光环问卷。

2. **光环问卷不参与重算**：haloActive=true 的问卷 weight 固定为 10000，重算时跳过，避免被内部排序覆盖。光环随问卷到期自动出池，无需后续处理。

3. **inc 条件更新**：资历累加使用原子 inc，不涉及条件匹配。

## Implementation Notes

- **Performance**：pin-pool 数据量极少（当前协议最多数百条），全量查询后内存中做加权采样，毫秒级完成。循环逐条 update weight 最多涉及同一用户的几条数据，写压力很小。
- **Logging**：draw 函数失败时 console.error 记录错误信息，不记录全量问卷数据避免日志过大。
- **Blast radius**：不修改 enterPoolImpl 的入池流程逻辑（槽位/资历/池满判断保持不变），仅修改 weight 写入数值和追加 recalcOwnWeights 调用。queueToPoolImpl 同理。不影响已有功能。

## Key Code Structures

**calculateWeightImpl** 核心逻辑：

```
function calculateWeightImpl(pinDoc, currentUserId, ownPinsSorted):
  if pinDoc.haloActive:
    return PIN_CONFIG.weight.haloWeight          // 10000

  if pinDoc.userId === currentUserId:
    // 归属分层 + 内部排序
    const { selfWeightMin, selfWeightMax } = PIN_CONFIG.weight
    if ownPinsSorted.length <= 1:
      return floor((selfWeightMin + selfWeightMax) / 2)
    idx = ownPinsSorted.findIndex(p => p._id === pinDoc._id)
    ratio = idx / (ownPinsSorted.length - 1)       // 0.0 ~ 1.0
    return floor(selfWeightMin + (selfWeightMax - selfWeightMin) * ratio)
  else:
    // 反向补偿
    level = getSeniorityLevel(pinDoc.senioritySnapshot)
    coeff = PIN_CONFIG.weight.reverseCompensationCoefficients[String(level)]
    base = floor((otherWeightMin + otherWeightMax) / 2)  // 100
    return floor(max(base * coeff, otherWeightMin))
```
