为特殊问卷全面改造评分方式。现有问卷系统支持普通问卷（`match` 字段单维度最高匹配），新需求为一份 28 个结果类型的特殊问卷引入向量匹配。改造内容：

- **Schema**：`surveys.schema.json` 中 resultTypes.maxItems 10→35，match 移出 required，新增可选 profile 数组字段
- **答题页**：`answer-quiz.vue` 的 `goResult()` 新增分支——检测 `resultTypes[0]?.profile`，存在则走欧几里得距离匹配 + `generateFakeScoresByProfile`，否则走现有逻辑。新增 `generateFakeScoresByProfile()` 方法
- **雷达图假数据**：特殊问卷按 profile 比例线性映射到 [30,70]，主维度 boost 到 75-85，非主维度加种子噪声后 clamp 到 [20,70]，gap 保证 ≥20
- **兼容性**：所有现有问卷数据不受影响，Coze 生成逻辑不改，无需数据库迁移

## 技术方案

### 技术栈

- 现有 Vue2 + uni-app + uniCloud 微信小程序
- 纯前端改造，不涉及云函数改动

### 实现策略

沿用「文档即设计」原则，两处改动同步进行：

1. **Schema 层**（`surveys.schema.json`）—— 打开一对多结果类型的上限
2. **业务逻辑层**（`answer-quiz.vue`）—— `goResult()` 分支 + 新增造假方法

两个改动互不依赖，可并行落地。

### 关键设计决策

**为什么不在 `survey-utils.js` 已有的 `nearestNeighborMatch()` 基础上改？**

- `survey-utils.js` 使用 `prototypes` 字段名，而需求文档和方案文档均使用 `profile` 字段名
- `survey-utils.js` 的模型假设了新的题目/选项数据结构（`Option.scores` 多维分值），与当前答题流程（固定 3 级评分 + 归一化）不兼容，引入后牵一发动全身
- 特殊问卷不改答题流程，只改结果匹配和造假策略。直接在 `answer-quiz.vue` 内实现更贴合现有代码结构，符合 YAGNI 原则

**profile 与 raw 同量纲（0-100）的收益：**

- 欧几里得距离直接计算，无需归一化
- 线性映射 `30 + (profile[i]-pMin)/(pMax-pMin)*40` 天然工作在原始值域内

**雷达图假数据 shape 保真：**

- `generateFakeScoresByProfile` 保证雷达图视觉形状 = profile 按比例缩放 + 种子噪声，高值维度在高分区、低值在低分区
- 确定性种子（hashString 分桶）确保同问卷同答案的雷达图完全一致

### 架构变化

```
goResult()
  +-- resultTypes[0]?.profile 存在 → 欧几里得距离 → generateFakeScoresByProfile
  |     (dimensionScores / submitAnswer / redirectTo 不变)
  +-- resultTypes[0]?.profile 不存在 → 最高分维度 match → generateFakeScores (现有逻辑不变)
```

### 实现注意事项

- **向后兼容**：`match` 从 required 移除不影响现有数据（它们本来就有 match）；profile 为可选字段，旧问卷无此字段
- **Blast radius**：`result.vue` 只通过 URL 参数接收 `rname/rdesc/emoji/scores/dims/colors`，不依赖 `match`，无需改动
- **边界处理**：`generateFakeScoresByProfile` 中 pMax===pMin（profile 全相等）时需 fallback 到随机分布
- **无性能风险**：欧几里得距离计算是 O(n*m)，n=5 维度、m≤28 结果类型，毫秒级完成
