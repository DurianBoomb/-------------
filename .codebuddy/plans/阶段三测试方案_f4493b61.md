## 用户需求

设计一套测试方案用于测试与验收阶段三的工作。脚本尽可能测试后端逻辑，脚本无法覆盖的前端 UI 部分，在小程序内做一个傻瓜式一键完成的 mock 测试页面。

## 阶段三验收范围

- **recordClick**：递增 clickCount，创建者自访跳过，系统问卷不晋升，用户问卷按 101/501/1501/5001 阈值晋升，首次 handmade0→handmade1 返回 promoted=true
- **getSurveyByTag**：返回问卷 + clickCount + rarity
- **getMySurveys**：返回列表 + clickCount + isPublic + rarity
- **submitAnswer**：正确存储 dimensionScores/matchedType/surveySnapshot
- **getSurveyDetail**：返回 creatorNickname
- **前端 UI**：survey-preview 私有/公开 Banner、clickCount/101 进度条、my-surveys 点击量显示、result 经验条经验百分比进度条和稀有度徽章
- **URL 传参链路**：search → preview → answer-quiz → result 各环节 clickCount/isPublic/rarity 正确传递

## 现存 bug 修复

quiz-home.vue 中 5 个导航方法指向已删除的测试页面（phase1-clickcount-test、phase1-nickname-test、phase2-test、phase3-test、phase4-test），需清理死链接。

## 技术栈

- 脚本测试：Node.js ESM (.mjs)，纯函数测试 + 模拟数据结构，`node test-phase3.mjs` 一键运行
- Mock 测试页面：Vue2 + uni-app，参照 phase1-test 页面的一键测试 + 日志面板模式
- 项目框架：uni-app (Vue2) + uniCloud Alipay + 微信小程序

## 实现方案

### 方案一：脚本测试（test-phase3.mjs）

**策略**：将阶段三云函数中的核心业务逻辑提取为纯函数，复制到本地脚本中测试。不依赖 uniCloud 运行时，直接 `node test-phase3.mjs` 运行。

**测试套件设计**：

| 套件 | 测试内容 | 方式 |
| --- | --- | --- |
| 套件一：晋升阈值判定 | recordClick 中 thresholds 数组逻辑（101/501/1501/5001），手工测试各边界值 | 纯函数，独立可测 |
| 套件二：getSurveyByTag 返回结构 | 模拟 survey-tags 联查结果，断言 data 包含 clickCount + rarity 字段 | 模拟数据 |
| 套件三：getMySurveys 返回结构 | 模拟列表，断言每条含 clickCount/isPublic/rarity，isPublic = rarity !== 'handmade0' | 模拟数据 |
| 套件四：submitAnswer 入参 | 模拟请求参数结构，断言 answers/dimensionScores/matchedType/surveySnapshot 各字段完整 | 模拟数据 |
| 套件五：经验条计算 | 复制 result.vue 中的 rarityLevels/currentLevel/expPercent/rarityDisplay 四个 computed 逻辑，测试各典型 clickCount 值下的输出 | 纯函数 |
| 套件六：自访跳过逻辑 | uid === creatorId 时 recordClick 跳过计数 | 纯函数逻辑 |
| 套件七：generateFromCoze 返回结构 | 返回值含 clickCount + isPublic 字段存在性 | 模拟数据 |
| 套件八：getAnswerHistory/getSurveyDetail | 返回结构字段完整性 | 模拟数据 |


**技术细节**：

- 复用 test-phase5.mjs 的测试框架模式（assert/pass/fail/统计）
- 经验条计算是前端的 4 个 computed 属性，复制到脚本中做纯函数测试
- 晋升阈值逻辑路径为 `survey/index.obj.js:685-693`，可复制 key 逻辑做边界测试
- 避免依赖 uniCloud，全部用模拟数据和纯函数

### 方案二：Mock 测试页面（phase3-test.vue）

**策略**：新建 pages-tools/phase3-test/phase3-test.vue，参照 phase1-test "一键运行全部测试 + 日志面板" 的设计模式，提供傻瓜式操作。

**页面结构**：

- 顶部：标题"阶段三验收测试"，一键全跑按钮
- 日志面板：深色背景，实时显示 pass/fail/skip 日志
- 按钮区：分组展示各测试项

**测试按钮设计**：

| 按钮 | 测试目的 | 执行逻辑 |
| --- | --- | --- |
| 测试 recordClick（系统问卷） | 调用云函数 recordClick，验证系统问卷 clickCount+1 且不晋升 | 调云函数 → 查结果 → 断言 |
| 测试 recordClick（用户问卷晋升） | 调 recordClick 多次直至跨阈值，验证 rarity 晋升 | 先 mock 设置 clickCount 至 100 → 再调一次 → 断言 rarity 变为 handmade1 |
| 测试自访跳过 | 用当前用户自己的问卷调 recordClick，断言 skipped=true | 调云函数 → 断言 reason=self_visit |
| 查看 getMySurveys 字段 | 调 getMySurveys，展示每条数据的 clickCount/isPublic/rarity | 调云函数 → 展示结果 |
| 查看 getSurveyByTag 返回 | 输入已知标签名，调 getSurveyByTag，展示 clickCount/rarity | 调云函数 → 展示结果 |
| 查看答题历史字段 | 调 getAnswerHistory，展示每条数据的字段完整性 | 调云函数 → 展示结果 |
| 测试经验条计算 | 本地计算 rarityLevels/expPercent/rarityDisplay，展示不同 clickCount 值下的结果 | 纯前端计算 → 展示表格 |
| 测试 URL 传参链路 | 模拟 URL 参数对象，验证 clickCount/isPublic/rarity 解析正确 | 纯前端解析 → 展示结果 |


**技术细节**：

- 使用 uniCloud.importObject('survey') 真调云函数（需要真实部署的云函数 + 已登录状态）
- 日志面板复用 phase1-test 的样式和 addLog/addPass/addFail/addSkip 模式
- 晋升测试需要先构造一个 clickCount=100 的测试问卷（可新增云函数 mockSetClickCount 或手动在数据库设置）
- 纯前端测试（经验条计算、URL 解析）不依赖云函数，可离线完成
