## 阶段四：候场区系统

### 产品概述

候场区是用户无法立即进入置顶池时的中间等待层。它被包装为一个虚构的"系统监控终端"——黑底绿字、等宽字体、日志逐行滚动。用户提交置顶请求后，不再看到枯燥的进度条，而是旁观系统对自己的问卷进行"含梗量检测""舆情预测"等一本正经的荒诞处理。

候场内容不再作为独立全屏页面，而是嵌入 `career-history` 页面的三槽位管理台中——用户点击"候场中"状态的槽位卡片，页面底部弹出半屏面板展示终端日志。

### 核心功能

1. **后端候场区状态管理**：`getQueueStatus` 计算当前处理阶段和日志文本；`executeAccel` 处理广告加速跳跃（第三次自动完成入池）
2. **日志推进算法**：后端根据 `enterAt` / `acceleratedCount` / `seniorityLevel` 计算当前阶段，取自然推进和加速推进的较远者
3. **候场终端半屏面板**：黑底绿字终端风格，日志逐行滚动，含"看广告加速"按钮
4. **三槽位管理台数据绑定**：从后端实时读取用户槽位状态，各状态卡片支持点击交互
5. **广告入口按钮接 handleAdReward**：触发激励视频广告，广告完成后调用云对象方法
6. **绿色通道闪屏整合**：入池返回 `greenChannel: true` 时自动展示闪屏动画

## 技术方案

### 技术栈

- **后端**：uniCloud 支付宝云云对象（Node.js），在 `pin-system/index.obj.js` 中新增/修改
- **前端**：uni-app（Vue 2），编译到微信小程序
- **数据库**：uniCloud MongoDB（`survey-queue` 集合 + `uni-id-users.career.slots` 扩展字段）
- **广告**：微信小程序激励视频广告（客户端 `wx.createRewardedVideoAd`），无服务端回调

#### 后端核心：阶段推进算法

严格遵循设计文档 §5.3 伪代码：

```javascript
function calcPhase(enterAt, acceleratedCount, seniorityLevel) {
  const elapsed = (now - enterAt) / 60000
  const phaseMap = PIN_CONFIG.queue.phases  // [{phase, endMin}]
  
  // 自然推进 index
  let naturalIdx = 0
  for (let i = 0; i < phaseMap.length; i++) {
    if (elapsed >= phaseMap[i].endMin) naturalIdx = i
  }
  
  // 加速跳跃 index
  const jumpMap = PIN_CONFIG.queue.accelJumpMap
  const accelIdx = Math.min(
    acceleratedCount * (jumpMap[String(seniorityLevel)] || 1),
    phaseMap.length - 1
  )
  
  // 取较远者
  const currentIdx = Math.max(naturalIdx, accelIdx)
  const isReady = phaseMap[currentIdx].phase === 'ready'
  
  return { currentPhase, phaseIndex, isReady }
}
```

**关键设计决策**：

- 日志文本由后端计算返回，前端仅做渲染——`getQueueStatus` 返回完整日志字符串数组，前端一行一行滚
- `getQueueStatus` 检测到 `currentPhase === 'ready'` 时，**后端自动调 `queueToPoolImpl` 完成入池**（兜底），再返回入池结果
- `executeAccel` 检测到加速后将达 3 次时，**内部自动调 `queueToPoolImpl`**，不需前端再次发起请求
- 日志模板使用 `PIN_CONFIG` 同层常量存放（后续统一迁移 config-center），设计文档的 15+ 条占位日志全部纳入

#### 候场半屏面板组件设计

`components/queue-terminal/queue-terminal.vue`：

- **入参**：`queueId`（候场记录 _id）、`visible`（是否显示）
- **行为**：
- 组件显示时立即调 `getQueueStatus({ queueId })` 获取当前日志
- 日志从第一条开始逐行自动滚入（每次间隔约 800ms-1500ms），模拟终端打字效果
- 每 10 秒自动轮询 `getQueueStatus` 检测阶段变化，有新日志追加
- 面板底部有"看广告加速"按钮 → 触发激励视频广告 → `handleAdReward({ scene: 'queue_accel', queueId })`
- 加速后或阶段推进到 ready → 面板自动更新日志 → 入池成功后自动关闭面板并 emit 'completed'
- **视觉风格**：黑底 `#0A0A0A`、绿字 `#4ADE80`、等宽字体（monospace）、行前带 `[时间戳]`

#### 三槽位管理台改造

`career-history.vue` 从静态假数据改为：

- `onLoad` + `onShow` 时调 `getQueueStatus({})`（不传 queueId = 查全部）获取槽位状态
- 三个槽位与 `career.slots` 数组一一对应
- 点击 `queuing` 状态槽位 → 打开 `queue-terminal` 半屏面板，传入 `queueId`
- 点击 `claimable` 状态槽位 → 跳转 `career-detail.vue`（归属阶段六，现仅路由跳转）
- `active` 状态槽位展示倒计时（剩余分钟 = (expireAt - now) / 60000）

#### 广告入口按钮

`pin-terminal-entry.vue` 从骨架改为：

- `onClick` → 激励视频广告 `wx.createRewardedVideoAd`
- `onRewarded` → 弹问卷选择器（暂用简单的 input 输入 surveyId）→ `handleAdReward({ scene: 'first_pin', surveyId })`
- 返回 `enter_queue` → 跳转 `career-history` 或更新槽位
- 返回 `direct_entry` → 回首页刷新置顶栏 + 绿色通道闪屏（如有）

#### 绿色通道闪屏整合

`green-channel-splash.vue` 已有完整骨架，无需改造。

- 首页 `index.vue` 中引用组件，绑定 `showGreenChannel` 状态
- `handleAdReward` 返回 `greenChannel: true` 且 `action === 'direct_entry'` 时 `showGreenChannel = true`
- 组件 2 秒后自动 emit 'close'

### 实现要点

- **日志模板复用**：设计文档 §5.3 的 4 个阶段 × 3 条日志 ≈ 12 条占位文本，全部硬编码进 `getLogsForPhase` 函数
- **推进算法与 `executeAccel` 的调度关系**：`executeAccel` 写入加速次数→删除旧 queue 文档→创建新 queue 文档（更新 `acceleratedCount` 和 `currentPhase`）→检测是否已达 ready→是则自动入池
- **轮询策略**：前端每 10 秒调一次 `getQueueStatus` 获取最新阶段。加速后立即调一次刷新，不等轮询
- **幂等**：`executeAccel` 内部检测 `acceleratedCount` 是否已被处理，防止广告重复回调
- **定时兜底衔接**：`pin-expiry` 已有候场超时兜底（35分钟），与本阶段的正常候场互不干扰

### 性能与可靠性

- 日志文本不大（最多 4 阶段 × 3 行 × 50 字符 = 600 字节），不存在传输瓶颈
- 10 秒轮询频率，每人每小时 360 次 `getQueueStatus` 调用，100 人同时在候场 = 1/秒，云函数无压力
- `executeAccel` 冷启动约 1-2 秒，用户可接受（广告结束到面板刷新有自然延迟）
