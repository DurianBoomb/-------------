## 需求描述

基于三份 Figma 移植指南文档，重写 `answer-quiz.vue` 页面的**题目文本区域**（`.stage > .card > .q-wrap > .q-txt > .char-drop`）及其相关动画特效。

### 修改范围

- **仅限题目文本区域**，不涉及顶部栏、选项区、浮层（flash/edge-glow/连击/纸屑等）
- 具体包括：容器层级样式修正、逐字渲染元素类型修正、入场/离场动画参数修正、keyframes 兼容性修正、数据准备流程修正

### 核心修改内容

1. 修复 `.q-wrap` 的 padding 为四边均匀 64rpx（为动画安全区）
2. 修复 `.char-drop` 元素类型为 `<view>` + `display: inline-block`
3. 移除 `charDrop` keyframes 中的 `filter: blur()`（小程序兼容）
4. 修正 `qIn`/`qOut` 的 timing-function 缓动曲线
5. 修正 `.q-txt` 的 line-height
6. 新增 `titleChars` 预计算机制（`Array.from()` 而非 `.split('')`）
7. 修复 v-for key 绑定为 `qid-ci` 组合键
8. 新增双 animation-name 交替机制保障切题动画重播
9. 在 slot 数据结构中补充 `titleChars`/`qid`/`flip` 字段

## 技术栈

- Vue 2 + uni-app + 微信小程序

## 实现方案

### 数据层修改

在 slot 对象中新增三个字段：

- `titleChars: []` — 预切割的逐字数组，加载题目时用 `Array.from(q.title)` 生成，替代模板中直接迭代 `q.title`
- `qid: 0` — 每题唯一 ID，递增计数器生成，用于 v-for 的 key 以触发节点重建
- `flip: false` — 双 animation-name 交替开关，切题时取反

新增顶层 `_qidCounter: 0` 计数器。

### 模板层修改

- `.char-drop` 从 `<text>` 改为 `<view>`（避免小程序原生组件的光栅层错位）
- key 绑定从 `:key="ci"` 改为 `:key="\`${slots[slot].qid}-${ci}\`"`
- 迭代源从 `slots[slot].q.title` 改为 `slots[slot].titleChars`
- 新增 `.char-drop` 的 class 绑定 `slots[slot].flip ? 'a' : 'b'`

### 样式层修改

- `.q-wrap`: `padding: 64rpx`（四边均匀）
- `.char-drop`: `display: inline-block; vertical-align: baseline; transform-origin: center bottom`
- `.q-txt`: `line-height: 1.5`
- `.card.in .q-txt` animation: `cubic-bezier(0.34, 1.25, 0.64, 1)`
- `.card.out .q-txt` animation: `cubic-bezier(0.4, 0, 1, 1)`
- 拆分 `.card.in .char-drop` 为 `.a`/`.b` 双 animation-name，动画属性独立声明（不覆盖内联 animationDelay）
- charDrop keyframes 移除 filter: blur
- 新增 charDropA/charDropB 双份相同关键帧

### 关键设计决策

- **双 animation-name 不用作主方案，而是兜底**：主方案仍是 `:key` 组合键触发节点重建，双名在真机 `:key` 无效时自动生效
- **caret 分离 animation 属性**：duration/timing/fill-mode 通过 CSS class 声明，delay 通过内联 style 设置，避免 animation 简写覆盖内联 delay
- **数据驱动**：titleChars 在每次加载题目时同步生成，与 `phase = 'in'` 在同一位置

### 性能

- 无额外运行时开销（双份 keyframes 仅在 `@keyframes` 中多一份同名定义，CSS 不增加运行时计算）
- 内联 animationDelay 通过 style binding 注入，无额外 DOM 操作
