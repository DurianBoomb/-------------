## 阶段五：置顶栏首页展示

在首页集成三个组件（置顶栏、看广告入口、绿色通道闪屏），实现完整的前端闭环。

**核心功能**：

1. **置顶栏组件**（`pin-topbar`）：首页顶部展示5张问卷卡片，数据来自 `draw` 接口的加权随机抽取；包含"自己的问卷"角标、登场光环边框动画、空池占位引导、回访自动刷新
2. **看广告置顶入口**（`pin-terminal-entry`）：首页上的入口按钮，点击触发激励视频广告流程，广告完成后路由到入池或候场区，已完整实现在组件中
3. **绿色通道闪屏**（`green-channel-splash`）：Lv.0 新用户入池时以 overlay 形式展示约 2 秒的进场动画
4. **首页集成**：三个组件按顺序排列到首页（品牌区 header 下方），处理 `onShow` 回访自动刷新、广告完成后置顶栏刷新、组件间事件协调

**后端配套改动**：入池时冗余写入作者昵称，使 `draw` 返回的卡片数据可展示作者名

## Tech Stack Selection

沿用项目现有技术栈，无新增依赖：

- **前端**：uni-app (Vue 2) + 微信小程序
- **后端**：uniCloud 支付宝云云对象（Node.js）
- **数据库**：MongoDB 兼容（uniCloud 云数据库）
- **广告**：微信小程序激励视频广告 SDK（组件已有实现，阶段五不涉及广告API调用本身）

## Implementation Approach

### 策略

阶段五是纯前端集成层，后端核心逻辑（enterPool/draw/calculateWeight/queueToPool）已在之前阶段完整实现。核心工作是：**将已就绪的3个组件从独立状态整合到首页**，建立组件间的事件协调机制。

### 关键技术决策

**1. pin-topbar 的刷新机制**

- 组件自身没有 `onShow` 生命周期，需要通过父页面触发刷新
- 方案：父页面 `index.vue` 通过 `$refs.pinTopbar.refresh()` 在 `onShow` 或广告完成后显式调用
- 为什么不是 watch prop：`onShow` 触发频繁但 refreshKey 方案会增加不必要的响应式开销，ref 直接调用更简洁
- 内部实现：async refresh() → loading=true → importObject('pin-system').draw({count:5}) → 更新数据 → loading=false

**2. 卡片数据中作者名的来源**

- `draw` 接口从 `pin-pool` 文档读取，当前 `pin-pool` schema 没有作者昵称字段
- 方案：在 `enterPoolImpl` 和 `queueToPoolImpl` 入池时，从 `uni-id-users` 查询当前用户的 `nickname` 字段，冗余写入 `pin-pool.surveyAuthor`
- 理由：避免高频 `draw` 调用时每次联表查询，团队已有类似冗余实践（surveyTitle 就是入池时冗余写入的）

**3. 首页 onShow 双职责**

- 当前 `index.vue` 的 `onShow` 已用于重建卡片 DOM 触发入场动画（`showGrid` 切换）
- 方案：在原 `onShow` 中追加 `this.$refs.pinTopbar?.refresh()`，两件事并行，互不阻塞

**4. 广告完成后的交互协调**

- `pin-terminal-entry` 触发 `@pinned` 事件 → index.vue 的 `onPinned` 处理：
- `direct_entry`：刷新 `pin-topbar` + 弹出 `green-channel-splash`
- `enter_queue`：跳转到 `career-history` 页面
- `green-channel-splash` 通过 `v-if="showGreenChannel"` 控制显隐，2秒后自动消失

### Performance & Reliability

- `draw` 接口为高频调用（每次 onShow 触发），pin-pool 全量查询 + 内存加权随机采样，同时活跃问卷最多数百张，毫秒级
- 冷启动影响：首页 `onLoad` 时已有 `ping()` 预热方案（阶段零B已实现）
- 空状态处理：`draw` 返回空列表时不展示空白区域，显示 "虚位以待" 引导卡片
- 加载态处理：接口返回延迟时展示骨架屏，避免白屏闪烁
- 失败兜底：`draw` 失败时保持原有数据不变，不展示错误提示，避免打扰用户体验

### Avoiding Technical Debt

- 严格遵守 vue2 uni-app 组件通信方式（props + $emit + $refs），不引入额外状态管理
- 所有配置参数已集中在前阶段创建的 `PIN_CONFIG` 常量中，本阶段不新增硬编码
- 组件 style 沿用现有命名前缀（`.ptb-`/`.pte-`/`.gcs-`），保持风格统一
- 首页原有 mock 预览和开发测试区域保留不删，等你上线前自己清理

## Implementation Notes

### 性能

- `draw` 调用后 `loading=true` → 异步等待 → `loading=false`，期间旧数据保留，避免白屏
- 空池时直接展示占位卡片，不额外渲染隐藏的空列表
- `refreshKey` 方案被否决（看上面的设计决策），使用 `$refs` 直接调用

### 后端兼容

- `pin-pool` 集合已有 `surveyCover` 字段（空字符串默认），入池时从 `surveys` 集合查询并写入
- 新增 `surveyAuthor` 字段不影响已有数据，旧记录显示空字符串即可
- `drawImpl` 的返回结构追加 `surveyAuthor` 字段，不破坏已有 call site

### 首页布局

- 品牌区 header 之后、scroll-view 之前固定放置 pin-terminal-entry 和 pin-topbar
- scroll-view 内的网格 + mock + dev-section 保持不动
- green-channel-splash 为 fixed overlay，放在页面最外层

## Architecture Design

### 组件关系

```
pages/index/index.vue
├── header (品牌区)
├── pin-terminal-entry （入口按钮）
│     └── @pinned → onPinned()
│     └── @green-channel → onGreenChannel()
├── pin-topbar （置顶栏5张卡片）
│     └── refresh() ← index.vue onShow / onPinned 调用
├── scroll-view （原有内容：工具网格+mock+开发测试）
└── green-channel-splash （overlay，v-if 控制）
```

### 数据流

```
用户回访首页
  → onShow()
    → this.$refs.pinTopbar.refresh()
      → uniCloud.importObject('pin-system').draw({count:5})
        → drawImpl (服务端加权随机采样)
          → 返回 items[] (含 surveyId/title/cover/author/isMine/haloActive)
      → this.cards = items
    → 渲染5张卡片

用户点击"看广告置顶"
  → pin-terminal-entry.onClick()
    → 模拟广告播放（生产环境改为真实激励视频广告）
    → handleAdReward({scene:'first_pin', surveyId})
      → enterPoolImpl (服务端判断绿色通道/池满线)
        → 直接入池 或 进入候场区
    → @pinned 事件
      → direct_entry → refresh pin-topbar + show green-channel-splash
      → enter_queue → navigateTo career-history
```

### draw 接口返回结构（修改后）

`draw` 返回的 items 数组中每条对象结构如下，新增 `surveyAuthor` 字段：

```javascript
{
  _id: String,           // pin-pool 文档ID
  surveyId: String,      // 问卷唯一标识
  surveyTitle: String,   // 问卷标题
  surveyCover: String,   // 问卷封面 URL
  surveyAuthor: String,  // 作者昵称（新增，从 uni-id-users.nickname 冗余）
  isMine: Boolean,       // 是否为当前用户所有
  haloActive: Boolean,   // 登场光环是否激活
  expireAt: Number       // 过期时间戳
}
```
