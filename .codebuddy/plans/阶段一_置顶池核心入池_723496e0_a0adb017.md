## 权重展示排序去"焊死感"

当前 `draw` 接口选取 5 份问卷后，严格按权重降序排列返回，导致每次抽取结果的位置几乎固定：光环第一、自己的按入池时间排、他人的按资历排，感觉"焊死"了。

**目标**：只改**选中后的排序逻辑**，不动权重本身（权重继续用于加权随机采样的概率控制）。

**新排序规则**：

- 分三层：**光环问卷 > 自己的问卷 > 他人的问卷**
- 层内不做权重排序，改为 **Fisher-Yates 完全随机乱序**
- 光环问卷一定排在自己和他人前面，但光环内部的顺序随机（可能第 2/3 位）
- 自己的问卷之间随机乱序
- 他人的问卷之间随机乱序
- 每次 draw 输出顺序有微妙差异，不再焊死

**不改**：权重算法、入池逻辑、抽取概率、返回格式字段——仅改 draw 输出排序。

## 技术方案

### 改动范围

仅修改 `uniCloud-alipay/cloudfunctions/pin-system/index.obj.js` 中的 `drawImpl` 函数（1 处改动），其他文件不变。

### 修改点

**当前代码**（第 428-429 行）——按权重严格降序，造成"焊死"感：

```javascript
// 按权重降序排列
result.sort((a, b) => b._weight - a._weight)
```

**改为**——分层 + 块内随机乱序：

```javascript
// 1. 按层分组
const haloItems = result.filter(p => p.haloActive)
const ownItems = result.filter(p => !p.haloActive && p.userId === uid)
const otherItems = result.filter(p => !p.haloActive && p.userId !== uid)

// 2. Fisher-Yates 随机乱序
function shuffle(arr) {
  for (let i = arr.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [arr[i], arr[j]] = [arr[j], arr[i]]
  }
  return arr
}

// 3. 合并：三层顺序保持，块内随机
const sorted = [
  ...shuffle(haloItems),
  ...shuffle(ownItems),
  ...shuffle(otherItems)
]
result.length = 0
result.push(...sorted)
```

### 关键设计决策

- **分层保序**：光环 > 自己 > 他人——这是归属分层语义底线，不打破
- **块内完全随机**：不做带倾向性的随机，让结果每次不一样才真正去掉"焊死感"
- **Fisher-Yates**：O(n) 时间、O(1) 额外空间，无需引入依赖
- **不碰权重计算**：权重继续写入 MongoDB，仍用于控制被抽中的概率

### 不需要的改动

- 权重算法（`calculateWeightImpl`）不改
- 权重重算（`recalcOwnWeights`）不改
- 入池逻辑（`enterPoolImpl` / `queueToPoolImpl`）不改
- PIN_CONFIG 配置不改
- Mock 页不改
- 返回字段不改（前端若依赖 weight 字段，数据仍保留但不再影响排序）
