### 核心场景

1. **用户画像页变成历史记录聚合页** — 显示所有答题记录（不去重），每条卡片有时间+删除按钮，不再只显示最后一次诊断
2. **首页icon替换** — 🥸用户画像 / ⭐收藏 / 📂历史档案 / 🪄我的生成；删除副标题和首页推广入口
3. **结果页闭环推广** — 答完问卷后直接在结果页点击"推广"→看广告→置顶问卷，无需记住ID去首页操作
4. **我的生成操作区重新布局** — 三个文字按钮横向排列（推广金/预览蓝/删除暗红），不再用emoji

## 技术栈

- **框架**: Vue 2 + uni-app + uniCloud
- **目标平台**: 微信小程序（含 H5 降级）
- **数据层**: uniCloud 云对象 `survey` / `pin-system`
- **广告SDK**: 微信小程序 `wx.createRewardedVideoAd`

### 关键技术决策

| 决策 | 方案 | 理由 |
| --- | --- | --- |
| ad-utils 文件位置 | `common/ad-utils.js` | common 目录已有同类工具文件（`survey-utils.js`），遵循项目惯例 |
| ad-utils 导出方式 | 直接导出函数：`export function playAd(sid)` / `export function simulateAd(sid)` | uni-app 支持 ES module；结果页和 my-surveys 页通过 `import` 引入 |
| profile.vue 数据源切换 | `getUserProfile()` → `getAnswerHistory({ pageSize: 100 })` | `getUserProfile` 按 tagName 去重只返回首次记录；`getAnswerHistory` 返回全部记录，包含 `_id`（删除用）、`createdAt`（时间显示用） |
| 时间格式 | 复用 answer-history.vue 的 `fmtTime`：`YYYY-MM-DD HH:mm` | 项目中已有现成实现，直接复制到 profile.vue 的 methods 中 |
| 删除确认 | 复用 uni.showModal 弹窗（与现有 my-surveys.vue 删除风格一致） | 项目已有统一确认弹窗模式 |
| 推广按钮广告播放 | 同页内直接调 `playAd(surveyId)`，不引入子组件 | 结果页已经有一套完整按钮样式体系，用函数调用比嵌入组件更可控 |
| my-surveys 操作区布局 | `flex-direction: row` 三个等分按钮 | 保持与卡片整体布局兼容 |


### 关键数据流

```
[用户点击"推广"]
    ↓
playAd(surveyId)  ← common/ad-utils.js
    ↓
wx.createRewardedVideoAd (微信) / setTimeout 模拟 (H5)
    ↓ 观看完成
uniCloud.importObject('pin-system').handleAdReward({ scene: 'first_pin', surveyId, adDuration })
    ↓
返回 { action: 'direct_entry' | 'enter_queue' }
    ↓
direct_entry → 弹"置顶成功" toast + 触发绿色通道事件
enter_queue → 弹"已进入候场区" + 800ms后跳 career-history
```

```
[profile.vue 改造后数据流]
    ↓
onLoad → getAnswerHistory({ pageSize: 100 })
    ↓
list 包含 _id / surveyId / tagName / emoji / resultName / createdAt
    ↓
渲染卡片：emoji + tagName + resultName + createdAt(时间)
    ↓
点击卡片 → 跳 answer-quiz（传 surveyId）
点击删除 → showModal → removeAnswer({ answerId: item._id })
```

### 性能注意事项

- **profile.vue 数据量**：`getAnswerHistory` 返回全部历史记录（pageSize=100），用户答题数通常不会超过100条，无分页加载性能问题。如果后续数据量大可加滚动分页
- **ad-utils单例**：`wx.createRewardedVideoAd` 在微信小程序中一个页面生命周期内只需要创建一次，ad-utils 内部用模块级变量缓存 videoAd 实例
- **my-surveys 列表渲染**：卡片列表用 `v-for` + `:key="item.id"`，三个按钮的 `@click` 直接绑定方法，不产生额外渲染开销
