## 二、代码实现

### 2.1 App.vue — 静默登录（无感登录）

```js
// App.vue
import initApp from '@/common/appInit.js';
import uniIdPageInit from '@/uni_modules/uni-id-pages/init.js';
import { store, mutations } from '@/uni_modules/uni-id-pages/common/store.js';

export default {
    onLaunch: function() {
        initApp();
        uniIdPageInit()
        
        // #ifdef MP-WEIXIN
        this._loginPromise = this.silentLogin()
        // #endif
    },
    methods: {
        getLoginPromise() {
            return this._loginPromise || Promise.resolve()
        },
        // #ifdef MP-WEIXIN
        async silentLogin() {
            const token = uni.getStorageSync('uni_id_token')
            const tokenExpired = uni.getStorageSync('uni_id_token_expired') || 0
            if (token && tokenExpired > Date.now()) return  // ← 关键：有 token 且未过期就直接跳过
            if (token) {
                uni.removeStorageSync('uni_id_token')
                uni.setStorageSync('uni_id_token_expired', 0)
            }
            try {
                const loginResult = await uni.login({ provider: 'weixin' })
                const loginRes = Array.isArray(loginResult) ? loginResult[1] : loginResult
                if (!loginRes || !loginRes.code) {
                    console.warn('[静默注册] uni.login 未返回 code')
                    return
                }
                const uniIdCo = uniCloud.importObject('uni-id-co', { customUI: true })
                const res = await uniIdCo.loginByWeixin({ code: loginRes.code })
                if (res.errCode === 0 || res.errCode === 'uni-id-account-exists') {
                    mutations.setUserInfo(res.userInfo || {}, { cover: true })
                    uni.$emit('uni-id-pages-login-success')
                    console.log('[静默注册] 成功', res.type)
                } else {
                    console.warn('[静默注册] 登录失败', res.errCode, res.errMsg)
                }
            } catch (e) {
                console.warn('[静默注册] 异常（不影响页面展示）', e.message)
            }
        }
        // #endif
    }
}
```

## 三、已排查定位

### 3.1 核心线索

**silentLogin() 的第 65 行有隐藏的短路逻辑：**

```js
if (token && tokenExpired > Date.now()) return  // 直接 return，不打印任何日志
```

如果有旧的 `uni_id_token` 存在 storage 中，且对应的 `uni_id_token_expired` 是一个未来的时间戳，`silentLogin()` 会**不做任何操作就返回**，所以完全看不到 `[静默注册]` 的日志。

### 3.2 第二次尝试过的事（无效）

- App.vue 中暴露 `getLoginPromise()`，页面等待登录完成后再调云函数
- `favorites.vue` 和 `quiz-home.vue` 中加了重试逻辑（等 1-1.5 秒重试）
- 清理了 `search-page.vue` 中 catch 块里删除 token 的代码

### 3.3 推测的根因

1. **云函数上传时依赖损坏**：`survey` 云函数的 `uni-id-common` 是通过相对路径 `file:` 引用的，某次上传部署时依赖解析中断，导致云端的 survey 函数缺少 `uni-id-common` 模块
2. **后果**：`this.getClientInfo().uid` 永远返回 undefined，所有需要登录的接口全部返回 AUTH_ERROR
3. **token 存在但失效**：虽然 `uni_id_token` 在客户端 storage 里，但云端无法解析它，所以 `silentLogin()` 因为 token 存在且未过期而跳过重新登录

### 3.4 现有修复尝试

| 尝试 | 结果 |
|------|------|
| 删除 unpackage 缓存重新运行 | ❌ 无效 |
| 加入 `getLoginPromise()` 等待机制 | ❌ 无效（问题不在时序，在云端） |
| 收藏页加 AUTH_ERROR 重试 | ❌ 无效（每次重试都失败） |
| 重传云函数 + 公共模块 | ❌ 未执行（用户可能忘了或传错了） |

# 回复
## 诊断结论

### Q1：依赖断裂判断是否正确？
**不完全正确，但接近。**  
`getClientInfo().uid` 返回 `undefined` 的根本原因不是 `uni-id-common` 依赖缺失，而是 **云端无法从客户端传来的 token 中解析出用户信息**。  
可能组合：
1. **客户端 token 有效但云端验证失败**：`uni-id-common` 公共模块未正确上传 → `this.getClientInfo()` 内部调用的 `uniID.parseToken()` 失败 → `uid` 为 `undefined`。  
2. **客户端 token 已过期且未刷新**：`silentLogin` 因 token 过期判断错误被跳过 → 客户端带着过期 token 请求 → 云端解析失败。

你观察到的 `getTagList` 正常，是因为它不依赖 token 解析。而 `getFavorites` 在云函数第一行就检查 `uid`，必然失败。

**确认方法**：在云函数 `_before()` 或 `getFavorites` 中添加：
```js
console.log('clientInfo:', JSON.stringify(this.getClientInfo()))
console.log('uniIdCommon loaded:', typeof require('uni-id-common') === 'function')
```
部署后查看云端日志。若 `uniIdCommon` 为 `false` 或 `getClientInfo()` 缺少 `uid` 字段，则依赖或 token 解析有问题。

## Q4：Token 短路逻辑的 Bug

**该逻辑存在严重缺陷**：
- `tokenExpired` 应该是 **毫秒时间戳**。但如果某次登录后存储的值被错误设置为 **秒级时间戳** 或 **Date 对象字符串**，`tokenExpired > Date.now()` 的比较结果会出错。
- 例如：`uni.setStorageSync('uni_id_token_expired', 9999999999)`（一个未来的秒数） → 永远不刷新。
- 更隐蔽的 bug：`silentLogin` 在 token 存在但已过期时，**只删除了 token，没有删除 expired**，导致下次启动时再次因 `token` 为空而进入登录流程，但可能因为网络或 uni.login 失败而跳过，最终 token 为空但 expired 仍是过期值。

**修复方案**：改用更严谨的判断，并增加 fallback：
```js
async silentLogin() {
  const token = uni.getStorageSync('uni_id_token')
  let expired = uni.getStorageSync('uni_id_token_expired')
  // 兼容错误格式：如果 expired 不是有效数字或小于当前时间，视为过期
  if (typeof expired !== 'number' || isNaN(expired) || expired < Date.now()) {
    expired = 0
  }
  const isValid = token && expired > Date.now()
  if (isValid) {
    console.log('[静默注册] token 有效，跳过登录')
    return
  }
  // 清除无效 token
  if (token) {
    uni.removeStorageSync('uni_id_token')
    uni.removeStorageSync('uni_id_token_expired')
  }
  // 执行登录...
}
```

## Q5：根本修复方案（健壮的无感登录）

### 方案一：客户端 + 云端协同修正

#### 1. 客户端改造（`App.vue`）：
- **修复短路逻辑**（见上）
- **增加全局登录状态监听**，在任何需登录接口收到 `AUTH_ERROR` 时，自动清除 token 并重新静默登录（避免用户手动点击）

在 `appInit.js` 的拦截器 `fail` 中：
```js
fail(e) {
  if (e.errCode === 'AUTH_ERROR' || (e.message && e.message.includes('未登录'))) {
    // 延迟重新登录，避免循环
    if (!uni.getStorageSync('_relogging')) {
      uni.setStorageSync('_relogging', true)
      setTimeout(async () => {
        await getApp().silentLogin?.() // 调用 App 的静默登录方法
        uni.removeStorageSync('_relogging')
      }, 1000)
    }
  }
  console.error(e)
}
```

#### 2. 云函数健壮性（`survey/index.obj.js`）：
- 当 `uid` 为空时，尝试手动从 token 解析（作为 fallback）：
```js
async getFavorites() {
  let uid = this.getClientInfo().uid
  if (!uid) {
    const token = this.getClientInfo().uniIdToken
    if (token) {
      const uniID = require('uni-id-common')
      const payload = await uniID.parseToken(token)
      uid = payload.uid
    }
  }
  if (!uid) return { errCode: 'AUTH_ERROR', errMsg: '未登录' }
  // 正常逻辑...
}
```
- **注意**：需要先检查 `uni-id-common` 是否可用，若不可用则返回明确错误码 `'DEPENDENCY_MISSING'`。

#### 3. 部署保障：
- 在 `package.json` 中锁定 `uni-id-common` 版本（如 `^1.0.8`），使用 npm 方式安装。
- 在 CI/CD 或上传脚本中，增加 **上传前自动安装依赖** 的步骤。

### 方案二（推荐）：彻底迁移到 uni-id-pages 的标准流程

uni-id-pages 已提供 `uniIdPageInit` 和 `store`，无需自己实现 `silentLogin`。正确用法：
```js
// App.vue onLaunch
import { store, mutations } from '@/uni_modules/uni-id-pages/common/store.js'
```
