## 二、问题表现

所有需要登录的云函数接口返回 AUTH_ERROR（`getClientInfo().uid` 为空），而公开接口正常。

### 客户端日志

```
[静默注册] force: false | token: true | expired: 1779050065000 | Date.now(): 1778792428833
[静默注册] token 有效，跳过登录

appInit.js:90 {objectName: "survey", methodName: "getTagList", params: Array(1), result: {…}}   ← ✅ 公开接口成功
appInit.js:96 {objectName: "survey", methodName: "getFavorites", params: Array(0), error: Error: 未登录}  ← ❌ 需登录接口失败
```

### 关键事实

- `getTagList`（公开接口，不检查 uid）→ **成功**
- `getFavorites`（第一行检查 `this.getClientInfo().uid`）→ **永远走到 `if (!uid)` 分支**
- token 在客户端 storage 中存在且未过期（`expired: 1779050065000` > `Date.now()`）
- `silentLogin()` 因此跳过重新登录，日志也印证了
- 即使手动 `uni.removeStorageSync` 清除 token 后重试，重新静默登录拿到新 token 后，`getFavorites` 依然报"未登录"

**结论**：问题不在客户端，在 **服务端无法从 token 解析出 uid**。

## 求助 1：支付宝云的 FUNCTION_COMPILE_ERROR 如何排查

### 根本原因
**支付宝云不支持 `file:` 路径依赖**，这是该错误的直接触发点。DCloud 官方社区已有多个用户确认：
> "支付宝运似乎不支持file这种依赖，它的检查机制有问题，没法引用common库了。我是取消了依赖，在上传部署。然后在添加依赖的。"

当 `uni-id-common/package.json` 中包含 `"uni-config-center": "file:../..."` 时，支付宝云的编译环境无法解析这种相对路径引用，导致上传时抛出 `FUNCTION_COMPILE_ERROR` 且无更详细的错误信息。

### 如何获取详细错误日志

**方法 1（最快）**：在 HBuilderX 中，`package.json` 的 `dependencies` 删除 `"uni-id-common": "file:..."` 一行（临时只上传函数体），上传成功后**删除云端旧函数**，再在 `survey` 云函数目录中重新添加依赖并安装。

**方法 2**：部署失败后，打开**HBuilderX 底部「控制台」面板**，切换到 **「终端」** 标签页，查看完整的 `npm install` 输出和打包过程日志。可以找到 `FUNCTION_COMPILE_ERROR` 前一行具体的报错点（如 `Module not found` 或 `SyntaxError`）。

**方法 3**：前往 [https://unicloud.dcloud.net.cn](https://unicloud.dcloud.net.cn) → 进入「支付宝云服务空间」→ 左侧菜单「云函数」→ 找到失败的 `uni-id-common` → 点击「查看日志」，可以看到编译阶段的详细错误输出。

## 求助 2：如何确认线上的 JWT_SECRET

### 方法 1：通过云端配置中心获取（推荐）

在云函数中新增一个仅用于本地调试的接口，打印配置信息：

```js
// survey/index.obj.js 临时添加
async _getConfig() {
    try {
        // 方式一：直接 require（如果 uni-config-center 能加载）
        const config = require('uni-config-center/uni-id/config.json');
        console.log('tokenSecret:', config.tokenSecret);
        return { tokenSecret: config.tokenSecret };
    } catch (e) {
        // 方式二：通过 uni-id-common 读取（如果已部署）
        const uniID = require('uni-id-common');
        console.log('uniID version:', uniID.version);
        return { error: e.message };
    }
}
```

部署后调用 `survey._getConfig()`，在云端日志中查看打印的值。

### 方法 2：从已登录用户 token 推断（不推荐，仅备用）

JWT token 可以在线解析，但无法直接看到 secret。用解析工具读取 payload：

- 进入 `https://jwt.io`，将 `uni.getStorageSync('uni_id_token')` 复制进去
- 解析后查看 payload 中的 `uid` 字段是否与预期一致
- 此方法不能获取 secret，但至少确认 token 格式是否被正确生成

### 方法 3：最优方案——不再依赖 JWT_SECRET

直接改用 **`uni-id-co` 的标准流程**（见求助 3），完全绕过内联 JWT 验证的问题。`uni-id-co` 内置了正确的 tokenSecret 读取逻辑，无需手动管理。

## 求助 3：有没有更简单的方案

### 推荐方案：完全依赖 uni-id-co

**原理**：将所有需要登录的接口都改为先调用 `uni-id-co` 的 `checkToken` 验证 token，拿到有效 uid 后再执行业务逻辑。

**具体实现**：

```js
// survey/index.obj.js
module.exports = {
    async getFavorites() {
        // 1. 从客户端 context 获取 token
        const token = this.getClientInfo().uniIdToken;
        if (!token) {
            return { errCode: 'AUTH_ERROR', errMsg: '未登录：无 token' };
        }

        // 2. 调用 uni-id-co 的 checkToken 接口验证
        let uid;
        try {
            const uniIdCo = uniCloud.importObject('uni-id-co');
            const checkResult = await uniIdCo.checkToken(token);
            if (checkResult.errCode !== 0) {
                return { errCode: 'AUTH_ERROR', errMsg: '未登录：token 验证失败' };
            }
            uid = checkResult.uid;
        } catch (e) {
            return { errCode: 'AUTH_ERROR', errMsg: '未登录：验证服务异常' };
        }

        // 3. 执行业务逻辑
        try {
            const favoritesCol = uniCloud.database().collection('favorites');
            const res = await favoritesCol.where({ userId: uid }).orderBy('createdAt', 'desc').get();
            return { errCode: 0, data: res.data };
        } catch (e) {
            return { errCode: 'DB_ERROR', errMsg: '查询失败' };
        }
    }
}
```

**前置条件**：确保 `uni-id-co` 云对象已部署（uni-id-pages 插件自带），且云函数有调用它的权限（同空间下自动允许）。

**优点**：不再依赖 `uni-id-common` 公共模块，不需要 JWT_SECRET，`uni-id-co` 内置了正确的配置读取逻辑。问题和依赖全部隔离。

### 备选方案：直接传 uid（仅适用于客户端已登录的场景）

客户端在登录后，从 store 中获取 `uid` 并作为参数传给云函数：

```js
// 前端调用
const uid = this.$store.state.userInfo?.uid;
const res = await survey.getFavorites({ uid });

// 云函数端
async getFavorites({ uid }) {
    if (!uid) return { errCode: 'AUTH_ERROR', errMsg: '未提供用户标识' };
    // 可以进一步验证 uid 是否有效（查询用户表），或信任前端传值
}
```

**缺点**：安全风险较高，任何客户端都可以伪造 uid 访问其他用户的数据，**仅适用于开发调试或非敏感数据场景**。

## 综合操作顺序

1. **放弃 `uni-id-common` 的依赖**，移除 `survey/package.json` 中的 `"uni-id-common"` 行。
2. **改用 `uni-id-co.checkToken` 方案**，替换 `survey/index.obj.js` 中所有需要登录的方法。
3. **重新部署 survey 云函数**（勾选「上传所有依赖」），测试 `getFavorites` 是否恢复。
4. 如部署仍有问题，**删掉云端旧 survey 函数**后再上传新版本。
5. 最后清理客户端本地 token：`uni.removeStorageSync('uni_id_token')`，重新进小程序触发静默登录，获取正确的 token。

**核心结论**：阿里云和腾讯云环境下的 `file:` 路径依赖方案，**不能直接迁移到支付宝云**，需要改用标准流程才能稳定运行。
