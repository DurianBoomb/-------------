# 换一批按钮标签掉落动画失效——完整解决过程

## 环境

- Vue 2 + uni-app + 微信小程序
- 页面路径：`pages-tools/search/search-page.vue`
- 组件结构：手风琴（accordion）展开后显示 16 个标签的网格，右上角有「换一换」按钮

## 需求

手风琴展开后，16 个标签以 `dropElastic` 动画入场（`translateY(-80rpx) → translateY(0)`，`opacity: 0 → 1`）。每个标签有不同的 `animation-delay`，形成交错掉落效果。点击「换一换」重新洗牌取 16 个标签，**新标签应从头播放掉落动画**。

## 问题一：换一换后动画不触发

### 现象

- 首次展开手风琴：动画正常 ✅
- 点击「换一换」：标签内容变了，但没有动画，直接显示 ❌

### CSS 动画定义

```css
.tag-inner {
	animation-name: dropElastic;
	animation-duration: 0.6s;
	animation-timing-function: cubic-bezier(0.34, 1.56, 0.64, 1);
	animation-fill-mode: both;
}

@keyframes dropElastic {
	0% { opacity: 0; transform: translateY(-80rpx); }
	100% { opacity: 1; transform: translateY(0); }
}
```

### 已确认排除的问题

- ✅ CSS `@keyframes` 定义正确，首次展开动画正常
- ✅ 标签数据确实变了（内容不同，洗牌生效）
- ✅ 新版标签的 `animation-delay` 确实不同
- ✅ 已删除 `unpackage` 缓存重跑，排除模拟器缓存
- ✅ `animation-name` 等属性在 CSS 中定义，未写 inline style

### 尝试方案 A：JS 样式复位

做法：先将所有标签 inline style 设为 `animation: none !important`，nextTick 后再设回 `animation-delay: Xs`。

结果：失败。因为 inline style 只控制 delay，`animation-name` 在 CSS 里。元素已存在时改 delay 不会重启动画。

### 尝试方案 B/C：:key 驱动 DOM 重建

做法：在 `.tag-grid` 上用 `:key="'grid-' + cat.refreshId"`，期望 `refreshId` 变化时 Vue 销毁旧 grid 重建新 grid，新节点的动画自然触发。

测试了两种变体（纯 `:key`、`:key` 配合 `animation: none` 复位）。

结果：全部失败。**uni-app 编译为微信小程序后，非 `v-for` 元素的 `:key` 变化不会导致 DOM 真正销毁重建**，同一位置的节点被复用，CSS 动画不会重播。

### 核心结论

微信小程序（uni-app）环境中，对于已存在于 DOM 中的元素，没有可行的纯 CSS/JS 方案可以重新触发 animation。唯一的可靠方式是 **让节点真正从 DOM 中移除再重新创建**。

### 首次修复方案：v-if 拔插网格

每次换一批时先用 `v-if="cat.showGrid"` 把 `.tag-grid` 从 DOM 拔掉，更新数据，再在 `nextTick` 后重新挂载，用 `showGrid = false → true` 驱动 DOM 重建。

```javascript
// refreshCategory 核心逻辑
cat.showGrid = false       // 1️⃣ 先卸载网格
// 更新 tags 数据...
this.$nextTick(() => {
	cat.showGrid = true     // 2️⃣ 重建网格 → 新节点动画触发
	this.$nextTick(() => {
		cat.refreshing = false
	})
})
```

实际效果：动画能触发了 ✅ 但引入了新问题。

## 问题二：换一换导致手风琴闪烁（收回去又弹出来）

### 现象

点击「换一换」时，手风琴会有一瞬间收回去又弹出来。

### 原因分析

```
.accordion-body (max-height transition 控制展开/收起)
  └── .body-inner (v-if="cat.expanded")
       ├── tag-pool-header (固定高度 ~80rpx)
       └── .tag-grid (v-if="cat.showGrid")     ← v-if 拔掉
```

`.accordion-body` 用 `max-height + transition` 实现手风琴展开/收起动画：

```css
.accordion-body {
	max-height: 0;
	overflow: hidden;
	transition: max-height 0.3s ease-in-out, opacity 0.2s;
	opacity: 0;
}
.accordion-body.body-open {
	max-height: 10000rpx;
	opacity: 1;
}
```

`refreshCategory` 中 `cat.showGrid = false` → `.tag-grid` 从 DOM 移除 → `.body-inner` 只剩 header（高度从约 350rpx 瞬间塌到约 80rpx）→ `.accordion-body` 的 `overflow: hidden` 配合 `max-height` transition 让这个高度塌陷**肉眼可见**（表现为手风琴收回去）→ 然后 `showGrid = true` 重建 grid → `.body-inner` 高度又弹回来（手风琴又展开）。

本质上是因为 **子元素 `v-if` 拔除导致容器高度变化，父元素的 `max-height transition` "感知"到了这个变化并播放了动画**。

### 最终的解决方案

**关键思路：不在 `.tag-grid` 上用 `v-if` 拔掉整个容器，而是在每个标签 `.tag-wrapper` 上用 `:key="cat.refreshId + '-' + ti"`，利用 `v-for` 的 key 变化驱动单个标签重建。**

这样 `.tag-grid` 容器始终在 DOM 里（不会造成高度崩塌），但每个标签的 key 随 `refreshId` 递增而变化 → Vue 销毁旧标签 DOM 元素 → 创建新标签 → CSS 动画在新元素上自动触发。

### 最终代码（当前代码状态）

**模板**：

```html
<!-- .tag-grid 不再有 v-if，始终在 DOM 中 -->
<view class="tag-grid">
	<view
		v-for="(t, ti) in cat.tags"
		:key="cat.refreshId + '-' + ti"        <!-- key 随 refreshId 变化 -->
		class="tag-wrapper"
		hover-class="press-9"
		:hover-start-time="0"
		:hover-stay-time="150"
		@click="goQuiz(t.name)"
	>
		<view :class="'tag-inner ' + t.cls" :style="t.animStyle">
			<text>{{ t.name }}</text>
		</view>
	</view>
</view>
```

**refreshCategory 方法**：

```javascript
refreshCategory(idx) {
	const cat = this.categories[idx]
	if (cat.refreshing) return
	cat.refreshing = true
	cat.spinDeg += 360          // 换一换图标旋转
	cat.refreshId++             // 递增 → v-for 的 key 变化 → 标签 DOM 逐个重建
	// 洗牌取新标签
	const arr = [...cat._allTags]
	for (let i = arr.length - 1; i > 0; i--) {
		const j = Math.floor(Math.random() * (i + 1));
		[arr[i], arr[j]] = [arr[j], arr[i]]
	}
	cat.tags = arr.slice(0, 16).map((t, i) => ({
		...t,
		animStyle: this.buildAnimStyle(i, cat.refreshId)
	}))
	cat.refreshing = false      // 同步释放锁，不需要 nextTick
},
```

**toggleCategory（手风琴展开/收起）**：

```javascript
toggleCategory(idx) {
	this.categories.forEach((c, i) => {
		c.expanded = i === idx ? !c.expanded : false
	})
},
```

不再需要 `showGrid` 属性，初始化和折叠逻辑全部简化。

**标签初始状态**（`loadData` 中）：

```javascript
return {
	name: c.name,
	subtitle: c.subtitle,
	emoji: c.emoji,
	expanded: false,
	refreshId: 0,
	refreshing: false,
	spinDeg: 0,
	_allTags: allTags,
	tags: arr.slice(0, 16).map((t, i) => ({
		...t,
		animStyle: this.buildAnimStyle(i, 0)
	}))
}
```

### 为什么这个方案有效

| 方案 | 原理 | 问题 |
|------|------|------|
| `v-if="cat.showGrid"` 拔掉整个网格 | 容器从 DOM 移除再重建，标签节点全新 → 动画触发 | 容器消失 → body-inner 高度塌陷 → 手风琴 transition 感知到 → 闪烁 |
| `:key="cat.refreshId + '-' + ti"` 逐个重建标签 | 容器始终存在，仅 v-for 下的子节点因 key 变化被逐个替换 → 新节点动画触发 | 容器高度不变 → 不触发手风琴 transition → 无闪烁 |

**核心要点**：在 uni-app 微信小程序中，只有 `v-for` 的 `:key` 变化才能可靠驱动子 DOM 节点重建。非 `v-for` 元素的 `:key` 变化（如方案 B 在 grid 容器上加 key）在编译为小程序后不生效。

### 副作用检查

- ✅ 手风琴首次展开：下拉动画正常（`.body-inner` 从无到有，新标签进入 DOM → 动画触发）
- ✅ 手风琴收起：`cat.expanded = false`，整个 `.body-inner` 被 `v-if` 移除 → `.accordion-body` 的 `max-height` 过渡关闭，无异常
- ✅ 换一换后：`refreshId` 递增 → 16 个 `.tag-wrapper` 的 key 全部变化 → 旧 DOM 销毁，新 DOM 创建 → CSS 动画从头播放，无容器高度闪烁
- ✅ 切换分类展开（手风琴互斥）：`cat.expanded = false` 收起当前 → `cat.expanded = true` 展开目标，`.body-inner` 重新创建 → 新标签动画正常
- ✅ 图标旋转动画：`cat.spinDeg` 递增 360 度，CSS transition 控制平滑旋转，不受影响
