# 特殊问卷方案讨论

## 背景

现有问卷系统匹配逻辑：每个题目关联一个维度 → 用户答题 → 计算各维度平均分 → **取最高维度** → 匹配到 `resultTypes` 中 `match` 字段对应的结果类型。

这套逻辑适用于「每维对应 1 个结果类型」的场景（如维度数 = 结果类型数）。

但新需求是一份 **28 个结果类型** 的特别问卷，无法为每个结果类型设计一个独立维度，需要新的匹配算法。

---

## 方案：给 `resultTypes` 加可选 `profile` 字段

### 核心思路

**不加 `type` 字段。** `profile` 字段的存在本身就是类型标记，不需要额外字段区分。

- `resultType` 有 `profile` → 五维向量欧几里得距离匹配
- `resultType` 没有 `profile` → 现有逻辑（单维度最大值匹配）

### 问卷结构

特殊问卷**不改变整体结构**。`dims`、`qs`、`tagName` 等全部复用，题目仍然通过 `dim` 字段关联 5 个维度，答题算分流程不变。

唯一区别在 `resultTypes`：

```json
// 普通问卷：match 一对一绑定维度名
{ "name": "结果A", "emoji": "🌭", "desc": "...", "match": "维度名" }

// 特殊问卷：profile 五维特征向量
{ "name": "结果A", "emoji": "🎯", "desc": "...", "profile": [90, 40, 60, 20, 85] }
```

本质：**普通问卷结构 + 每个 `resultType` 加一个可选 `profile`**。

### 匹配算法

用户答完题 → 计算 5 个维度的得分 → 得到 5 维向量 `raw = [82, 45, 67, 30, 91]`

遍历所有结果类型，计算每个 `profile` 与 `raw` 的欧几里得距离：

```
距离 = sqrt( Σ(profile[i] - raw[i])² ), i = 0..4
```

**距离最小者命中。**

## 技术实现细节

### 1. Schema 改动（`surveys.schema.json`）

两处改动：

**① `resultTypes.maxItems`：`10` → `35`**

```json
"maxItems": 35
```

**② `resultTypes.items.properties` 新增 `profile`**

```json
"profile": {
  "bsonType": "array",
  "description": "五维特征向量，0-100。有此字段则走向量匹配，无则走单维度最大值匹配",
  "items": { "bsonType": "number" }
}
```

**不放 `required`，不做 `minItems`/`maxItems` 校验。** 特殊问卷是手写的，不会配错。

### 2. `goResult()` 代码改动（`answer-quiz.vue`）

现有逻辑（第 615-616 行）：

```javascript
const topDim = dims.reduce((a, b) => raw[dims.indexOf(a)] >= raw[dims.indexOf(b)] ? a : b)
const result = this.survey.resultTypes.find(r => r.match === topDim) || this.survey.resultTypes[0]
```

改为：

```javascript
let result
if (this.survey.resultTypes[0].profile) {
  // 特殊问卷：五维向量欧几里得距离匹配
  const distances = this.survey.resultTypes.map(rt => {
    const sumSq = rt.profile.reduce((acc, p, i) => acc + Math.pow(p - raw[i], 2), 0)
    return Math.sqrt(sumSq)
  })
  const minIdx = distances.indexOf(Math.min(...distances))
  result = this.survey.resultTypes[minIdx]
} else {
  // 普通问卷：取最高维度（现有逻辑不变）
  const topDim = dims.reduce((a, b) => raw[dims.indexOf(a)] >= raw[dims.indexOf(b)] ? a : b)
  result = this.survey.resultTypes.find(r => r.match === topDim) || this.survey.resultTypes[0]
}
```

后续 `submitAnswer` / `redirectTo` 代码不变，`result` 对象已就位。

**判断条件 `resultTypes[0].profile`：** 因为一个问卷要么全是普通结果类型、要么全是特殊结果类型，不会混用，看第一个就够了。

### 3. 兼容性

| 数据 | 行为 |
|---|---|
| 官方预制问卷（无 `profile`） | 走旧逻辑，无影响 |
| Coze 生成的问卷（无 `profile`） | 走旧逻辑，无影响 |
| 未来 Coze 继续生成的新问卷 | 走旧逻辑，无影响 |
| 手写的特殊问卷（有 `profile`） | 走向量匹配，命中 28 个结果之一 |

- 旧问卷不需要迁移
- 不需要数据库批量改字段
- Coze 生成逻辑不需要改 prompt

### 4. 副作用分析

**无副作用。** 特殊问卷是手写的，你不会配错：

- `profile` 长度不会和 `dims` 不匹配（你手写时自然对齐）
- 值域不会溢出（你手写时自然在 0-100 内）
- 不会出现同一问卷混用 `profile` 和 `match`（你手写时自然统一）
