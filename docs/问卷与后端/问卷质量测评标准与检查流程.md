# 问卷质量测评标准与检查流程

> 用途：对 Coze 批处理节点产出的问卷进行质量审查，判断是否可入库。
> 受众：自动化脚本 / 其他 AI 窗口，按此文档执行检查即可，不需追问。

---

## 一、输入输出格式速览

### 1.1 Coze 批处理输入格式

```json
{
  "batch_data": [
    { "tagName": "确诊为烤肠", "tagDesc": "形容一个人表面光鲜但里面没什么真料" }
  ]
}
```

批处理节点输出的是一个数组，每个元素是一份问卷 JSON。

### 1.2 问卷 JSON 标准字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `tag` | string | ✅ | 标签名，必须与输入 `tagName` 一致 |
| `title` | string | ✅ | 问卷页面标题，不能是 `"{tagName}测试问卷"` 这种模板 |
| `dims` | string[] | ✅ | 维度名称列表，3-7 个 |
| `qs` | object[] | ✅ | `{ title: string, dim: string }`，每维 3 题 |
| `resultTypes` | object[] | ✅ | `{ name, emoji, emojiBg, desc, match }`，数量 = dims 数 |
| `prompt_version` | string | 否 | 提示词版本 |
| `_status` | string | 否 | `"success"` 或 `"failed"`（Coze 状态标记） |
| `_error` | string | 否 | 失败时的错误信息 |

## 二、硬性校验清单

**以下条件任意一条不满足 → 问卷无效，拒绝入库。**

### 2.1 `_status` 检查

- **`_status: "failed"`** → 生成失败，直接丢弃，标记需重跑
- **`_status: "success"`** 或不存在 → 进入下一步检查

### 2.2 兜底模板检测

标题如果等于 `"{tagName}测试问卷"`，说明 JSON 解析失败走了兜底逻辑，**问卷无效**，标记需重跑。

| tagName | 有效 title 示例 | 无效 title（兜底模板） |
|---------|---------------|---------------------|
| 领带薪拉屎冠军 | 你的工位延伸到了第几格？ | 领带薪拉屎冠军测试问卷 |
| 前世是什么外卖 | 你上辈子是哪份外卖？ | 前世是什么外卖测试问卷 |

### 2.3 `dims` 数量

- 范围：**3-7 个**
- 列表不能为空
- 维度名不能有空字符串或全是空格
- 维度名不能重复

### 2.4 题目数量与维度对应

- `qs.length` **必须等于** `dims.length × 3`
- 每条 `qs[i].dim` **必须在** `dims` 数组中
- 题目不能为空字符串

### 2.5 结果类型数量与匹配

- `resultTypes.length` **必须等于** `dims.length`
- 每个 `resultTypes[i].match` **必须在** `dims` 数组中
- 每个 `resultTypes[i].name` 不能为空
- 每个 `resultTypes[i].emoji` 不能为空
- 每个 `resultTypes[i].desc` 不能为空
- 每个 `resultTypes[i].emojiBg` 需为有效颜色值（如 `"#FFEAA7"`）

### 2.6 match 字段名一致性

**常见 bug：** match 字段名和 dims 里的维度名 **字面不一致**。

```json
// ❌ 失败案例（实际发生的）
"dims": ["静态姿势复杂度", ...],
"resultTypes": [{ "match": "静态姿势复杂性" }]
// ↑ "复杂度" vs "复杂性" —— 前端雷达图匹配不上
```

**检查规则：** 逐条对比 `resultTypes[i].match` 与 `dims` 数组，必须**完全字符串匹配**，包括标点符号和空格。

## 三、软性质量评分标准

硬性校验通过后，用以下标准对问卷进行质量评级。

### 3.1 评分维度（每条 0-5 分）

| 维度 | 0-1 分 | 2-3 分 | 4-5 分 |
|------|--------|--------|--------|
| **A. 概念创意** | 套模板、无新意，感觉是随机拼凑的 | 概念合理但不够出彩，属于"还行"级别 | 角度刁钻、有画面感，让人想立刻点进去 |
| **B. 维度设计** | 维度间重复/混淆，语义交叉严重 | 维度方向正确但不够精炼，有 1-2 个凑数的 | 每个维度都精准切中概念的一个侧面，互补不重叠 |
| **C. 题目质量** | 题目绕口/抽象/看不懂，或与维度不相关 | 大部分合理，少数题目方向与维度有偏差 | 每道题都像真实情景，直观贴切，有生活细节 |
| **D. 结果类型** | 名字/描述敷衍，没有画面感 | 名字合理但中规中矩 | 名字有趣、描述有梗，"哈哈哈哈是我"级别 |
| **E. emoji/配色** | 乱用 emoji，配色扎眼 | 中规中矩，不丑也不出彩 | emoji 贴切，配色舒服，有设计感 |

### 3.2 综合评级

| 总分 | 评级 | 建议 |
|------|------|------|
| 20-25 | ⭐⭐⭐⭐⭐ 卓越 | 直接入库，可做推荐/精选 |
| 15-19 | ⭐⭐⭐⭐ 优秀 | 直接入库 |
| 10-14 | ⭐⭐⭐ 合格 | 入库，但可考虑后续优化 |
| 5-9 | ⭐⭐ 较差 | 需要手动重写/重生成 |
| 0-4 | ⭐ 无效 | 丢弃 |

### 3.3 常见扣分项

- 维度名太抽象（如"指标 X"、"因子 Y"）→ 扣 2 分
- 题目都是问"你是不是XXX"这种同句式 → 扣 2 分
- 结果类型的描述只有一句话且很敷衍 → 扣 2 分
- emoji 和维度/结果类型不相关 → 扣 1 分
- 题目和 dim 方向的贴合度差，像是在凑数 → 扣 2 分
- 多维度题目的区分度不够，尺度不能拉开、接近无限循环 → 扣 3 分

## 四、失败模式速查表

| # | 失败模式 | 表现形式 | 根因 | 处理方式 |
|---|---------|---------|------|---------|
| 1 | 兜底空问卷 | `title="测试问卷"`, `dims/qs/resultTypes` 全空 | Coze 并发生成压力大，JSON 解析失败 | 单独重跑该标签 |
| 2 | match 不匹配 | match 字段与 dims 字面不一致（复杂度 vs 复杂性） | 大模型输出不稳定 | 手动修正 match 字段 |
| 3 | 维度数量不合格 | dims.length < 3 或 > 7 | 标签太抽象，大模型不知道往哪写 | 补充 tagDesc 后重跑 |
| 4 | 题目数不对 | qs.length ≠ dims.length × 3 | 少维度或多题 | 重跑或手动补齐 |
| 5 | 标签重复 | 语义相似的标签产出两份（如社恐等级 vs 社恐评级） | 生成时没做去重 | 合并或只留一份 |
| 6 | tag 与输入不一致 | tag 字段不等于 tagName | 大模型输入变量映射错误 | 手动修正 tag 字段 |

## 五、检查执行流程

```
step 1: 检查 _status
  ├── "failed" → 标记需重跑，跳过
  └── "success" / 无此字段 → 继续

step 2: 检查 title 是否为兜底模板
  ├── 等于 "{tagName}测试问卷" → 标记需重跑，跳过
  └── 正常标题 → 继续

step 3: 硬性校验
  ├── dims.length ∈ [3, 7] ?
  ├── qs.length === dims.length × 3 ?
  ├── 每题 dim ∈ dims ?
  ├── resultTypes.length === dims.length ?
  ├── 每个 resultTypes.match ∈ dims ?
  ├── match 字段与 dims 字面一致 ?
  ├── emojiBg 格式正确 ?
  └── 全部通过 → 进入软性评估

step 4: 软性质量评分
  ├── 概念创意 (0-5)
  ├── 维度设计 (0-5)
  ├── 题目质量 (0-5)
  ├── 结果类型 (0-5)
  ├── emoji/配色 (0-5)
  └── 汇总 → 评级

step 5: 输出检查报告
```

```markdown

- **质量评分：** XX/25
```

## 七、实测案例参考

以下为本项目实测中各评级的典型问卷，用于校准判断标准。

### 7.1 卓越案例（领带薪拉屎冠军）

- **评分：** 23/25
- **评价：** 6 维 18 题 6 结果。"战略规划性""风险对冲能力"两个维度角度刁钻，每道题都有真实生活细节（"进隔间前先确认手机电量、耳机和纸巾"），结果类型名有梗且有画面感
- **核心亮点：** 概念本身就搞笑，维度覆盖了从规划到收尾的全流程

### 7.2 卓越案例（废话大师鉴定）

- **评分：** 22/25
- **评价：** 5 维 15 题 5 结果。"跑题半径""闭环困难指数"非常精准，题目充满了"哈哈哈哈是我"的即视感

### 7.3 优质但有小问题案例（用睡觉姿势推测历史地位）

- **评分：** 18/25
- **问题：** match 字段写的是"静态姿势复杂性"但 dims 里是"静态姿势复杂度"——**字段名不一致**，需手动修正
- **修正后评级：** 可升至 22/25

### 7.4 合格案例（在同事群聊备注里叫什么）

- **评分：** 14/25
- **评价：** 概念合理，"备注来源权"视角刁钻。但 5 维 15 题相对保守，结果类型的中等偏多，没有特别亮眼的梗

### 7.5 无效案例（首次跑时的 6 个失败）

- **评分：** 0/25
- **表现：** `title="领带薪拉屎冠军测试问卷"`，`dims/qs/resultTypes` 全空
- **根因：** 并发压力导致 JSON 解析失败 → Coze 兜底返回空结构
- **处理：** 在 Coze 修复重试机制后重新运行，全部成功

## 八、常见 FAQ

### Q: 标题看起来像模像样但 dims 是空的？

**A:** 这是 Coze 批处理节点的另一种失败模式——部分字段生成了，关键字段（dims / qs / resultTypes）没生成。同样标记为需重跑。

### Q: 大部分题目不错，但有一道题的 dim 写错了怎么办？

**A:** 如果只有 1-2 处错误，手动修正后入库。如果是系统性错误（如所有题都不对应维度），重跑。

### Q: 同一个标签跑了两份问卷，留哪份？

**A:** 用评分标准评估两版，留分高的。分接近的话留**维度数更多**的那版（内容更丰富）。

### Q: 质量很差但硬性校验通过了，要不要入库？

**A:** 评分低于 10 分的不入库。这类问卷上线后用户不会喜欢，浪费数据库空间。标记为"质量不合格，需重新生成"。

### Q: 如何判断"维度间重复"？

**A:** 两个维度的题目互换后用户感知不到明显区别 → 说明这两个维度语义重叠。正常设计的维度应该让用户觉得"这是不同的方面"，而不是"同一个问题换了个问法"。

## 九、质检日志 CSV 格式规范

`Coze输出/质检日志.csv` 是每批问卷的质检记录文件，后续批次逐行追加，不覆盖历史记录。

### 9.1 列定义

| 列名 | 类型 | 必填 | 填写说明 |
|------|------|------|---------|
| `批号` | string | ✅ | 格式 `批XX_开始编号-结束编号`，如 `批01_1-40`。试跑批次填 `试跑-第1批` |
| `标签名` | string | ✅ | 对应问卷的 `tag` 字段 |
| `分类` | string | 否 | 来自标签元数据的 category，失败时可留空 |
| `_status兜底模板` | string | ✅ | `通过` / `失败` / `失败(兜底模板)`。_status=failed 或 title 等于 `{tagName}测试问卷` 都标记失败 |
| `dims数量` | string | ✅ | 格式 `N(正常)` 或 `N(异常)`，如 `6(正常)`、`2(异常)`。异常时在「问题」列说明 |
| `qs数量` | string | ✅ | 格式 `N=M×3` 或 `N≠M×3`，如 `18=6×3`、`15≠5×3` |
| `qs.dim匹配` | string | ✅ | `全部匹配` 或 `N题不匹配`。不匹配时在「问题」列写明具体哪些 dim 值 |
| `resultTypes数量` | string | ✅ | 格式 `N=M` 或 `N≠M`，如 `6=6`、`3≠6` |
| `match匹配` | string | ✅ | `全部匹配` 或 `N处不匹配`。不匹配时在「问题」列写明具体值 |
| `硬性校验` | string | ✅ | `通过` / `失败` / `修正后通过`。修正后通过代表有次要问题（如几处 match 错别字），手动修正后入库 |
| `概念创意` | int | ✅ | 0-5 分，失败问卷填 0 |
| `维度设计` | int | ✅ | 0-5 分，失败问卷填 0 |
| `题目质量` | int | ✅ | 0-5 分，失败问卷填 0 |
| `结果类型` | int | ✅ | 0-5 分，失败问卷填 0 |
| `emoji配色` | int | ✅ | 0-5 分，失败问卷填 0 |
| `总分` | int | ✅ | 五项评分之和，失败问卷填 0 |
| `评级` | string | ✅ | 根据总分：`⭐⭐⭐⭐⭐`(20-25) / `⭐⭐⭐⭐`(15-19) / `⭐⭐⭐`(10-14) / `⭐⭐`(5-9) / `⭐`(0-4)。失败问卷统一 `⭐ 无效` |
| `问题` | string | 否 | 详细描述硬性校验失败的原因，多个问题用分号隔开。通过的问卷可留空 |
| `处理方式` | string | ✅ | `直接入库` / `需修正match字段后入库` / `需重跑` / `丢弃` |

### 9.2 填写规则

1. **逐行一条**：每份问卷一行，不合并、不省略
2. **失败问卷直接填 0**：_status=failed 或命中的兜底模板的问卷，5 项评分全部写 0，评级写 `⭐ 无效`，硬性校验列填 `失败`，处理方式填 `需重跑`
3. **修正后通过**：硬性校验有非致命问题（如少数几处 match 同音/形近错字），手动修正后硬性校验填 `修正后通过`，软性评分正常打分
4. **分类列只在试跑批次填**：全量批次分类列留空，因为分类信息在标签元数据中，质检不需要重复填写
5. **对标点、空格敏感**：match 匹配检查时，中英文标点、全半角空格都必须严格匹配

### 9.4 追加方式

质检脚本每次运行，只将该批次的新行追加到 CSV 末尾，不修改已有行。格式要求：

- **BOM 头**：文件开头用 `\uFEFF`（UTF-8 BOM），确保 Excel 打开不乱码
- **引号转义**：字段内包含逗号或双引号时，整体用双引号包裹，内部双引号用 `""` 转义
- **行尾**：每行以 `\n` 结尾，不使用 `\r\n`
