## 一、背景

当前项目前端 5 个页面全部已跑通，但所有数据均为硬编码 mock。

现有后端基础设施：
- `uniCloud-alipay/database/` 下有 `surveys.schema.json`、`survey-answers.schema.json`、`tools.schema.json`——**但属于过时架构，不采用**
- `uniCloud-alipay/cloudfunctions/` 下有 `tools`、`ai`、`product` 三个云函数——**`ai` 云函数名字过短，后续重写**

需要从零设计数据结构，建立"标签 → 问卷"的完整生产管线，使前端能够从真实数据源动态获取内容。

## 二、核心概念：标签 ≠ 问卷

标签和问卷是两个独立的实体，一个标签可以关联多份问卷。

**示例：**
```
标签"确诊为烤肠"
  ├─ 问卷版本A（题目偏"淀粉含量"方向）
  ├─ 问卷版本B（题目偏"精神状态"方向）
  └─ 问卷版本C（题目偏"社交属性"方向）

用户点击"确诊为烤肠" → 从 A/B/C 中随机抽取一套 → 答题
```

### 这种设计的价值

1. **内容多样性**：同一个标签，不同用户可能抽到不同的题，降低了重复感
2. **润色替换**：后续如果某份问卷被 Coze 润色出新版本，可以保留旧版继续使用，新旧共存
3. **后续广告生成**：当用户搜索不到时，Coze 实时生成的新问卷就是一个标签对应一份新问卷

### 数据关系

```
survey-categories  ←  1:N  →  survey-tags  ←  1:N  →  surveys
    分类                     标签                问卷（可多份）
```

## 三、需要新建的数据表

### 3.1 `survey-categories` — 分类（搜索页手风琴组）

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 自动生成 |
| `name` | string | 分类名（如"生活百态"、"校园日常"） |
| `emoji` | string | 分类 emoji |
| `subtitle` | string | 简短描述（搜索页显示） |
| `sort` | number | 排序权重 |

### 3.2 `survey-tags` — 标签元数据

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 自动生成 |
| `name` | string | 标签名，唯一且必须是有趣的测评标题（如"确诊为烤肠"） |
| `category` | string | 所属分类 ID，关联 `survey-categories` |
| `emoji` | string | 标签 emoji（如 "🌭"） |
| `description` | string | 简短描述 |
| `popularity` | number | 热度（初始 0，后续按答题次数递增） |
| `status` | string | `draft` / `published` / `disabled` |
| `surveyCount` | number | 该标签下的问卷数量（冗余字段，方便展示） |
| `createDate` | timestamp | 创建时间 |

**注意：** 不直接在 `survey-tags` 中存问卷 ID 关联。问卷通过 `tagName` 字段关联回标签，这样新增/删除问卷不影响标签数据。

### 3.3 `surveys` — 问卷实体

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 自动生成 |
| `tagName` | string | **必填**，关联的标签名（如"确诊为烤肠"），答题页头部直接展示 |
| `dims` | string[] | 维度列表（3-7 个） |
| `qs` | object[] | 题目数组（详见下方结构） |
| `resultTypes` | object[] | 结果类型数组（详见下方结构） |
| `status` | string | `active` / `disabled` |
| `createDate` | timestamp | 创建时间 |

**qs 元素结构：**
```json
{
  "title": "周末你更倾向于一个人待着？",
  "dim": "淀粉含量"
}
```

**resultTypes 元素结构：**
```json
{
  "name": "纯正淀粉肠",
  "emoji": "🌭",
  "emojiBg": "#FFE4B5",    // 结果卡片背景色，Coze 提供
  "image": "",              // 结果配图 URL（预留，当前留空）
  "desc": "你就是一根纯粹的淀粉肠……",
  "match": "淀粉含量"
}
```

> 数据结构采用 Coze 友好版，所有评分逻辑在前端完成。详见 `docs/问卷数据结构规范.md`。

## 四、Coze 工作流设计

### 4.1 标签批量生成工作流（新建）

| 项目 | 说明 |
|------|------|
| **用途** | 一次生成 30-50 个标签 |
| **输入** | 种子提示（风格约束） |
| **输出** | `[{ name, category, emoji, description }]` |
| **生成方式** | 在 Coze 平台手动运行，输出 JSON 后由开发者手动检查并上传 |

**输入示例：**
```json
{ "seed": "社恐、确诊文学、精神状态、MBTI 风格" }
```

**输出示例：**
```json
[
  { "name": "确诊为烤肠", "category": "life", "emoji": "🌭", "description": "测测你是一根什么肠" },
  { "name": "搬屎大王", "category": "daily", "emoji": "💩", "description": "你的搬屎指数有多高" }
]
```

### 4.2 问卷生成工作流（新建，取代旧的 question 工作流）

| 项目 | 说明 |
|------|------|
| **用途** | 根据标签生成完整问卷 |
| **输入** | `{ tagName, tagDesc }` |
| **输出** | `{ title, dims, qs, resultTypes }` |
| **生成方式** | 在 Coze 平台手动运行，一个标签可以多次运行生成多份不同版本的问卷 |
| **输出格式** | 按 `docs/问卷数据结构规范.md` 的 Coze 友好版格式 |

**输出格式要求：**
```json
{
  "tag": "确诊为烤肠",
  "title": "你被确诊为什么东西？",
  "dims": ["淀粉含量", "加肉程度", "受欢迎度", "性价比", "抗造性"],
  "qs": [
    { "title": "周末你更倾向于一个人待着？", "dim": "淀粉含量" },
    { "title": "你吃泡面会加肠吗？", "dim": "加肉程度" }
  ],
  "resultTypes": [
    { "name": "纯正淀粉肠", "emoji": "🌭", "desc": "...", "match": "淀粉含量" },
    { "name": "货真价实肉肠", "emoji": "🍖", "desc": "...", "match": "加肉程度" }
  ]
}
```

**约束规则（Coze 提示词中体现）：**
- `dims.length`：3-7 个
- `qs.length` = `dims.length × 3`
- 每题 `dim` 必须在 `dims` 列表中
- `resultTypes` 至少 1 个，`match` 必须在 `dims` 列表中
- `tag` 必须与输入的 `tagName` 一致

## 五、需要新增的云函数

> **云函数定位调整：**
> - 废弃原有的 `ai` 云函数（名字过短 + 架构过时）
> - 不需要写自动调用 Coze 的云函数（生成由开发者手动操作）
> - 云函数只负责前端数据消费和基础业务逻辑

### 5.1 新建 `survey` 云函数（替代 `ai`/`tools` 的问卷部分）

**云函数命名规范：** 以业务领域命名，当前领域为"问卷业务"。

#### `getTagList({ category, page, pageSize, sortBy })`
- **说明：** 前端获取标签列表
- **支持：** 按分类筛选、分页、按热度/随机排序
- **返回值：** 分页后的标签数组 + 总数

#### `getCategories()`
- **说明：** 前端获取分类列表（搜索页手风琴分组）

#### `getSurveyByTag({ tagName, randomSeed })`
- **说明：** 根据标签名获取一份随机问卷
- **逻辑：**
  1. 查 `surveys` 中 `tagName = tagName` 且 `status = active` 的所有问卷
  2. 随机选取一份返回
  3. 如果只有一个问卷就直接返回
- **为什么不用前端随机：** 后续可以加入"用户历史答题去重"逻辑

#### `submitAnswer({ tagName, surveyId, answers, scores, resultType })`
- **说明：** 提交答题记录（可选，初期可以前端本地算分不提交后端）

#### `getHotTags({ limit })`
- **说明：** 获取热搜标签（按 `popularity` 降序）

## 六、数据生产流程

```
阶段一：分批在 Coze 生成标签
  │
  ├─ 打开 Coze 标签工作流，输入种子 → 跑一次得 30-50 个标签
  ├─ 检查输出质量（去重/分类是否合理/名字是否有趣）
  └─ 检查通过 → 导出 JSON

阶段二：手动上传标签数据
  │
  ├─ 将 JSON 写入 survey-tags 的 init_data.json
  └─ 或通过管理后台手动导入

阶段三：分批在 Coze 生成问卷
  │
  ├─ 逐个标签跑 Coze 问卷工作流
  ├─ 一个标签可以跑多次，生成多份不同版本的问卷
  ├─ 检查每份输出的完整性（维度/题目/结果匹配）
  └─ 检查通过 → 导出 JSON

阶段四：手动上传问卷数据
  │
  ├─ 将 JSON 写入 surveys 的 init_data.json
  └─ 或通过管理后台手动导入

阶段五：前端接入消费
  │
  ├─ quiz-home 首页 → 调 getTagList 显示标签池
  ├─ search 搜索页 → 调 getCategories + getTagList
  └─ answer-quiz 答题页 → 调 getSurveyByTag 拿随机问卷
```

## 九、待讨论问题

### 1. 标签去重（语义级别）

Coze 批量生成时可能产出语义高度相似的标签（如"社恐等级测试"和"社交恐惧症评级"）。

**希望方案：** Coze 工作流在生成时自己检测相似标签并合并或剔除。需要编写提示词让大模型做语义去重。

### 2. 数据格式兼容

现有 `surveys.schema.json`（旧架构）使用 `ranges`/`score` 格式，新架构采用 Coze 友好版 `match`/`dim` 格式。

**方案：** 直接用新格式重写 `surveys.schema.json`，废弃旧格式。不兼容问题由开发者手动处理。

### 3. 一个标签下的问卷版本管理

同标签多份问卷时，`answer-quiz.vue` 中 `getSurveyByTag` 随机返回一份。后续需要：
- 记录用户已答过的版本，不重复出
- 某个版本质量差时可以手动 disable

这些等到前端接入时再讨论细节。
