# 问卷生成系统设计——标签重名、署名与用户生成

> 生成时间：2026-05-15（首次编写）／2026-05-15（补充用户生成流程）
> 状态：**已定稿**
> 关联文档：`docs/问卷与后端/后端总纲——标签与问卷生产流程.md`、`docs/待做事项.md`

---

## 一、背景

用户生成标签功能上线后，不同用户可能创建同名的标签（"确诊为芋泥波波奶茶" → 小狐狸版 vs 奶茶仙人版）。如果 `tagName` 设为唯一约束，第二个用户会被阻止，但体验非常糟糕——他搜不到同名标签，却无法创建同名标签，陷入死锁。

需要一种既允许重名、又保证数据不混淆的方案，同时配套完整的用户生成流程和可见性规则。

---

## 二、核心方案：唯一 ID + 同名共存

### 2.1 数据层

`survey-tags` 表的 `tagName` **不设唯一约束**。同名标签共存，区分依据是 `_id`。

用户生成标签的额外字段（相比预置标签）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `creatorId` | string | 创建者用户 ID，关联 `uni-id-users` |
| `source` | string | `'system'`（预置）或 `'user'`（用户生成） |
| `shareCount` | number | 分享计数，达到阈值后进入公共池 |
| `rarity` | string | 稀有度等级，由综合数据动态计算 |

```json
// 两条记录可以 tagName 相同
{
  "_id": "abc123",
  "name": "确诊为芋泥波波奶茶",
  "creatorId": "user_001",
  "source": "user",
  "shareCount": 0,
  "rarity": "common"
}

{
  "_id": "def456",
  "name": "确诊为芋泥波波奶茶",
  "creatorId": "user_002",
  "source": "user",
  "shareCount": 0,
  "rarity": "common"
}
```

| 场景 | 行为 |
|------|------|
| 用户 B 创建同名标签 | 直接生成新记录，`_id` 不同，互不影响 |
| 用户 B 搜索 | 搜到的是自己可看到的结果（自己的 + 已晋升公共的），如果两个同名标签都达到了可见条件，**都展示** |
| 分享 / 收藏 | 按 `_id` 走，各算各的，不混淆 |
| 晋升公共（≥200次分享） | 各自的分享数独立计算，互不干扰 |

### 2.2 需要改的东西

- `survey-tags` 表：确认 `name` 字段无唯一索引（大概率没有，如有则删除索引）
- `survey-tags` 表：新增 `creatorId`、`source`、`shareCount`、`rarity` 字段
- 其余部分几乎不涉及代码改动，因为底层本来就是以 `_id` 为准的

## 三、署名方案：存 ID，不存名字

### 3.1 核心原则

不要在每条标签/问卷上存用户当前的署名，**只存用户的 `creatorId`**。署名存在 `uni-id-users` 表或 `uni-id-users` 附属的用户画像字段中。

```
survey-tags 记录
├── tagName: "确诊为芋泥波波奶茶"
├── creatorId: "user_xxx"    ← 存 ID，不存名字
└── ...
```

### 3.2 改署名时的数据一致性

用户改了署名 → **只改 `uni-id-users` 里的一条记录** → 所有历史标签自动更新。

无需批量更新、无需数据迁移、永远不会出现"旧的署名还留在老问卷上"的情况。

### 3.3 展示时怎么拿名字

前端拿到搜索结果列表后，**收集所有不同的 `creatorId`**，调一个轻量云函数批量查回来：

```
前端 → batchGetDisplayNames({ userIds: ["id1", "id2", ...] })
    → 云函数查 uni-id-users 返回 { "id1": "嘎嘎", "id2": "神秘人" }
    → 前端把名字填到每条结果里展示
```

**不用 N+1 查询**，一次批量查完。

### 3.4 默认值

用户未设置署名时，默认显示 `"神秘人"`。逻辑在云函数侧处理，前端无感知。

## 四、同名标签的展示方案

同名时，在搜索结果项的标签名字右侧加一个轻量的创建者标识：

```
🥤 确诊为芋泥波波奶茶  ·  来自 小狐狸
🥤 确诊为芋泥波波奶茶  ·  来自 奶茶仙人
```

规则：
- **同名时才显示** "· 来自 XXX"
- **无同名冲突就隐藏**，不增加视觉噪声
- 样式：12px 灰字，与 result-title 同色系

## 五、用户画像中的署名功能

### 5.1 功能定义

在用户画像/个人中心加一个"修改昵称/署名"的入口。这个署名用于：

- 标识该用户创建的标签/问卷（"来自 XXX"）
- 未来如支持评论等功能时也可复用

### 5.2 实现要点

- 修改操作：调云函数更新 `uni-id-users` 的对应字段
- 无需批量更新任何标签数据（因为存的是 ID）
- 修改后立刻生效，所有历史标签展示新的署名

## 六、看广告生成问卷流程

> 对应待做事项 #14，最高优先级。

### 6.1 流程

```
用户搜索无结果 → 弹窗"要不要看广告生成？"
  → 弹出标签输入框（标签名 + 标签描述，描述限 30 字）
  → 播放激励视频广告
  → 广告期间 Coze 实时生成问卷（仅需 tagName 即可正常生成，无需 tagDesc）
  → 生成完成后直接跳答题页
```

- 标签描述输入框限制最多 30 个字符，超出不可输入
- `tagDesc` 为可选补充，传空也不影响 Coze 生成

### 6.2 标签标记方式

`survey-tags` 表通过 `source` 字段区分标签来源：

- `'system'` — 预置标签（默认）
- `'user'` — 用户通过看广告生成的标签

也可用 `isUserGenerated: true` 布尔字段替代，选一个即可。推荐 `source` 字符串字段，扩展性好（未来可加 `'coze_v2'` 等来源）。

### 6.3 入口

- **触发入口**：搜索页搜索结果底部"看广告定制"卡片，点击后开始广告→生成流程
- **筛选入口**：个人页或搜索页新增"📦 我的定制"入口，点击只展示 `source: 'user'` 且 `creatorId === 当前用户` 的标签列表

### 6.4 可见性规则（按时间线）

| 阶段 | 可被搜索 | 可被标签池刷新 | 可分享 | 可收藏 | 进历史记录 |
|------|---------|--------------|--------|--------|-----------|
| 刚生成 | ❌ | ❌ | ✅ | ✅ | ✅ |
| 分享 ≥ 200 次 | ✅ | ✅ | ✅ | ✅ | ✅ |

- **分享计数**：`survey-tags.shareCount`，每次分享卡片时 +1
- **晋升条件**：`shareCount >= 200` 时，云函数将该标签设为搜索可见（`searchable: true`），进入公共搜索池和标签池刷新列表
- 可见性晋升不改变 `source` 字段，`source` 始终保持 `'user'`，标签仍归属于创建者

### 6.5 稀有度

用户生成的问卷从创建那一刻就拥有动态稀有度，随用户互动数据实时演变。**任何用户生成的问卷都有潜力成长为最高稀有度（暗金）。**

**稀有度维度（综合计算，算法待设计）：**

| 指标 | 权重 | 数据来源 |
|------|------|---------|
| 点击量（热度） | 高 | `survey-tags.popularity`（每次答题 +1） |
| 点赞数 | 中 | `survey-likes` 表按 tag `_id` 统计 |
| 收藏数 | 中 | `survey-favorites` 表按 tag `_id` 统计 |
| 分享数 | 高 | `survey-tags.shareCount` |

> **注：** 以上维度及各档权重为定性参考，具体算法和升级阈值待实现时设计，写死为常量即可，不做动态配置。

**稀有度等级（从低到高）：**

```
普通（Common） → 优秀（Rare） → 史诗（Epic） → 暗金（Legendary）
```
- 创建时默认为 `common`
- 达到不同阈值自动升级，**只升不降**
- 暗金（Legendary）没有上限——只要用户互动数据够好，任何标签都有机会

**升级规则：**
- 标签的稀有度只看累计成就，不看近期趋势，所以不存在下降
- 云函数定期（或每次触发互动事件时）重新计算 `rarity` 字段，仅当综合得分超过下一级阈值时提升
- 也可以采用惰性计算——只有当用户查看标签详情/搜索结果时才触发计算，避免频繁写库

**扩展建议：**
- 前端用 `rarity` 驱动视觉表现：大小、颜色、标签上的特效徽章
- 后续可对接标签稀有度系统（待做事项 #12）的通用能力

### 6.6 涉及文件

- `survey-tags` 表 schema（新增 `creatorId`、`source`、`shareCount`、`rarity` 字段）
- `survey/index.obj.js`（新增生成触发、分享计数、晋升逻辑、稀有度计算）
- 搜索页（"看广告定制"卡片、稀有度视觉展示）
- 个人页（"📦 我的定制"入口和列表、创建者标签稀有度概览）

## 七、总结

| 维度 | 方案 | 优点 |
|------|------|------|
| 重名策略 | 唯一 ID + 同名共存 | 零约束，用户不困惑 |
| 署名存储 | 存 `creatorId`，不存名字 | 改署名即时生效，无需迁移 |
| 署名查询 | 批量查 → 前端填充 | 一次接口完成，不 N+1 |
| 同名展示 | 同名时加 "· 来自 XXX" | 区分清楚，无冲突时隐藏 |
| 默认值 | `"神秘人"` | 不暴露用户隐私 |
| 用户生成 | 看广告 → Coze 实时生成 | 满足长尾需求，零库存成本 |
| 可见性晋升 | 分享 ≥ 200 次 → 公共搜索可见 | 去中心化筛选，质量自验证 |
| 稀有度进化 | 综合热度/点赞/收藏/分享，只升不降，无上限 | 每个用户生成的标签都有机会成为暗金，且不会掉回去 |
