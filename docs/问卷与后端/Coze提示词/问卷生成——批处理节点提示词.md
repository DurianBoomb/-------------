# Coze 批处理节点配置 · 批量问卷生成

> 用途：在问卷生成工作流中加入批处理节点，一次处理 40 个标签
> 输入方式：上游节点传入包含 tagName + tagDesc 的对象数组
> 输出格式：含 40 个问卷结果的数组

---

## 一、批处理节点位置

在你的问卷生成工作流中，找到「批处理」节点（图标是一个播放列表/并行符号）。将此节点插入在以下位置：

```
[输入节点] → [批处理节点] → [汇总节点/直接输出]
```

---

## 二、输入配置

### 2.1 来源

批处理节点的输入为**裸数组**，不需要外层对象包裹：

```json
[
  { "tagName": "确诊为烤肠", "tagDesc": "形容一个人表面光鲜但里面没什么真料" },
  { "tagName": "社交电池容量", "tagDesc": "测你的社交能量上限，见人掉电、独处充电" },
  { "tagName": "深夜emo等级测试", "tagDesc": "一到深夜就开始多愁善感，测你有多严重" }
]
```

> ⚠️ Coze 批处理节点的根对象必须是 **array** 类型，不要套 `batch_data` 外层。

### 2.2 输入变量映射

在批处理节点的输入配置中：

| 配置项 | 值 |
|--------|---|
| **数据来源** | 直接选中整个数组变量（或手动粘贴数组） |
| **单条变量名** | `tagName` |
| **单条变量名** | `tagDesc` |
| **并发数** | `8` |

> 并发数 8：每批处理 8 个标签（总 40 个，分 5 批跑完）。LLM 节点属于计算密集型，不建议超过 10。

---

## 三、批处理体内部结构

批处理体内是一个简化版的问卷生成流程。每个 `tagName` 独立执行以下节点：

```
[tagName + tagDesc] → [大模型节点：用「问卷生成提示词」生成问卷 JSON] → [输出 tagName + 生成的 JSON]
```

### 3.1 大模型节点

将现有的**问卷生成提示词（合并版）** 复制粘贴到此节点的系统提示词中。

### 3.2 输入/输出映射

**输入变量：**

| 变量 | 来源 | 说明 |
|------|------|------|
| `sys.tagName` | 批处理传入的 `tagName` | 单条标签名 |
| `sys.tagDesc` | 批处理传入的 `tagDesc` | 这条标签的创作方向说明 |

> **提示**：在「问卷生成提示词（合并版）」的输入格式部分，将 `tagName` 输入扩展为同时接收 `tagName` 和 `tagDesc`。大模型看到描述后能更准确地把握这个标签该往哪个方向写题——比如"确诊为烤肠"如果描述说"表面光鲜里面没料"，题目的方向感会完全不同。

**输出格式要求：**

大模型节点的输出必须是**纯 JSON 对象**（与合并版提示词的输出格式一致），包含：

```json
{
  "tag": "确诊为烤肠",
  "title": "你是一根什么肠？",
  "dims": ["淀粉含量指数", "爆裂阈值", "翻面频率"],
  "qs": [ ... ],
  "resultTypes": [ ... ]
}
```

**注意**：确保大模型节点的输出配置中**不包含任何额外字段或包裹**，直接输出上述 JSON。

---

## 四、输出汇总

批处理节点的输出是一个数组，包含 40 个元素，结构如下：

```json
[
  {
    "tag": "确诊为烤肠",
    "title": "你是一根什么肠？",
    "dims": ["淀粉含量指数", "爆裂阈值", "翻面频率"],
    "qs": [ 9个题目 ],
    "resultTypes": [ 3个结果类型 ]
  },
  {
    "tag": "社交电池容量",
    "title": "你的社交电池多大？",
    "dims": ["满电容量", "耗电速率", "回血速度"],
    "qs": [ 9个题目 ],
    "resultTypes": [ 3个结果类型 ]
  },
  // ... 共 40 条
]
```

---

## 五、速度预估

以并发数 8、单次 LLM 调用约 10-15 秒计算：

| 阶段 | 耗时 |
|------|------|
| 40 个标签 ÷ 8 并发 = 5 轮 | 每轮 ≈ 10-15 秒 |
| **总耗时** | **≈ 50-75 秒** |

实际耗时取决于模型响应速度（4o / Claude / DeepSeek 有差异）。

## 六、注意事项

### 6.1 错误处理

如果某个标签生成失败（JSON 格式错误/字段缺失），批处理节点**不会中断整个流程**。该条数据会在输出数组中留空或携带错误信息。你可以在下游加一个「数据清洗」节点来过滤掉失败条目。

### 6.2 批量上限

Coze 批处理节点单次上限 100 条，最多 200 条。40 条完全在安全范围内。

### 6.4 并发失败隐患

**现象：** 10 个标签并行发送时，部分请求因 LLM 并发压力大导致 JSON 格式异常，返回空结构（`dims:[], qs:[], resultTypes:[]`，标题变成 `"{tagName}测试问卷"` 的兜底格式），且无任何报错提示。

**根因：** Coze 批处理节点的底层代码在 JSON 解析失败时**静默返回空结构**，不记录原始响应文本，也没有重试机制。

**修复状态：** ⚠️ **需自行确认 Coze 平台是否已修复。** Coze 官方给出的修复方案：
- 解析失败时抛异常触发重试
- 重试 3 次 + 指数退避（1s → 2s → 4s）
- 记录原始响应前 200 字符到日志

**建议：**
- 跑完一批后检查输出中是否含 `_status: "failed"` 或 `_error` 字段
- 有失败的标签**单独重跑**即可，不是标签内容的问题
- 如需大量重复生成，建议降低并发数到 4-5 以减少碰撞概率

### 6.3 测试验证

先在批处理节点的输入中写一个**3 条的小数组**测通，确认输出格式正确后，再换成 40 条跑全量。

示例小数组（**裸数组，不包 batch_data**）：
```json
[
  { "tagName": "确诊为烤肠", "tagDesc": "形容一个人表面光鲜但里面没什么真料" },
  { "tagName": "社交电池容量", "tagDesc": "测你的社交能量上限，见人掉电、独处充电" },
  { "tagName": "深夜emo等级测试", "tagDesc": "一到深夜就开始多愁善感，测你有多严重" }
]
```

## 七、整体工作流结构参考

```
[开始节点]
  │
  ├── 输入：[40 个 { tagName, tagDesc }]
  │
  ▼
[批处理节点] ← 并发 8
  │
  ├── 批处理体：[大模型节点]
  │     系统提示词：问卷生成提示词（合并版）
  │     输入变量：{{tagName}}, {{tagDesc}}
  │     输出：单个问卷 JSON
  │
  ▼
[输出节点]
  │
  └── 输出：40 个问卷 JSON 的数组
```

> 提示：如果后续需要对所有问卷做统一的数据处理（如聚合统计、转存数据库），可在批处理节点后加一个「代码节点」做后处理。
