# Coze 工作流更新说明 · 在输出中加入 tagDesc

> 用途：指导你在 Coze 平台上更新**问卷生成工作流**（对应 bot 系统提示词 `问卷生成——Coze工作流提示词（合并版）.md`），
> 让工作流的输出 JSON 额外包含 `tagDesc` 字段，用于入库 `survey-tags.description`。

---

## 一、为什么要改

当前工作流的行为已经是这样了——

- 输入收到 `tagDesc` 就走优化（第四章 情况 B）
- 输入没收到 `tagDesc` 就自行生成（第四章 情况 A）

但是 **输出的 JSON 里没有 `tagDesc 字段**，生成/优化后的描述只存在于工作流的内部上下文里，前端和后端都拿不到。

改完之后，输出 JSON 会多了 `tagDesc`，供后端入库到 `survey-tags.description`。

---

## 二、改什么

### 2.1 改 bot 系统提示词（已改好）

`docs/Coze提示词/问卷生成——Coze工作流提示词（合并版）.md` 中的 **第四章 标签描述预处理** 已经写好了生成/优化 tagDesc 的完整逻辑。你只需要在 Coze 平台上把这个文件的最新内容粘贴覆盖即可。

### 2.2 改输出格式——给生成的 JSON 加一个字段

在提示词中，**第九章（输出格式）** 范例如下——需要在 JSON 顶层加一行 `tagDesc`：

```json
{
  "prompt_version": "2.0",          // ← 可以顺手改成 "2.1"
  "tag": "确诊为烤肠",
  "tagDesc": "表面光鲜但里面没什么真料，一烤就爆",   // ← 新增这行
  "title": "你是一根什么肠？",
  "dims": [ ... ],
  "qs": [ ... ],
  "resultTypes": [ ... ]
}
```

### 2.3 字段说明表加一行

在提示词字段说明表中追加：

| `tagDesc` | 标签描述。经过预处理后最终确定的版本——可能是用户提供的优化版，也可能是自行生成的。风格：生活观察，不是功能介绍。 |

### 2.4 最后检查加一条

在第十章（最后检查）追加：

4. **`tagDesc` 不是功能介绍。** 读一遍——它像"测测你的XX"吗？像就重写。它像"我们都这样"的生活观察吗？像就过。

---

## 三、如果你在 Coze 里配置的是多节点工作流

如果你的问卷生成工作流不是"一个 bot 一锅端"，而是拆成了多个节点（比如一个 LLM 节点处理解剖，另一个节点出题），那需要额外做一件事：

### 3.1 确认 tagDesc 在节点间传递

在**第一个节点**（负责标签描述预处理 + 解剖）的输出中，**必须显式在输出结构里带上 tagDesc**，否则下游节点接不到。

在第一个节点的输出配置中增加：

```json
{
  "tagDesc": "……",
  ...
}
```

### 3.2 最后一个节点的输出加上 tagDesc

在你最终输出 JSON 的节点（通常是最后一个 LLM 节点或 Code 节点），把 tagDesc 加到输出结构里。确保：
- `tagDesc` 的值来自第一步预处理后的版本（不是原始输入，是生成/优化后的版本）
- 不要二次加工——生成/优化已经在第一步做完了，最后一步只是原样带出去

### 3.3 如果你用 Code 节点做 JSON 组装

在 Code 节点里找到组装 JSON 的地方，补一行：

```javascript
// 在最终对象里加入 tagDesc
output.tagDesc = input.tagDesc;  // 或 context.tagDesc
```

---

## 四、验证方法

在 Coze 平台打开工作流，分别用以下两种输入跑测试：

**测试 1：不带 tagDesc**
```json
{ "tagName": "确诊为烤肠" }
```
期望：输出的 `tagDesc` 是一个自行生成的生活观察描述，不是功能介绍。

**测试 2：带 tagDesc**
```json
{ "tagName": "确诊为烤肠", "tagDesc": "测测你的烤肠类型" }
```
期望：输出的 `tagDesc` 被优化为生活观察风格，不再是"测测你的XX"。

**测试 3：带好的 tagDesc**
```json
{ "tagName": "确诊为烤肠", "tagDesc": "表面光鲜但里面没什么真料" }
```
期望：输出的 `tagDesc` 与输入一致（原文过关，不做改动）。

三个测试都通过，说明工作流更新正确。
