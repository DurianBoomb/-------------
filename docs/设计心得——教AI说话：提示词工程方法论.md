# 教AI说话：面向自然语言生成的提示词工程方法论

> 副标题：从"让AI写出不像AI的句子"到"让AI生成完整的可交付内容"——基于趣味问卷生成项目的工程实践记录
>
> 作者：张哲晗（产品/方向） & 张渊（执行/记录）
>
> 日期：2026-05-11
>
> 适用范围：本方法论适用于任何需要 AI 产出"自然感很强"的文字内容的场景——不限于问卷生成，可迁移至文案、选题、测试题、人格描述等。

## 一、摘要

本文件记录了一套围绕"用 AI 产出自然语言内容"的完整方法论。它回答的不是"怎么写提示词"这个泛问题，而是**"怎么让 AI 写出来的东西读起来像人写的，而不是像 AI 填的"**这个具体问题。

方法论基于"快乐大狐狸工具集"项目中的趣味问卷生成实践，经历了从直觉试调到理论框架建立、从理论到可执行约束体系、从约束体系到结构性重构的三个完整周期。最终沉淀为六条可操作的方法，以及三条"这样写一定会死"的反模式警示。

## 二、问题定义

### 2.1 "AI味"是什么

"AI味"不是一个模糊的直觉判断，它可以被精确描述。在大量试调中，我们发现 AI 产出的文字只要具备以下特征之一，就会让人类读者感到"不对"：

| 特征 | 表现 | 读者感受 |
|------|------|---------|
| **句法单调** | 句句以"我"开头，句式重复 | "像机器人写的" |
| **抽象化** | 用抽象概念替代具体场景 | "不接地气" |
| **解释自己** | 加了括号注释、补充说明 | "你在教我做事？" |
| **打磨痕迹** | 修辞精致到不像是人随口说的 | "太正经了" |
| **模板感** | 同一结构反复出现，缺乏随机性 | "复制粘贴的" |
| **概括人群** | "当代年轻人""大多数人都" | "你代表不了我" |

### 2.2 为什么这是个难题

让 AI 写出不像 AI 的东西之所以难，有三个深层原因：

**原因一：训练数据的分布偏差。**
AI 的训练数据中，规范、正式、结构化的文本（维基百科、新闻稿、教科书）占绝大多数。自然口语、带毛边的日常对话比例极低。模型天然倾向输出"像维基百科的句子"而非"像人随口说的句子"。

**原因二：输出格式的诱导效应。**
当 AI 知道自己的输出要被解析为 JSON、填入模板、供给下游使用时——这个认知本身就会让它倾向于"规范、完整、不出错"的表达，而**恰好是这种"不出错"的表达，读起来最不像人**。

**原因三：约束监控的注意力消耗。**
AI 在生成长文本时，如果同时需要维护格式约束（JSON 结构）、逻辑约束（维度来源正确）、内容约束（自然感强），它会优先保证前两者。自然感是"最后被挤掉的那个"。

这三者共同构成了一个不可能三角——**严格约束 → 规范输出 → 自然感丢失**。本方法论的每一处设计都在试图打破这个三角。

### 2.3 本问题的特殊场景

本方法论产生的具体场景是：**Coze 平台 + LLM 单次调用 + 纯 JSON 输出 → 趣味问卷**。

这意味着：
- 没有多轮对话（没有"修正"机会）
- 没有思维链（thinking block 需要额外节点）
- 输出格式固定（JSON，不能被 Markdown 包裹）
- 单次调用的 token 量有限（不能发太多示例）

这些限制让"教 AI 说话"的难度又高了一层——必须在一次回答中，同时完成"理解任务→执行流程→写自然句子→格式化 JSON→自检修正"五个动作。

## 三、理论框架

### 3.1 概念隐喻理论（Lakoff & Johnson）

这是本项目最早借用的理论框架，用于解决"实体-人映射"场景下的内容偏离问题。

**核心概念**：隐喻不是修辞手段，是认知机制。人们通过一个概念域（源域）的结构来理解另一个概念域（目标域）。

**不变原则（Invariance Principle）**：隐喻映射保留源域的认知拓扑结构。当你说"某人是烤肠"时，烤肠的属性必须能回推到烤肠本身上。如果某个属性（如"社交媒体活跃度高"）在烤肠上找不到对应物，这个映射就是断裂的。

**衍生工具——三类映射失效模式**：

| 模式 | 表现 | 矫正方式 |
|------|------|---------|
| 维度脱离源域本体 | dim 在源域无对应特征 | 溯源三问：这个 dim 来自特征表的哪一条？ |
| 结果类型不是真实子类 | name 是"人后缀"，不是真实品类 | 品类下位约束：结果名必须在源域真实品类树中 |
| 多源域混合 | 同一份问卷出现两个实体的特征 | 单源一致约束：一个问卷只能有一个源域 |

**对"教AI说话"的扩展应用**：概念隐喻理论的价值不止于"实体→人"映射。它揭示了一个更普遍的规律——**AI 在没有锚点的情况下，会默认从自己最熟悉的训练数据池中提取内容来源。** 所以"教AI说话"的第一步不是告诉它"说得像人"，而是**给它一个具体的、不来自其训练数据的源域做锚点**。有锚点就不会漂移。

### 3.2 角色锚定理论（本项目自定义）

**核心假设**：LLM 的输出风格可以由初始角色设定来锚定，但一个角色无法贯穿所有阶段。

**机制**：
- 角色设定本质上是一个"认知模式开关"——它告诉模型应该用哪种知识库、哪种语言风格、哪种推理方式来完成任务。
- 一个角色如果同时承载"放松直觉"和"严谨流程"两种要求，模型会优先遵循出现更早、更生动的那一个。在 本项目中，"凌晨三点被朋友叫起来写备忘录"（第 1 节）的放松直觉流，压过了"不能跳步"（第 4 节）的流程纪律。

**分阶段挂载角色**：
```
阶段 A（解剖阶段）：刚喝完咖啡的解剖学者 → 冷静、精确、有耐心拆东西
阶段 B（出题阶段）：凌晨三点半写备忘录的直觉朋友 → 放松、口语化、凭感觉写题
```

**时态作为切换机制**：比换角色描述更有效的切换方式是用时态——解构阶段用一般现在时（"这个实体由什么构成"），出题阶段用一般将来时/过去回忆时（"你会不会……""你有没有过……"）。模型对时态极其敏感，时态本身就是认知模式的开关。

### 3.3 来源锚定原理（本项目自定义）

**核心洞察**：AI 跳过某个步骤的根源不是"规则约束不够强"，而是"下游长得太独立"。一个"躺平程度"维度不需要任何解剖表就能生成。所以治本的方法不是在上游锁门，而是让**每块下游砖都自带一个必须填的上游孔**。

**原理**：
```
传统约束：不得凭空捏造维度，维度必须有来源
（本质是"注意事项"——模型可以选择遵守或忽略）

来源锚定：每个维度的输出格式自带 source 字段
（本质是"结构缺陷"——不填 source 就是格式不完整）
```

**关键区别**：规则是"可选遵守的"，结构缺陷是"格式上不可容忍的"。模型对格式缺陷的敏感度远高于对规则提示的敏感度。

**实现方式**：来源锚定不需要修改最终输出格式。在生成思维链中完成标注就够了——"蓄力时长 → 要素'状态参数' → '蓄力越长越容易陷入僵直'"。模型在写下 dim 名称时顺带写下它的来源引用，这个动作本身就会阻止它使用无源 dim。

### 3.4 对称验证原理（本项目自定义）

**核心问题**：AI 在写题过程中容易"写嗨了"——在某个维度上过度展开，挤压其他维度的空间。

**传统方案**：事后检查（"输出前数一遍题数，不对就改"）。但模型是左到右生成 token 的，检测到错误时已经写到了 JSON 末尾，不可能回头改。

**本方案的突破**：把"事后检查"改成"**前置硬边界 + 对称验证**"的双层保险：

```
第一层（前置硬边界）——在写题开始前：
"每个 dim 固定 3 题，不可多不可少。写完 3 题立刻刹车。"

第二层（对称验证）——在写题完成后：
"少了补，多了砍。删成 0 题就重出。"
```

**关键设计**：前置硬边界不是"尽量写 3 题"，是"第 3 题写完门就锁上了"。模型的心理模型从"写够了"变成了"门锁了"——前者是可选的，后者是结构性的。

## 四、核心方法：六条可操作技术

### 方法一：素材锚定法

**目的**：让 AI 写作时使用真实的生活素材，而不是抽象概念。

**做法**：在提示词中提供一个或多个具体的"生活素材池"——不需要修辞、直接拿出来就是共鸣的意象：

> ✅ 素材从生活里捞——外卖点了同一家黄焖鸡三天 / 备忘录里存着没发出去的话 / 深夜刷修驴蹄子刷了一小时——这些不需要修辞，直接写就是共鸣。

**原理**：AI 在看到抽象要求（"写有共鸣的题目"）时，会从训练数据中提取"看起来有共鸣的句子"——通常是那些被反复标记为"写得好"的句子。而"写得好"的训练数据和"人随口说的"恰好相反。提供具体素材池替代了 AI 的自我检索过程，跳过了"看起来好的句子→其实不像人说的"这个陷阱。

### 方法二：画面先行法

**目的**：让 AI 从场景出发，而非从概念出发。

**做法**：

> ✅ 先有画面，再出题——脑子里先浮现一个画面——"有个人周末瘫在沙发上，手机砸脸上睡着了"——再从这个画面出题。不从概念出发。

**原理**：概念出发→抽象题目（"你是个容易内耗的人？"）。画面出发→具体场景（"被老板骂了你多久能缓过来？"）。前者是人格测试的语法，后者是朋友聊天的语法。两者的本质区别在于"可点头性"——人看到后者的第一反应是在脑子里回想有没有类似的经历，看到前者的第一反应是防御性地评估"我是不是这样的人"。

### 方法三：语感替代法

**目的**：替代基于"字/词"的机械规则，改为基于"读感"的语义判断。

**示例**：

```
旧（字首匹配）：
"你是否""你是不是""你认为"——禁止使用这些开头
→ 模型躲进"句句我字打头"的安全区

新（语感判断）：
不管句子以什么字开头，只要听起来像在审问做题者，就不能用。
"刷到前任的动态，我会忍不住点进去。"——陈述感，能用
"你是否会复盘自己的操作？"——审问感，不能用
```

**原理**：字首匹配是"可规避的"——模型可以轻松地换一种字首开头，但换完之后仍然写出审问感的句子。语感判断把评判权交给模型的"语言直觉"——LLM 对语感的敏感性远超对字面规则的理解能力。关键是要用**对比对**（审问感 vs 陈述感）来激活模型的语言直觉，而不是用禁令列表来约束。

### 方法四：对比对教学法

**目的**：用正反对比教 AI 理解一个"概念性"的要求，而不是给出具体的可执行指令。

**示例**：

```
❌ 你不能写："你是个容易内耗的人？"
✅ 你可以写："被老板骂了你多久能缓过来？"

❌ 你不能写："你会……吗？"
✅ 你可以写："看到打折你囤不囤？"
```

**原理**：禁止句式列表（"你不准用 X、Y、Z"）只能挡住有限的几个具体表达。对比对教学法教的是"什么是对的感和错的感"——模型学会的不是"避开这几个词"，而是"这种语感是错的，那种语感是对的"。这是从**规则约束到能力培养**的飞跃。

**应用技巧**：对比对的数量不需要多。3 对足够。再多会变成"参考模板"，模型就只从例子中复制，不会自己推理。

### 方法五：角色分阶段法

**目的**：解决单一角色无法同时承载"严谨"和"放松"两种要求的矛盾。

**做法**：将工作流拆为两个阶段，每个阶段挂一个子角色，用时态切换来完成角色切换：

```
阶段 A：一般现在时 + 精确逻辑 → 解剖阶段
  "这个实体由什么构成？""各组件的可量化维度是什么？"
  
阶段 B：一般过去时/回忆时 + 直觉放松 → 出题阶段
  "你有没有过……""被骂了，半天缓不过来。"
```

**原理**：模型对时态的敏感性远超对人设描述（"你是一个XX的人"）的敏感性。时态变化自动触发认知模式切换——过去时激活叙事模式，现在时激活分析模式。这是利用了 LLM 在训练数据中学到的"时态-文体对应关系"，而不需要在 prompt 层面额外写角色描述。

**适用边界**：这个方法的适用条件是工作流明确分为"构思→落地"两个阶段且界限清晰。如果工作流是单一连续任务或需要反复往返（构思一半回去改构思），分阶段反而会造成切换损耗。

### 方法六：粗糙真实优先法

**目的**：让 AI 优先选"粗糙但真实的表达"，而非"精致但平庸的表达"。

**做法**：

> 粗糙但真实 > 精致但平庸——一句话读起来像被反复打磨过的，删掉重写。活人说话带着毛边。

**示例**：
```
❌ "用意念阻止太阳升起来"——写得挺好，但不是人说的
✅ "就是不想闭眼"——这才是人说的话
```

**原理**：AI 有天然的"美化倾向"——它倾向于产出语法完美、修辞得当的句子。但人的日常语言恰好不是这样的：句式残缺、主语省略、夹带语气词……这些"缺陷"恰恰是真实感的来源。所以教 AI 说话不是教它"写更好"，是教它**"写得糙一点"**——降低自我审查的阈值。

**执行要点**：这个要求必须放在所有写作规则之后、实际动笔之前。如果放在风格指导中（与其他写作要求并列），模型会把它当成可选风格指南。如果放在最后作为"输出前最后一件事"，模型会在写完初稿后做一道"检查自己的句子是不是太精致了"的工序。

## 五、反模式：三条"这样写一定会死"的警示

### 反模式一：抽象原则当执行指令

**表现**：提示词写"请使用正确方向，从源域出发进行映射"——没有任何执行步骤，只有抽象的论断。

**为什么死**：抽象原则对 AI 是无效的。模型不能理解"从源域出发"这个操作是什么——它没有一个叫"源域出发"的认知模块可以被激活。它只能理解"先做 A，再做 B，然后做 C"这种步骤级指令。

**死因解剖**：
```
❌ 抽象原则："请从源域出发进行隐喻映射"
→ 模型无法执行，继续按默认方式生成

✅ 执行步骤：
  1. 列源域特征表（至少 6 条）
  2. 每条配一句人话翻译
  3. 从人话翻译中选 5-7 个作为维度
  4. 每个维度标注来源
→ 模型可以执行
```

**判断标准**：写完一段指令后问自己——"如果是一个不聪明的人，看到这句话知道第一步该干什么吗？"不知道就是抽象原则。

### 反模式二：无限追加示例

**表现**：每次遇到特定标签跑偏，就加一个该标签的示例到提示词里。最终提示词变成一本"示例大全"。

**为什么死**：1）没完没了，每个标签都要加示例，永远追不完。2）模型看到示例会直接复制模仿，而不是理解原理——这降低了模型的推理能力，增加了刻板性。

**死因解剖**：
```
"大招蓄力时间"跑偏 → 加一个"大招蓄力时间"的正确示例
"社交牛逼症"跑偏 → 再加一个"社交牛逼症"的示例
"反内卷体质"跑偏 → 再加一个"反内卷体质"的示例
...
→ 提示词膨胀，模型变成刻板匹配器
```

**正确的替代方案**：不是加示例，是改结构。比如——发现 dims 跑偏，不是加"正确的 dims 应该长这样"的示例，而是给每个 dim 加一个"必须填的来源引用"字段。不改内容改结构，打补丁和装闸门的区别。

### 反模式三：无限修复循环

**表现**：每次发现一个问题，就加一条规则去堵。每次加规则，都让提示词更厚、更重、更刻板。

**为什么死**：提示词硬化是一个不可逆的过程。每加一条"不能"，模型的自由探索空间就缩一圈。最终你会得到一个不会犯错也不会出彩的模型。

**死因解剖**：
```
问题1 → 加规则1 → 提示词 +2 行
问题2 → 加规则2 → 提示词 +3 行
问题3 → 加规则3 → 提示词 +4 行
...
→ 规则密度的边际效益递减；增加规则的副作用（降低自由度）累积
→ 第 N 次修改后，模型被绑死了，产出平淡无味的及格内容
```

**止损策略**：
1. **封版阈值**：设定"最多改 N 轮"或"改到第 X 个问题后不管是否存在残留问题都封版"
2. **结构性 vs 规则性判断**：每次发现新问题，先问"这是结构缺陷还是规则漏洞？"结构缺陷值得改，规则漏洞未必。
3. **批量化测试**：不在单个标签上修到完美。跑 10 个标签看整体质量分布，如果 8/10 没问题、2/10 有问题且不是系统性偏移——接受不完美。

## 六、迭代史：从直觉到方法论

### 6.1 第一轮：直觉试调

**时期**：项目启动 ~ 5月10日

**做法**：
- 第一版提示词用"凌晨三点被朋友叫起来写备忘录的人"做人设
- 输出要求"自然、有生活感、要像人说的"
- 结果：初见效果好，但内容开始漂移

**暴露的问题**：
- 角色设定有效但不够——模型知道"要写得像人"，但不知道"具体该怎么写"
- "社交媒体活跃度"等无关维度开始混入
- "深夜emo肠"等贴皮结果类型出现

**学到的东西**：
- "写得像人"是一个抽象原则（反模式一），下游需要具体执行指令
- 人设有效，但必须配合执行步骤

### 6.2 第二轮：理论框架 + 约束体系

**时期**：5月10日 ~ 5月11日凌晨

**做法**：
- 引入概念隐喻理论做诊断
- 设计四个约束（单源一致、特征筛选、品类下位、溯源三问）
- 设计四步工作流
- 写进 Coze 提示词 v3

**暴露的问题**：
- 约束体系理论正确，但 Coze 执行不了——高密度约束在长 JSON 生成中会选择性丢失
- Coze 底层模型承载不了"在生成过程中维护多层一致性"

**学到的东西**：
- 约束体系是对的，但放错位置了——应该从"提示词内的约束"改为"代码内的校验"
- Coze 能力边界：发散可以，一致性不行

### 6.3 第三轮：结构重构 + 来源锚定

**时期**：5月11日下午

**做法**：
- 取消"加更多示例/规则"的补丁思路
- 改为结构重构——角色分阶段、来源锚定、分类确认、对称验证
- DeepSeek 专家模式贡献了决定性洞察

**暴露的问题**：
- 禁用句式用字首匹配太机械 → 改成语感判断
- 评分方向规则位置不对 → 迁移到写题之后

**学到的东西**：
- 结构性改动 > 规则性改动 —— 前者不降自由度，只改路径
- 分阶段角色 > 单一角色贯穿 —— 时态切换是认知模式开关
- 来源锚定 > 来源检查 —— 结构缺陷比规则提醒有效

### 6.4 最终定型

**时期**：5月11日傍晚

**最终提示词结构**：

```
第1-3节：角色设定（"被朋友叫起来出题的人"）
↓
阶段 A — 解剖阶段（一般现在时）
  第1步：分类 + 确认分类
  第2步：模板解剖 → 产出人话翻译表
  第3步：溯源三问 + 降级规则 + 来源锚定
  第4步：结果类型（从源域真实谱系选）
↓
阶段 B — 出题阶段（一般过去时/回忆时）
  第5节：写题（语感判断替代字首匹配）
    → 写完后执行「结果命名方向规则」
  第6节：题型约束（同意/中立/否定）
  第7节：对称验证（题量 + 维度来源）
  第8节：输出格式（含 prompt_version）
  第9节：最后检查
```

## 七、总结

### 7.1 一句话结论

> **教AI说话的核心不是教它"说得更好"，是教它"不要说得太好"。**

AI 天然倾向于输出语法完美、结构工整、修辞得当的句子——这些特征恰好是"不像人话"的来源。教 AI 说话的全部努力，本质上是在对抗它的"美化本能"。

### 7.2 两条铁律

1. **结构 > 规则。** 永远优先选择改结构（分阶段、改格式、加必填字段）而不是加规则（"不能""必须""禁止"）。规则降自由度，结构只改路径。

2. **锚点 > 约束。** 给 AI 一个具体的、不从其训练数据来的源域（素材池、特征表、人话翻译），比告诉它"不要跑偏"有效一万倍。

### 7.3 三个判断标准

写好一段引导 AI 写作的提示词后，用这三条检查自己：

| 检查项 | 好 | 差 |
|--------|-----|-----|
| **可执行性** | "先做什么，再做什么，最后做什么" | "请使用正确方向" |
| **具体性** | "被老板骂了你多久能缓过来？" | "你是个容易内耗的人？" |
| **容忍度** | 跑 10 个标签，8 个好就行 | 每个标签都必须完美 |

### 7.4 适用边界

本方法论产生的场景是：**单次 LLM 调用 + 固定输出格式 + 无多轮对话 + 无人类在 loop 中**。

如果以下条件满足，部分方法可以迁移：
- ✅ 需要 AI 产出"自然感强"的文字
- ✅ 内容需要有多层一致性（tag→dim→question→result 的链条逻辑）
- ✅ 约束条件复杂且多样
- ❌ 场景属于纯发散创意（不需要约束体系）
- ❌ 有条件做多轮对话或人工介入修改（不需要源域锚定）
