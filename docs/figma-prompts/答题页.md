## 答题页 · 给 Figma AI 的设计提示词

请用 React + Tailwind CSS 为我生成一个移动端答题页面。

### 核心原则
- **极简**——用户不需要思考"怎么操作"，看到题目选就完了
- **一题一屏**——每屏只显示一道题，没有滚动
- **选中即过**——点击选项后直接跳到下一题，不需要"下一题"按钮
- **整体调性保持"贱贱的、好玩"**，和首页风格一致

### 页面布局

**1. 顶部进度条（很细）**
- 显示当前题号，文案可以皮一点，例如「第3/10题 · 离确诊又近了一步」
- 文字小而轻，不抢视线

**2. 题目区域（居中，占最大面积）**
- 题目是一段情景描述文字，例如「周末你更倾向于一个人待着，而不是出门社交」
- 字体适中偏大，居中显示，段落自然换行
- 不需要配图

**3. 选项区域（底部，三个按钮纵向排列）**
- 三个选项按钮，纵向排列，间距均匀
- 每个按钮是一个大圆角卡片，尺寸够大方便点击
- 三个按钮的文案和 emoji 根据当前题目的配置显示（见下方说明）
- 点击时：按钮有选中反馈（颜色加深/放大/弹性动画），然后自动跳转到下一题

**4. 选项文案示例（每道题从以下套中随机选一套）**
```
绝非如此 🤨  |  有点意思 🤔  |  被看穿了 😱
根本不是 🚫  |  也许吧 🤷    |  就是我本人 ✅
太扯了 🙄    |  说不准 🫤    |  太准了 😳
绝对不是 🤨  |  好像有点 🫤  |  本人在此 😳
你瞎了 🙅‍♂️  |  猜对一半 🤷  |  你监视我？ 🎯
举报了 🚫    |  再想想 🤔    |  删掉监控 ✅
我裂开 💀    |  有点痛 🩹    |  精准打击 🔪
不是我 🙈    |  一半一半 🐒  |  是我本人 🐺
```

### 交互流程
1. 页面加载 → 显示第一题（带掉落动画，从底部轻微上滑）
2. 用户点击选项 → 选项高亮反馈（0.2s）→ 自动切到下一题（当前题向上淡出，下一题从底部上滑）
3. 最后一道题答完 → 自动跳转到结果页

### 数据流机制（告诉页面测什么）

**首页 → 答题页的出参方式：**
- 首页点击标签后，通过 URL 参数将标签名传给答题页，例如：
  ```
  /quiz?tag=确诊为烤肠
  ```

**答题页拿到 tag 后的数据模型：**

答题页接收到 tag 后，从本地模拟数据中根据 tag 查找对应的试卷数据。数据结构如下：

```js
// 根据 tag 查到的完整试卷数据
{
  "title": "你被确诊为什么东西？",
  "tag": "确诊为烤肠",
  "dimensions": [
    { "name": "淀粉肠指数" },
    { "name": "加肉程度" }
  ],
  "questions": [
    {
      "title": "你平时吃路边摊会首先考虑什么？",
      "options": [
        { "text": "便宜就行", "scores": [{ "dIndex": 0, "value": 8 }] },
        { "text": "看眼缘",   "scores": [{ "dIndex": 0, "value": 5 }] },
        { "text": "必须是肉", "scores": [{ "dIndex": 0, "value": 2 }] }
      ]
    }
    // ...更多题目
  ]
}
```

### 技术要求
- 移动端视口（375px-448px）
- 背景色与首页一致 #F7F8FA
- 所有按钮尺寸舒适，方便单手点击
- 不需要底栏或顶栏（除了进度条）

---

**设计参考**：想象一个"选择题版抖音"——每一题就是一条视频，滑过去（选中）就进入下一条。
