## figma的动画说明
1. 入场动画
第一题入场
哪些元素：题目文本块、各个选项卡片。
@keyframes 完整 CSS：
/* 弹性上滑进入 */
@keyframes slideUpElastic {
    0% { opacity: 0; transform: translateY(40px); }
    100% { opacity: 1; transform: translateY(0); }
}
动画参数：
animation-duration: 0.6s
animation-timing-function: cubic-bezier(0.34, 1.56, 0.64, 1)（标志性的果冻回弹曲线）
animation-delay: 题目为 0s，选项分别为 0.1s, 0.15s, 0.2s 等（阶梯延迟）
animation-fill-mode: both（保证动画前透明隐藏，动画后保持位置）
说明：首次进入时，题目先出现，随后选项像发牌一样自下而上依次弹性滑出。这种微小的错落感能极大提升应用的“顺滑感”。
题目切换动画
旧题离开：整体向上淡出。
参数：duration: 0.3s, timing-function: ease-in, transform: translateY(-30px), opacity: 0。
新题进入：与第一题入场完全相同，从底部使用 slideUpElastic 弹性上滑。
选项表现：切换题目时，选项是独立于题目动作的。旧选项跟随旧题一起向上淡出；新选项在新题文字出现后，再次执行阶梯式的弹性上滑。这比把题目和选项打包成一个整体滑动显得更轻盈。
2. 交互反馈
选项点击
未选中态 → 选中态：
颜色：背景从白色/浅灰变为主题色（或带有主题色透明度的浅色），文字颜色随之加深或变白，边框变成粗体主题色（如 border: 2px solid #yourTheme）。
缩放：瞬间缩小至 scale(0.95) 产生“果冻按压感”。
用时和曲线：颜色/边框变化使用 transition: all 0.2s ease；物理按压感由于要快速响应，使用 0.05s ease-in 塌陷，松手后 0.2s cubic-bezier 回弹。
点击后切换时机：选中态保持约 400ms - 500ms 才切到下一题。给足用户心理确认时间（“啊，我选好了”），太快切换会让用户产生焦虑感和误触怀疑。
实现方式：
颜色、边框等状态变化用 Vue 数据绑定 + CSS transition 实现。
瞬间的物理按压缩放在小程序中强制要求使用 hover-class 实现。
进度条
进度更新：平滑过渡（transition），绝对不能瞬跳。
宽度变化曲线：transition: width 0.4s ease-out;（快出慢停，感觉很丝滑）。
3. 其他动效
循环动画：无。
说明：为了保持界面的“极简和干净”，答题过程中除了用户的交互反馈和切题动画，没有任何持续的呼吸或浮动动画。不打扰用户阅读题目和做出选择，是测试类小程序的重要原则。
4. Vue / uni-app 移植建议
DOM 结构
组件层级拆分建议：
QuizPage (页面级)
├── Header (含 Progress 进度条，固定在顶部)
├── ScrollArea (题目滑动区，确保长选项能滚动)
│   └── TransitionWrapper (用于切换动画的包裹层)
│       ├── QuestionText (题目文本区)
│       └── OptionsList (选项列表区)
│           └── OptionItem (单个选项：外层 hover-class，内层 animation)
DOM 分层原则（极其重要）： 如之前所说，必须分离 animation 和 hover-class！
<!-- 错误示范：动画和按压在同一个节点，会导致 hover 失效 -->
<view class="option" hover-class="pressed" style="animation: slideUp...">...</view>

<!-- 正确示范：严格分层 -->
<view hover-class="press-95" :hover-start-time="0" :hover-stay-time="150">
  <view class="option-inner" :style="{ animationDelay: delay + 's' }">
     选项内容
  </view>
</view>
动画实现
题目切换的最稳方式：利用 Vue 的 :key 机制强制重建 DOM。 在微信小程序中，不要用 JS 去反复增删 CSS 类名来做动画，既麻烦又容易出并发 Bug。
<!-- 当 currentQuestionIndex 改变时，Vue 会自动销毁旧 DOM 并创建新 DOM -->
<!-- 这会完美且自动地触发我们写在 CSS 里的 slideUpElastic 入场动画！ -->
<view :key="'question-' + currentQuestionIndex">
    <view class="question-text"> {{ currentQuestion.title }} </view>
    <!-- 选项列表 -->
</view>
(注：如果需要“旧题淡出”的效果，可以结合 Vue 的 <transition name="fade-up" mode="out-in"> 组件，并在 CSS 中写好 .fade-up-leave-active 等类名，uni-app 对此支持良好。)
兼容性
防止疯狂点击：小程序环境存在点击延迟，必须在 Vue data 中加一个 isSwitching: false 的锁。用户点击选项后立即设为 true，等 500ms 切换完成再设为 false。如果不加，用户狂点会导致连续跳题甚至数组越界。
Text 组件的 Transform 限制：微信小程序的 <text> 标签属于行内元素，很多时候 transform 缩放或位移不生效或乱飘。务必使用 <view> 标签作为动画容器，里面的文字再用文本样式控制。
底部安全区截断：选项列表的底部必须留出足够的空白（如 padding-bottom: env(safe-area-inset-bottom); 加额外 60rpx），否则最后一题的最下面一个选项会被 iPhone 的小白条遮挡。
