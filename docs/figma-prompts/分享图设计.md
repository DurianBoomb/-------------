# 分享图设计需求

## 目标

设计一张微信小程序分享卡片封面图，程序会通过 **Canvas 代码将设计稿逐像素还原**（并非直接使用设计稿图片）。所以设计完成后还有一个 **移植环节**——开发人员根据设计稿上的标注，用 Canvas API 一行一行把图形和文字画出来。

这意味着：
- 设计稿不是"出图就行了"，而是 **移植的施工图纸**
- 每个元素的精确参数都必须标注清楚，否则无法移植
- 设计时需要提前知道：**这个效果 Canvas 能不能画出来？**

---

## 基础信息

| 项目 | 值 | 说明 |
|------|-----|------|
| **用途** | 分享到微信好友/群聊时，卡片上显示的图片 |
| **画布尺寸** | **500 × 400 px** | 推荐 5:4 比例，请按此尺寸出图 |
| **渲染方式** | Canvas 代码还原（非图片资源加载） | 不支持使用外部图片，不支持加载自定义字体文件 |
| **输出平台** | 微信小程序 | |

---

## 移植环节说明（重要）

### 移植流程

```
Figma 设计 → 出标注文档 → 开发人员按标注手写 Canvas 代码 → 运行验证
```

- 设计稿的每一个元素都会被翻译成对应的 Canvas 绘图指令（`fillRect`、`fillText`、`quadraticCurveTo` 等）
- 移植不是切图导出，是**代码还原**
- 标注越精确，还原度越高

### 移植难度分级

| 难度 | 元素类型 | 说明 |
|------|---------|------|
| ★ 简单 | 纯色矩形、圆角矩形、实心圆 | Canvas 原生支持，直接一行代码 |
| ★ 简单 | 文本（PingFang / sans-serif） | `fillText()` 直接渲染，指定字号/颜色即可 |
| ★★ 中等 | 渐变色（线性/径向） | Canvas 支持，需要标注起止色和方向 |
| ★★ 中等 | 图标/Emoji | Emoji 直接用 `fillText()` 渲染；图形图标需转为 Canvas Path |
| ★★★ 困难 | 复杂图形/不规则形状 | 需要手动写 Path 贝塞尔曲线，开发成本高 |
| ★★★ 困难 | 阴影、高斯模糊、投影 | 微信小程序 Canvas 性能有限，低端机可能卡顿 |
| ✗ 不可移植 | 自定义字体（woff/ttf） | 小程序 Canvas 不支持加载外部字体文件 |
| ✗ 不可移植 | 外链图片/网络图 | Canvas 无法跨域加载图片用于绘图 |
| ✗ 不可移植 | 图层混合模式（叠加、正片叠底等） | Canvas 仅支持 `globalCompositeOperation` 有限几种模式 |

### 对设计师的建议

- **优先使用纯色块和文字排版**，移植最准、最快
- **如需图标**，优先选 Emoji 方案（兼容性好、零移植成本）
- **如需渐变色**，标注清楚渐变方向（水平/垂直/角度）和起止颜色
- **如需复杂装饰图形**，提前和开发确认 Canvas 能否实现，避免设计完发现做不了
- **圆角**可以直接用，Canvas 有圆角矩形的绘制方法

## 页面上可使用的文案数据

以下信息都是从程序中动态获取的，设计时请预留可变长度的空间：

| 数据 | 字数范围 | 示例 |
|------|---------|------|
| **A. 标签名**（主标题） | 3~12 字 | `确诊为烤肠`、`纯正淀粉肠` |
| **B. 问卷标题**（副标题） | 6~20 字 | `你被确诊为什么东西？` |
| **C. 固定引导文案** | 写死的固定文字 | `点击测一测` + 标签名（动态拼接） |
| **D. 固定底部脚标** | 写死的固定文字 | `微信小程序 · 答完即出结果` |

> 标签名（A）和问卷标题（B）都是变量，长度不固定，设计时请考虑最长情况下的排版效果，或设置最大字数并约定超出后的处理。

## 设计要求

### 必须包含的元素

1. **标签名** — 最大、最醒目的文字，是分享卡的核心内容
2. **问卷标题** — 辅助说明，字号小于标签名
3. **引导文案** — 引导用户点击的短句，位置不限
4. **底部品牌标识** — 如"微信小程序 · xxx"之类

### 可选元素

- 顶部/装饰性色块或渐变条
- 图标/Emoji
- 分隔线
- 背景色块/底纹

### 设计约束

1. **字体**：仅支持系统安全字体（PingFang / Noto Sans SC / sans-serif），不支持上传自定义字体
2. **图标**：支持三种方案——
   - Emoji 字符（用 `fillText()` 渲染，兼容性好）
   - 纯文字排版（无图标）
   - Canvas Path 绘制（复杂图形，开发成本高，慎重选择）
3. **圆角矩形**：Canvas 可以画圆角矩形，见下方标注要求
4. **不要使用阴影/滤镜**：Canvas 渲染性能有限，复杂特效在小程序低端机上可能出现问题

---

## 需要 Figma 输出什么

设计完成后，请提供：

1. **设计稿截图**（500 × 400 px）
2. **标注文档**——这是移植的核心依据，必须包含以下所有元素的参数：

| 需要标注的内容 | 说明 |
|---------------|------|
| **背景色**（整体/局部色块） | HEX 色值 |
| **每个文本元素** | 字号(px)、字重(regular/bold)、颜色(HEX)、x/y 坐标 |
| **每个色块/装饰元素** | 位置(x/y)、尺寸(w/h)、圆角半径(r)、颜色(HEX) |
| **分隔线** | 位置(y)、颜色(HEX)、粗细(px) |
| **渐变** | 渐变方向（水平/垂直）、起止颜色(HEX) |
| **图标** | 如果是 emoji 则指定字符；如果是图形则提供 Canvas Path 数据 |
