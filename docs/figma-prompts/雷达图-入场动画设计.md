## 2. 缓动函数(完整函数体,照抄)

```js
// 把全局进度 t 截到子区间 [a, b] 并归一化到 [0, 1]
function sub(x, a, b) {
  return Math.max(0, Math.min(1, (x - a) / (b - a)));
}

// 立方缓出:平滑减速
function easeOutCubic(x) {
  return 1 - Math.pow(1 - x, 3);
}

// 回弹缓出:终值前轻微过冲再回落 (用于网格弹出 / 数据点飞射)
const c1 = 1.70158;
const c3 = c1 + 1;
function easeOutBack(x) {
  return 1 + c3 * Math.pow(x - 1, 3) + c1 * Math.pow(x - 1, 2);
}

// 弹性缓出:多次衰减振荡 (用于顶点 pop)
function easeOutElastic(x) {
  if (x === 0 || x === 1) return x;
  const c4 = (2 * Math.PI) / 3;
  return Math.pow(2, -10 * x) * Math.sin((x * 10 - 0.75) * c4) + 1;
}
```

> ⚠️ **不要换库实现、不要换公式参数**。`c1 = 1.70158` 是 CSS spec 里 easeOutBack 的标准常量,改了就不是同一个手感。

## 3. 时间窗机制(stagger 自适应)

每个图层的"第 i 个元素"在归一化进度 `t ∈ [0, 1]` 中占用一段子窗口 `[a, b]`。窗口起点随维度索引线性移动,起点跨度按维度数自适应:

```js
// frac(i): 第 i 个元素在 N 个元素中的相对位置 (0 ~ 1)
function frac(i, N) {
  return N <= 1 ? 0 : i / (N - 1);
}

// win(i, N, startBase, startSpan, duration):
//   返回 [a, b],单位是归一化进度 (0 ~ 1)
//   a = startBase + frac(i) * startSpan
//   b = a + duration
function win(i, N, startBase, startSpan, duration) {
  const a = startBase + frac(i, N) * startSpan;
  return [a, a + duration];
}
```

**为什么要这样设计**:维度数 N 变化时,`startSpan` 是固定预算,N 大 → 步长 `startSpan / (N-1)` 自动变小、错峰更密;N 小 → 步长变大、错峰更明显。这保证 3 维和 8 维都有合理的节奏感。**小程序里必须用同一套公式,不要硬编码具体延迟。**

## 4. 主循环(rAF 驱动)

```js
let raf = 0;
let startTs = 0;
let t = 0; // 当前归一化进度,所有图层从这里读

function tick(now) {
  if (!startTs) startTs = now;
  const elapsed = now - startTs - START_DELAY;
  if (elapsed < 0) {
    raf = requestAnimationFrame(tick);
    return;
  }
  t = Math.min(1, elapsed / DURATION);
  drawFrame(t); // ← 每帧全量重绘,见第 5 节
  if (t < 1) raf = requestAnimationFrame(tick);
}

// 启动 & 重置
function start() {
  cancelAnimationFrame(raf);
  startTs = 0;
  t = 0;
  raf = requestAnimationFrame(tick);
}
```

### 重新触发的坑

- **必须重置 `startTs = 0`**。小程序 `requestAnimationFrame` 的 `now` 是单调累加的,不重置会让 `elapsed` 一进来就 ≥ DURATION 直接跳到终态。
- **必须 `cancelAnimationFrame` 旧的 raf id**,否则多次进入页面会有多个循环同时跑。
- 路由复用(`onShow`)和首次进入(`onLoad`)都要调 `start()`。

### 绘制策略:**每帧全量重绘**

不要做静态层 / 动态层分离。本动画里 10 层全都是动态的(网格在弹出阶段、轴线在生长阶段、数据点位置在变、数字在滚动、标签在淡入),分层反而增加复杂度。每帧 `ctx.clearRect(0, 0, SIZE, SIZE)` 后从头画一遍即可。N=5 时每帧约 30~40 次 `sin/cos`,低端机也跑得动。

### 性能兜底

- N=5 时单帧绘制成本约 < 2ms,稳 60fps。
- 真有低端机掉到 30fps,**不要降级精度**(那会改变还原度),改用"按真实时间推进"——`t` 已经按 `elapsed / DURATION` 计算了,天然不依赖帧率,只是观感上稍卡。

## 5. 10 个图层 · 逐层规格

**绘制顺序就是数字顺序**(1 在最底层,10 在最上层)。下表所有窗口起止参数都是归一化进度 `t ∈ [0, 1]`,乘以 `DURATION=1900` 即得毫秒。

### Layer 1 · 背景同心网格(4 圈五边形)

| 项 | 值 |
|----|-----|
| 元素 | `level ∈ [25, 50, 75, 100]` 共 4 圈五边形 |
| 时间窗 | 第 idx 圈: `[idx * 0.06, idx * 0.06 + 0.35]` |
| 缩放函数 | `s = easeOutBack(local)`;每个顶点用 `getPoint(level * s, i)` 计算 |
| 描边 | `#E5E7EB`,`lineWidth = 1` |
| 虚线 | level=100 实线;其余 `setLineDash([3, 3])` |
| 不透明度 | `Math.min(1, local * 2.5)` |
| 早退 | `s <= 0` 时跳过该圈不画 |

```js
[25, 50, 75, 100].forEach((level, idx) => {
  const local = sub(t, idx * 0.06, idx * 0.06 + 0.35);
  const s = easeOutBack(local);
  if (s <= 0) return;
  ctx.beginPath();
  for (let i = 0; i < N; i++) {
    const p = getPoint(level * s, i);
    if (i === 0) ctx.moveTo(p.x, p.y);
    else ctx.lineTo(p.x, p.y);
  }
  ctx.closePath();
  ctx.setLineDash(level === 100 ? [] : [3, 3]);
  ctx.lineWidth = 1;
  ctx.strokeStyle = '#E5E7EB';
  ctx.globalAlpha = Math.min(1, local * 2.5);
  ctx.stroke();
});
ctx.setLineDash([]);
ctx.globalAlpha = 1;
```

### Layer 2 · 轴线(从圆心射出 N 条)

| 项 | 值 |
|----|-----|
| 时间窗 | `win(i, N, 0.10, 0.15, 0.30)` |
| 生长函数 | `g = easeOutCubic(local)`;终点 = `getPoint(100 * g, i)` |
| 描边 | `#E5E7EB`,`lineWidth = 1` |
| 不透明度 | `Math.min(1, local * 3)` |

### Layer 3 · 中心冲击波(只放一发)

| 项 | 值 |
|----|-----|
| 时间窗 | `shockT = sub(t, 0.28, 0.62)` |
| 显隐条件 | `0 < shockT < 1` |
| 半径 | `shockR = shockT * RADIUS * 1.15`(允许越出网格外) |
| 描边 | `#FB923C`,`lineWidth = 2`,`fill: none` |
| 不透明度 | `(1 - shockT) * 0.55` |

### Layer 4 · 数据点飞射拖尾

| 项 | 值 |
|----|-----|
| 时间窗 | `win(i, N, 0.30, 0.25, 0.45)` |
| 拖尾终点 | 与当前数据点 `currentPoints[i]` 同位置(见 Layer 5) |
| 描边 | `#FB923C`,`lineWidth = 1.5`,`lineCap: 'round'` |
| 不透明度 | `Math.sin(local * Math.PI) * 0.55`(中间最亮、两端淡出) |
| 早退 | `opacity <= 0.02` 跳过 |

### Layer 5 · 数据多边形 · 填充

**先算出 `currentPoints` 数组(后续 Layer 5/6/7/8/9 都要用)**:

```js
// 数据点当前位置:沿轴线从圆心 easeOutBack 弹射到目标值
const currentPoints = scores.map((s, i) => {
  const [a, b] = win(i, N, 0.30, 0.25, 0.40);
  const eased = easeOutBack(sub(t, a, b));
  const r = (s / 100) * RADIUS * eased;
  const angle = i * ANGLE_STEP + START_ANGLE;
  return {
    x: CENTER + r * Math.cos(angle),
    y: CENTER + r * Math.sin(angle),
  };
});
```

| 项 | 值 |
|----|-----|
| 填充色 | `rgba(249, 115, 22, 0.2)` |
| 不透明度乘子 | `sub(t, 0.42, 0.8)` |
| 路径 | 连接 `currentPoints` 闭合 |

> Canvas 实现:`ctx.globalAlpha = sub(t, 0.42, 0.8)`,然后 `ctx.fillStyle = 'rgba(249, 115, 22, 0.2)'` 走多边形 fill。注意 `globalAlpha` 与 `fillStyle` 的 alpha 是相乘关系——保留这两层,不要合并。

### Layer 6 · 数据多边形 · 描边

| 项 | 值 |
|----|-----|
| 描边 | `#F97316`,`lineWidth = 3`,`lineJoin: 'round'` |
| 不透明度 | `sub(t, 0.42, 0.72)` |
| 路径 | 同 Layer 5 |

### Layer 7 · 描边高光闪一下(爽点)

| 项 | 值 |
|----|-----|
| 时间窗 | `flashT = sub(t, 0.78, 0.95)` |
| 不透明度 | `flashOpacity = Math.sin(flashT * Math.PI) * 0.85`(钟形,中间最亮) |
| 显隐条件 | `flashOpacity > 0.02` |
| 描边 | `#FFFFFF`,`lineWidth = 3`,`lineJoin: 'round'` |
| 路径 | 同 Layer 5(沿数据多边形描一圈白闪) |

### Layer 8 · 数据顶点 elastic 弹出 + 外圈光晕

| 项 | 值 |
|----|-----|
| 时间窗 | `win(i, N, 0.68, 0.14, 0.28)` |
| 弹性进度 | `pop = easeOutElastic(local)` |
| 早退 | `pop <= 0` 跳过 |
| 光晕圆 | `cx, cy = currentPoints[i]`,`r = 9 * pop`,`fill: #F97316`,`opacity = (1 - local) * 0.35`(随时间淡出) |
| 实心圆 | `cx, cy = currentPoints[i]`,`r = 4 * pop`,`fill: #FFFFFF`,`stroke: #F97316`,`lineWidth = 2` |

> 顶点本体半径 4,描边 2 → 视觉直径 8。光晕半径 9 是从顶点向外散开的呼吸效果,光晕随 `local` 走 → 弹到位以后慢慢淡掉。

### Layer 9 · 得分数字滚动

| 项 | 值 |
|----|-----|
| 时间窗 | `win(i, N, 0.52, 0.18, 0.35)` |
| 早退 | `local <= 0` 跳过 |
| 显示值 | `display = Math.round(scores[i] * easeOutCubic(local))`(从 0 滚到目标分) |
| 文字位置 | 沿第 i 条轴,半径 `r = Math.max((scores[i] / 100) * RADIUS - 16, 22)`;**不是固定半径,而是跟随得分**,这样高分数字在顶点附近、低分数字也不会缩到中心 |
| 坐标 | `x = CENTER + r * cos(angle)`,`y = CENTER + r * sin(angle) + 4`(+4 是为了让基线对齐顶点视觉中心) |
| 文字 | `fontSize: 11`,`fontWeight: 900`,`fill: #F97316`,**textAlign: 'center'** |
| 不透明度 | `Math.min(1, local * 2)` |

> Canvas 2D:`ctx.font = '900 11px sans-serif'`;`ctx.textAlign = 'center'`;`ctx.textBaseline = 'alphabetic'`(SVG `<text>` 默认基线)。坐标记得 `Math.round()` 防模糊。

### Layer 10 · 外围维度标签(最后淡入)

| 项 | 值 |
|----|-----|
| 时间窗 | `win(i, N, 0.82, 0.10, 0.16)` |
| 标签锚点 | `getPoint(130, i)`——半径 130(在 RADIUS=90 之外 40px,即网格外圈再向外 40) |
| 文字基线 y | `p.y + 4` |
| **水平对齐(关键)** | 按 x 相对 CENTER 的偏移决定:`p.x < CENTER - 10` → `right`(右对齐,文字往左展开);`p.x > CENTER + 10` → `left`(左对齐,文字往右展开);其余 → `center`。**这是为了避免左右两侧的标签压到雷达图本体** |
| 文字 | `fontSize: 12`,`fontWeight: bold`,`fill: #6B7280` |
| 不透明度 | `local` |

> Canvas 2D 的 `textAlign` 取值对应:`'start' / 'end' / 'left' / 'right' / 'center'`。用 `'left' / 'right' / 'center'` 最稳。

## 6. 完整 Canvas 绘制骨架

```js
function drawFrame(t) {
  ctx.clearRect(0, 0, SIZE, SIZE);

  // —— Layer 1: 网格 ——
  drawGrids(t);

  // —— Layer 2: 轴线 ——
  drawAxes(t);

  // —— Layer 3: 冲击波 ——
  drawShockwave(t);

  // —— 先算 currentPoints,Layer 4-9 都要用 ——
  const currentPoints = computeCurrentPoints(t);

  // —— Layer 4: 拖尾 ——
  drawTrails(t, currentPoints);

  // —— Layer 5: 数据填充 ——
  drawDataFill(t, currentPoints);

  // —— Layer 6: 数据描边 ——
  drawDataStroke(t, currentPoints);

  // —— Layer 7: 高光闪 ——
  drawFlash(t, currentPoints);

  // —— Layer 8: 顶点 ——
  drawDots(t, currentPoints);

  // —— Layer 9: 数字 ——
  drawScores(t);

  // —— Layer 10: 标签 ——
  drawLabels(t);
}
```

每帧结尾记得把 `ctx.globalAlpha = 1`、`ctx.setLineDash([])` 复位,避免污染下一帧。

## 7. 关于颜色——本动画**不**使用动态 colors 数组

⚠️ 上游需求文档(1.2 节)提到当前小程序里有 `colors` 数组按维度动态着色。**本设计稿没有沿用这个机制**,统一使用以下橙色系:

| 用途 | 颜色 |
|------|------|
| 网格 / 轴线 | `#E5E7EB` |
| 冲击波 / 拖尾 / 顶点光晕 / 数据描边 / 数字 | `#F97316`(主橙) |
| 冲击波 / 拖尾 | `#FB923C`(亮橙,比主橙浅一档) |
| 数据填充 | `rgba(249, 115, 22, 0.2)` |
| 顶点本体 | `#FFFFFF` + `#F97316` 边 |
| 高光闪 | `#FFFFFF` |
| 标签文字 | `#6B7280` |

**如果产品方明确要保留 `colors` 数组按维度变色**,改的地方只有:Layer 4 / 5 / 6 / 7 / 8 / 9 中的橙色全部换成 `colors[i]`,Layer 5 的填充改为 `hexAlpha(colors[i], 0.2)`(但这样数据多边形是单色填充——按 *主色 colors[0]* 取还是按 *逐边混合* 处理,这是上游设计决策,不在本文档范围内)。**未经设计方确认前,默认按本文档统一橙色实现。**

## 8. 与结果页 CSS 入场序列的协同

### 8.1 各层动画的归属

| 层 | 动画 | 实现位置 |
|----|------|---------|
| CSS-1 | Emoji + 结果名:从上掉落 | 外层 CSS(小程序 `animation`) |
| CSS-2 | **雷达图容器**:scale 0.5 → 1 | **外层 CSS,保留** |
| CSS-3 | 结果描述卡片:底部滑入 | 外层 CSS |
| CSS-4 | 底部操作按钮:底部滑入 | 外层 CSS |
| Canvas | 雷达图内部 10 层动画 | **Canvas 内部 rAF,独立运行** |

**结论:容器 scale 由 CSS 做,Canvas 内部不重复做整体缩放**。两层并存,因为 Canvas 的 `START_DELAY=450ms` 已经把内部动画推到容器 scale 完成之后,不会打架。

### 8.2 完整时间线表(从页面进入算 0ms)

| 时刻 (ms) | 事件 |
|-----------|------|
| 0 | Emoji 开始掉落(CSS-1, 500ms, `cubic-bezier(0.34, 1.56, 0.64, 1)`) |
| 150 | 雷达图容器开始 scale 0.5 → 1(CSS-2, 600ms, `cubic-bezier(0.34, 1.56, 0.64, 1)`)。**Canvas 此时已开始 rAF 循环,但 `elapsed < 0`,空帧** |
| 300 | 结果描述卡片开始滑入(CSS-3, 400ms, `ease-out`) |
| 450 | 底部按钮开始滑入(CSS-4, 300ms, `ease-out`) |
| 450 | **Canvas 内部动画开始 `t = 0`**(START_DELAY 结束) |
| 500 | Emoji 落定 |
| 700 | 结果描述卡片落定 |
| 750 | 底部按钮落定 |
| 750 | 雷达图容器 scale 落定 |
| 450 + 1900×0.06 ≈ 564 | Layer 1 第 1 圈网格开始弹出 |
| 450 + 1900×0.10 = 640 | Layer 2 第 1 条轴线开始射出 |
| 450 + 1900×0.28 = 982 | Layer 3 冲击波启动 |
| 450 + 1900×0.30 = 1020 | Layer 4/5 第 1 个数据点开始飞射 |
| 450 + 1900×0.42 = 1248 | Layer 5/6 数据多边形开始可见 |
| 450 + 1900×0.52 = 1438 | Layer 9 第 1 个得分数字开始滚动 |
| 450 + 1900×0.68 = 1742 | Layer 8 第 1 个顶点开始弹出 |
| 450 + 1900×0.78 = 1932 | Layer 7 描边高光闪 |

| 450 + 1900×1.00 = 2350 | **Canvas 动画收尾完毕** |

后续元素(描述卡、按钮)的延迟**不需要因为 Canvas 动画长而往后推**——它们是并行的,用户在等数据揭晓的时候,描述卡和按钮已经就位,这是有意为之的"先把 UI 框架搭好,再给数据下高潮"的节奏。

## 9. 移植自检清单

实现完成后,按这个清单逐项对比 Web 端效果:

- [ ] 第 0 个顶点指向正上方(12 点钟)
- [ ] 4 圈网格里只有最外圈是实线,内 3 圈是 `3,3` 虚线
- [ ] 网格从内圈先弹出,外圈后弹出(每圈相差 0.06 × 1900 = 114ms)
- [ ] 轴线像激光从圆心射出去(不是淡入,是几何长度生长)
- [ ] 数据飞射时,每个数据点有一条橙色拖尾从圆心连向当前位置,拖尾呈钟形透明度(中间亮、两端淡)
- [ ] 中心在 ~1000ms 时炸出一发橙色圆环冲击波,半径越出网格外
- [ ] 数据多边形描边封口的瞬间(~1900ms)整圈白色闪一下
- [ ] 数据顶点弹出有 elastic 振荡(不是单调到位,会有 2~3 次小幅回弹)
- [ ] 顶点外圈有 9px 橙色光晕,随时间淡出
- [ ] 得分数字从 0 滚到目标值,位置在该顶点轴线上、距顶点 16px 偏向圆心
- [ ] 左侧标签右对齐、右侧标签左对齐、上下标签居中——切到 8 维时长标签不会压到数据
- [ ] 重新进入页面时动画完整重播,没有跳到终态
- [ ] 切换 3 / 4 / 5 / 6 / 7 / 8 维,节奏感都合理(stagger 步长自适应)

## 10. 常见还原走样 & 排查

| 症状 | 根因 |
|------|------|
| 网格弹出感觉"硬",没有过冲 | `easeOutBack` 的 `c1` 被改成其他值,或者用了 `easeOutCubic` 替代 |
| 数据点直接出现,没有从圆心飞出 | 没读 `currentPoints` 的实时坐标,而是直接用了 `getPoint(score, i)` 终态 |
| 数字滚动跳变(从 0 直接到目标) | 没乘 `easeOutCubic(local)`,或者忘了 `Math.round` |
| 字模糊 / 抖动 | 坐标没 `Math.round`,或者 DPR 没 `ctx.scale` |
| 重新进入页面动画不播 | `startTs` 没重置,或者旧 rAF 没 cancel |
| 维度从 5 改成 8 后,节奏挤成一团 | `frac(i, N)` 没用,把 stagger 步长硬编码成具体毫秒了 |
| 标签压到数据多边形 | Layer 10 的 textAlign 三分支判断没实现,全部用了 `center` |
| 描边高光看不见 | `flashOpacity` 计算公式错,或者高光画在了数据填充之下 |

---

**就这些。每个数字都对得上原稿。出问题先查时间窗参数,再查缓动函数,最后查绘制顺序。**
