    if (this.locked) return

    this.sel = i

编号问题逐条回答
① 选中瞬间是否要独立于 hover 的按压动画？
要。hover-class 在 @click 触发后小程序会立刻撤销 hover 态，松手回弹只有几十毫秒，肉眼几乎看不到"按下确认"的力度。

做法：在 pick() 里临时给选中项加一个 o-confirm class，250ms 后撤掉。这个 class 跑一次 confirmPop keyframes：

.o-inner.o-confirm { animation: confirmPop 0.22s cubic-bezier(0.34, 1.56, 0.64, 1); }
@keyframes confirmPop {
    0%   { transform: scale(0.95); }
    55%  { transform: scale(1.03); }
    100% { transform: scale(1); }
}
② 选中态保持 420ms 期间应该 scale 多少？
scale(1)。按压塌陷 → 经过 confirmPop 的 1.03 微弹 → 回到 1。保持期间是"颜色 + 边框点亮，尺寸恢复"的状态。如果一直保持 0.95 会显得软塌，独立开发者的"贱贱的"调性需要那一下回弹来"嘚瑟一下"。

③ 选项离场要阶梯吗？
要，但不是按"最后选的最后走"，而是从上到下顺序离场（delay 0/30/60/90ms）。原因：用户视线最后停留在选中项，从顶部顺序扫下来视觉上像"翻页"，体验比"以选中项为中心扩散"更利落。题目固定 delay 0，所以题目先动 30ms，建立"翻篇感"。

④ keyframes 里的位移用 px 还是 rpx？
全部 rpx。这是 uni-app 项目，rpx 在小程序里会按设备宽度换算到 px。数值见上表。

⑤ "文字先出 → 选项跟着上"怎么实现？
用 animation-delay，不要用双 :key。双 :key 会引入两套不同步的 DOM 生命周期，容易抖动。

题目 q-txt：animation-delay: 0.06s
选项 4 项：animation-delay: 0.14 / 0.20 / 0.26 / 0.32s
题目比第一个选项早 80ms，视觉上是"题目落定 → 选项跟上"的两段式节奏。

⑥ 叠加窗口我理解对了吗？
理解一半对、做法要改。叠加不是"靠 fill-mode 保持中间帧"——那种依赖 keyframes 中断状态的做法在小程序里不稳定。正确做法是：

新旧 DOM 并存 ~320ms。旧 DOM 进入离场态后，100ms 时把新 DOM 加进来开始入场，等旧 DOM 离场动画播完（220ms）再销毁。窗口内两套 DOM 同时存在。

为了让"叠加"视觉上不混乱，旧 DOM 在离场期间用 pointer-events: none 锁住，且新 DOM 加进来时 position: absolute; inset: 0 叠在同一坑位上——靠 transform 错位避免视觉重合。具体见下面代码。

⑦ :key 重建在叠加方案下还行得通吗？
不行了。:key="'q-' + idx" 是"同一节点 idx 变化 → 旧 DOM 被立刻替换 → 离场动画被截断"。要切换到双槽位（A/B slot）模型：维护 slotA 和 slotB 两套数据，每次切题往空闲槽位放新数据，旧槽位倒计时销毁。

⑧ 双 DOM 并存是必须的吗？
是。这是小程序里实现"叠加切换"唯一可靠的范式。这也是小程序 swiper、各种 Tabbar 切换库底层都在用的思路。

⑨ 两个 animation 同时跑会掉帧吗？
1 个题目 + 4 个选项 = 5 节点的 transform/opacity 同时跑，2 套就是 10 节点。这个量级在 iOS / 中高端安卓上完全无压力。低端安卓（小程序基础库 < 2.10 的红米机型）可能在叠加那 120ms 里掉 1–2 帧，但人眼几乎察觉不到。

降级方案：检测到 wx.getSystemInfoSync().performance 或基础库版本偏低时，把叠加窗口设为 0（即旧题播完再插新题），其他参数不变。不需要降画质。

模板
<view class="stage">
    <block v-for="slot in ['A', 'B']" :key="slot">
        <view v-if="slots[slot].visible"
              class="card"
              :class="slots[slot].phase">  <!-- 'in' | 'out' -->
            <view class="q-wrap">
                <text class="q-txt">{{ slots[slot].q.title }}</text>
            </view>
            <view class="opts">
                <view v-for="(o, i) in slots[slot].q.opts" :key="i"
                      class="o-wrap"
                      hover-class="o-press"
                      :hover-start-time="0"
                      :hover-stay-time="150"
                      @click="pick(slot, i)">
                    <view class="o-inner"
                          :class="{
                              'o-on': slots[slot].sel === i,
                              'o-confirm': slots[slot].confirm === i
                          }"
                          :style="{ '--idx': i }">
                        <text class="o-txt">{{ o.text }}</text>
                    </view>
                </view>
            </view>
        </view>
    </block>
</view>
data 初始化
data() {
    return {
        idx: 0,
        locked: false,
        activeSlot: 'A',
        slots: {
            A: { visible: true,  phase: 'in', q: null, sel: -1, confirm: -1 },
            B: { visible: false, phase: 'in', q: null, sel: -1, confirm: -1 }
        }
    }
}
pick 时序
pick(slot, i) {
    if (this.locked || slot !== this.activeSlot) return
    this.locked = true
    const cur = this.slots[slot]
    cur.sel = i
    cur.confirm = i
    this.ans.push({ /* 略 */ })

    // 220ms 后撤掉 confirmPop 类（避免下次进入时残留）
    setTimeout(() => { cur.confirm = -1 }, 240)

    // 420ms 选中态保持
    setTimeout(() => {
        if (this.idx + 1 >= this.qs.length) { this.goResult(); return }
        this.idx++

        // 旧槽位进入离场
        cur.phase = 'out'

        // 100ms 后新槽位入场（叠加窗口）
        const next = slot === 'A' ? 'B' : 'A'
        setTimeout(() => {
            this.slots[next].q = this.qs[this.idx]
            this.slots[next].sel = -1
            this.slots[next].confirm = -1
            this.slots[next].phase = 'in'
            this.slots[next].visible = true
            this.activeSlot = next

            // 再过 220ms（旧动画播完）销毁旧槽位
            setTimeout(() => {
                cur.visible = false
                this.locked = false
            }, 220)
        }, 100)
    }, 420)
}

关键注意点
.card 必须 position: absolute——两个槽位同坑位，否则离场期间页面高度会塌。给 .stage 一个最小高度（按你设计稿的题目+选项区域算死，比如 min-height: 900rpx）。
will-change: transform, opacity 提前申明合成层，避免叠加 120ms 时低端机首帧卡顿。
hover-class 必须配 :hover-start-time="0" + :hover-stay-time="150"——和你们全局规则一致。
o-confirm 的清除用 240ms（比动画时长 220ms 多 20ms），保证动画完整播完再撤类，避免下次切题进来时残留。
不要用 !important——双槽位 + 类名隔离已经能区分 in/out，!important 会让未来调试变难。
按这套参数和时序，旧题在第 0–220ms 离场，新题在第 100–600ms 入场，叠加窗口 100–220ms（120ms 共存）。整个切题节奏：选中后 420ms 选中态 → 220ms 旧题滑出（中段 120ms 新题已开始上来） → 新题最晚一项 320ms 落定，全流程约 1060ms，节奏紧凑不拖沓。
