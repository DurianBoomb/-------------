# 踩坑记录 · Figma 动画移植到 uni-app

> 2026-05-08 · 搜索页手风琴标签掉落动画

---

## 坑 1：px → rpx 的转换

**Figma 设计稿**：375px 宽度
**uni-app 基准**：750rpx 宽度

**公式**：`rpx = px × (750 / 设计稿宽度)` → 375px 设计稿下 **×2**

| Figma px | 正确 rpx | 错误写法 | 后果 |
|----------|----------|---------|------|
| 40px | 80rpx | 40rpx | 位移只有一半，动画幅度不够 |

## 坑 2：`hover-class` 不能用 `:active`

**错误**：
```css
.press-9 { }
.press-9:active { transform: scale(0.9); }
```

**正确**：
```css
.press-9 { transform: scale(0.9); }  /* 纯 class，不加 :active */
```

**原理**：uni-app 的 `hover-class` 直接往元素上加 class，不是 `:active` 伪类。

**还要补时间参数**：
```html
<view hover-class="press-9" :hover-start-time="0" :hover-stay-time="150">
```

## 坑 3：`transform` 冲突（CSS Animation vs hover-class）

**问题**：`@keyframes` 动画的 `animation-fill-mode: both` 会锁定 `transform` 属性，优先级高于 hover-class 的 `scale()`。按下去时缩放被覆盖，看不到反馈。

**解决**：DOM 结构拆分
```html
<!-- 外层负责按压 -->
<view class="tag-wrapper" hover-class="press-9">
    <!-- 内层负责掉落动画 -->
    <view class="tag-inner" :style="{ animationDelay: '...' }">
```

## 坑 4：微信小程序不支持 `:key` 表达式

**问题**：`<view :key="'grid-' + ci + '-' + refreshId">` 在 WXML 中不会生成 `wx:key`，DOM 不重建。
**log 表现**：控制台报 `[WXML Runtime warning] ... Now you can provide attr wx:key`

**解决**：用 `v-if` 两步重建代替：
```javascript
cat.showGrid = false
this.$nextTick(() => {
    cat.showGrid = true  // DOM 重建 → 动画重新触发
})
```

## 坑 5：动画时序——容器展开 vs 标签掉落

**问题**：容器 `max-height: 0 → 700rpx` 需要 0.3s 过渡。如果标签 0s 就开始掉落，前 0.3s 被 `overflow: hidden` 裁掉。

**解决**：加基础延迟 0.1s，让容器先拉开一点再掉：
```javascript
animationDelay: (0.1 + Math.abs(Math.sin(ti + refreshId * 10)) * 0.4) + 's'
//             ↑ 基础偏移      ↑ 伪随机 0~0.4s 散落
```

## 坑 6：Figma 的参数不要随意简化

Figma 用 `Math.sin()` 生成伪随机延迟，是有意设计的——让标签看起来像自然散落，不是机械排队。
**不要**图省事换成 `ti * 0.08` 这种线性公式，效果差很多。

## 坑 7：`<text>` 不支持 transform

在 uni-app 中 `<text>` 是内联元素，无法应用 `transform` 动画。旋转图标需要用 `<view>` 包裹。

---

**总结**：Figma 的每个参数都有设计意图，移植时逐行对照，不要自作聪明简化。

## 坑 8：scroll-view 的 padding 在小程序中不生效

**现象**：scroll-view 设置了 `padding: 40rpx`，但内部子元素左/右间距不对称，内容整体偏向右侧，底部最后一排元素被截断。

**根因**：微信小程序的 scroll-view 是一个原生滚动容器。它的 **padding 不参与内部内容的布局计算**——内容始终从 `(0,0)` 开始渲染。padding 只是扩大了 scroll-view 的盒模型范围，不改变内容区域。

**修复**：不在 scroll-view 上设 padding，内部套一层容器来扛：

```html
<!-- ❌ 错误 -->
<scroll-view class="body" scroll-y style="padding: 40rpx">
  <view class="tag">内容</view>
</scroll-view>

<!-- ✅ 正确 -->
<scroll-view class="body" scroll-y>
  <view class="body-inner" style="padding: 40rpx">
    <view class="tag">内容</view>
  </view>
</scroll-view>
```

```css
.body { flex: 1; }                    /* scroll-view 自身无 padding */
.body-inner { padding: 40rpx; }       /* 内部容器承担所有间距 */
```

**经验**：微信小程序中，所有使用 scroll-view 的页面，需要间距时一律套内部容器。这与浏览器标准行为不同，是微信小程序特有的渲染差异。
