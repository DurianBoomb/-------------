### 3. 用户校验与数据隔离验收

**背景：** P1.5 开始涉及用户数据（历史记录、收藏、点赞、画像），每新增一个功能都需要确认数据不被其他用户越权访问。

**验收 checklist（逐项核查）：**

| 检查点 | 说明 |
|--------|------|
| ☐ Schema permission | `read` / `create` / `update` 是否配置了 `auth.uid` 规则 |
| ☐ 云函数 auth 守卫 | 涉及用户数据的接口开头有无 `if (!uid) return { errCode: 'AUTH_ERROR' }` |
| ☐ 云函数查询过滤 | 查询是否加了 `where: { userId: uid }` |
| ☐ 客户端无绕行路径 | 前端代码中没有直接 `db.collection('xxx').get()` 读敏感表 |
| ☐ 旧接口回归 | 已接的 `submitAnswer` / `getAnswerHistory` 同上标准 |

**涉及文件：**
- `uniCloud-alipay/database/survey-answers.schema.json` — ✅ 已修复（read 加锁）
- `uniCloud-alipay/cloudfunctions/survey/index.obj.js` — `submitAnswer` + `getAnswerHistory` 已守卫

## P1（新增）广告生成问卷 🔥 最高优先级

### 14. 搜索不到→看广告→Coze 实时生成问卷

**流程：**
```
用户搜索无结果 → 弹窗"要不要看广告生成？"
  → 播放激励视频广告
  → 广告期间 Coze 实时生成问卷
  → 直接跳答题页
```

**已确认：** Coze 只传 `tagName` 即可正常生成，无需 `tagDesc`。

**用户生成问卷的额外细节：**

**标记方式：**
- `survey-tags` 表新增字段 `source: 'system' | 'user'`，`system` 为预置标签，`user` 为用户生成。
- 也可用 `isUserGenerated: true` 布尔字段，选一个就行。

**入口：**
- 搜索页搜索结果底部"看广告定制"卡片点击后，走完广告流程生成的问卷，该标签自动加入"我的定制"列表。
- 个人页或搜索页新增一个"📦 我的定制"入口，点击只展示 `source: 'user'` 的标签列表。

**可见性规则（按时间线）：**

| 阶段 | 可被搜索 | 可被标签池刷新 | 可分享 | 可收藏 | 进历史记录 |
|------|---------|--------------|--------|--------|-----------|
| 刚生成 | ❌ | ❌ | ✅ | ✅ | ✅ |
| 分享 ≥ 200 次 | ✅ | ✅ | ✅ | ✅ | ✅ |

- **分享计数**：`survey-tags` 表新增 `shareCount` 字段，每次分享卡片时 +1。
- **晋升条件**：`shareCount >= 200` 时，云函数将 `source` 改为 `'system'`（或新增 `searchable: true` 字段），使其进入公共搜索池和标签池刷新列表。
- **注意**：晋升后不可逆，避免反复横跳。

**稀有度：**
- 用户生成的问卷晋升为公共标签后，稀有度算法待定。
- 可能的思路：按晋升速度（达到 200 次分享所需天数）决定稀有度，越快越稀有。
- 暂不实现，等标签稀有度系统（#12）稳定后再接入。

**涉及文件：** `survey-tags` 表 schema、`survey/index.obj.js`、搜索页、个人页
