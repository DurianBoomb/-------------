# 后端接入踩坑记录

> 记录时间：2026-05-10
> 场景：将前端 mock 数据切换为 uniCloud 云函数真实数据的过程中遇到的问题

---

## 问题一：云对象（.obj.js）开发环境超时

### 症状

- 前端调用 `importObject('survey').getTagList()` 始终报 `Error: timeout`
- 云函数日志显示查询正常，30ms 内返回了 27 条数据
- 报错信息：`WAServiceMainContext.js:1 Error: timeout`

### 根因

**云对象（.obj.js）通过 WebSocket 通信**，WeChat 开发工具在本地调试模式下，WebSocket 连接跟踪机制不稳定，导致数据已返回但 Promise 仍被 reject。

流程：
```
前端请求 → 云函数处理成功(30ms) → 数据返回 → WebSocket 连接超时 → Promise reject
                                                       ↑ 数据实际到了，但连接先超时了
```

### 修复

将云对象（`.obj.js`）改为普通云函数（`.js`），传输机制从 WebSocket 改为 HTTP：

| 改造项 | 之前（云对象） | 之后（云函数） |
|--------|--------------|--------------|
| 文件名 | `index.obj.js` | `index.js` |
| 导出方式 | `module.exports = { 方法 }` | `exports.main = async (event) => { switch(action) {...} }` |
| 前端调用 | `importObject('survey').方法()` | `callFunction({ name: 'survey', data: { action, params } })` |
| 返回值 | 直接返回对象 | 需 `res.result` 解一层 |

## 问题二：改脚本时删掉了 computed

### 症状

- "精选发疯"正常显示 3 个推荐标签
- "随便逛逛"标签池一片空白
- 控制台无报错

### 根因

全量替换 `<script>` 块时，`computed: { processedTags() { ... } }` 章节整段丢失。模板中的 `v-for="tag in processedTags"` 找不到计算属性，返回 undefined，渲染结果为空。

### 教训

全量替换脚本时，必须逐一核对所有章节：

```
☐ data()         ← 初始化所有响应式数据
☐ computed: {}   ← 计算属性（容易忘！）
☐ onLoad/onShow  ← 生命周期
☐ methods: {}    ← 方法
```

## 问题三：uniCloud 数据库没有 .sort() 方法

### 症状

云函数调用 `getTagList` 时报"用户函数代码语法或逻辑异常"。

### 根因

用了 `.sort({ popularity: -1 })`，但 uniCloud 数据库操作链不支持 `.sort()`，只有 `.orderBy()`：

```javascript
// ❌ 不存在
.sort({ popularity: -1 })

// ✅ 正确写法
.orderBy('popularity', 'desc')
```

### 随机排序方案

需要随机排序时，先用 `.orderBy()` 正常查询，拿到结果后在内存中打乱：

```javascript
const query = tagsCol.where(where).field({...})
const ordered = sortBy === 'random' ? query : query.orderBy('字段', 'desc')
const res = await ordered.get()
if (sortBy === 'random') res.data.sort(() => Math.random() - 0.5)
```

## 问题四：云对象 vs 云函数返回值结构不同

### 症状

数据拿到了但前端解包方式不对，拿不到实际数据。

### 对比

| 调用方式 | 返回值示例 | 数据提取 |
|---------|-----------|---------|
| `importObject('survey').getTagList()` | `{ errCode: 0, data: { list: [...] } }` | 直接使用 `result.errCode` |
| `callFunction({ name: 'survey', data: {...} })` | `{ result: { errCode: 0, data: { list: [...] } } }` | 需 `res.result.errCode` |

### 常见错误

```javascript
// ❌ 云对象 + callFunction 混用
const res = await uniCloud.callFunction({ name: 'survey' })
if (res.errCode === 0)  // 错误！res 是 { result: {...} }，不是 { errCode: ... }

// ✅ 正确
const data = res.result
if (data.errCode === 0)
```

## 经验总结

### 调试优先级

```
云函数日志（uniCloud 控制台）> 前端 console.log > 猜
```

云函数日志能直接看到：
- 函数入口（确认是否被调用）
- 入参（`action` 和 `params`）
- 每条 DB 查询的耗时和结果数
- 异常时的错误堆栈

### 开发环境避坑

1. **WeChat 开发工具 timeout 不代表函数有问题**，必须配合云函数日志判断
2. **每次修改后要删 `unpackage` 缓存**，否则小程序可能跑的是旧版代码
3. **云函数本地调试用 `callFunction` 比 `importObject` 稳定**，生产环境两者都可以
4. **全量替换时逐段核对**，每改完一个 `<script>` 块检查一下 `data/computed/methods/lifecycle` 是否完整

### 推荐的技术选型

| 场景 | 推荐 |
|------|------|
| 简单增删改查 | 普通云函数（`.js`）+ `callFunction` |
| 复杂业务对象 | 云对象（`.obj.js`）+ `importObject` |
| 本地开发调试 | 优先普通云函数 |
| 生产环境 | 两者均可，视场景而定 |

## 问题五：HBuilderX 编译缓存污染，Vue data() 失效

### 症状

- 搜索页 `search.vue` 持续报 `Property or method "categories" is not defined on the instance`
- 但 `categories: []` 确凿定义在 `data()` 中
- 改用 `_loaded` 也报同样错误
- 文件内容完全正确的简单测试（3 个硬编码分类名）也失败
- 添加的 debug 日志（`console.log('[DEBUG] search.vue data() called')`）完全不输出
- 删除 `unpackage` 缓存 + 重启电脑均无效

### 根因

**HBuilderX 的 Vue 文件编译缓存发生不可恢复的损坏。** 具体表现为：

- 编译器内部缓存了该文件路径对应的**旧的 WXML 模板编译产物**
- 即使 `.vue` 源文件被完全重写、甚至删掉重建，编译器仍然使用旧缓存
- 导致模板编译出的 render 函数在运行时找不到 `data()` 中定义的属性
- 访问 `categories` 时 Vue 报"not defined"

**检出条件：**
- 多轮反复修改同一个 `.vue` 文件
- 期间热更新 + 手动停止/运行多次
- 在源文件上反复增删属性名

### 修复

**换文件名。** 这是唯一有效的解决方案：

1. 删除原文件 `search/search.vue`
2. 用新文件名创建 `search/search-page.vue`
3. 更新 `pages.json` 中的 `path` 为 `search/search-page`
4. 更新所有跳转链接（如 `quiz-home.vue` 中的 `navigateTo` 路径）
5. 删 `unpackage` 重新运行

新文件名触发编译器完全重新编译，缓存问题消失。

### 诊断方法

在 `data()` 和脚本顶层加 debug 日志帮助快速定位：

```javascript
<script>
console.log('[DEBUG] xxx.vue module loaded')  // 文件是否被加载
export default {
  data() {
    console.log('[DEBUG] xxx.vue data() called')  // data 是否被执行
    return { ... }
  }
}
```

- **两个日志都不出现** → 文件根本没被编译（大概率缓存污染）
- **module loaded 出现但 data() 不出现** → export 块语法错误
- **两者都出现但属性仍报未定义** → 模板编译层面问题（本案例就是这个）

### 经验

- **不要长时间反复修改同一个 .vue 文件**，如果发现属性定义明确但模板报"not defined"，果断换文件名
- **换文件名比任何缓存清理手段都彻底**（删 unpackage、重启电脑、清除项目缓存都试过，无效）
- 涉及的跳转路径要同步更新：`pages.json`、`navigateTo`、`switchTab` 等
- debug 日志是区分"文件没编译"和"代码有 bug"最直接的手段
