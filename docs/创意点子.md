## 1. 标签稀有度系统

**提出时间**：2026-05-07  
**来源**：先生闲聊时灵光一闪  
**状态**：✅ 已确认，待编码时实现

### 想法
标签池里的每个标签不再随机分配大小和颜色，而是根据**人气值**（答题次数+分享次数加权）划分稀有度等级，在视觉上体现出来。

### 分级

| 等级 | 人气值 | 样式 | 池中比例 |
|------|--------|------|---------|
| 🌟 传说 | 80-100 | 大号 + 橙底 + 深色文字 | 5% |
| ⭐ 稀有 | 50-79 | 标准大小 + 彩色浅底（紫/蓝/绿） | 20% |
| ◻️ 普通 | 0-49 | 白底 + 灰边（空心） | 50% |
| 🔹 默认 | 暂无数据 | 白底 + 无边框 | 25% |

### 设计意义
- 传说级标签激发点击欲望
- 普通级标签给人"发现宝藏"的快感
- 整个标签池更有"内容广场"的感觉

## 2. 搜索缺失 → 广告 → 实时生成

**提出时间**：2026-05-07  
**来源**：先生琢磨搜索页交互时想到  
**状态**：☑️ 已确认设计方向，待编码时实现

### 触发逻辑
用户搜索某个标签 → 题库中无匹配 → 搜索结果区提示"没找到？看广告帮你生成一个专属测试" → 用户点击 → 播放激励视频广告。

### 广告播放期间
前端弹出广告的同时，云端触发 Coze API 根据用户搜索的关键词实时生成一套完整试卷（含维度、结果类型、题目）。广告播放完毕 → Coze 生成完毕 → 弹出结果页。

### ⚠️ 待讨论 · 广告失败的细节处理

广告播放结束但生成失败时，具体怎么收场需要后续想清楚：

- 失败后"再试一次不用看广告"——这个"免费重试"的额度怎么记？本地存储还是云端？
- 如果重试还是失败呢？无限重试还是有上限？
- 广告平台的数据怎么回传（广告已播完但未产出内容，是否影响结算）
- 用户如果多次触发同一个缺失标签的搜索，每次都要看广告吗？要不要加冷却？

**标记原因**：涉及广告变现 + 用户体验 + Coze稳定性三方的平衡，需要等主要功能做完后专门花时间讨论。

### 优化思路（待定）
可改为：先触发 Coze 生成，确认生成启动成功后再播广告。这样广告一旦播完，内容一定是准备好的。但会增加一次请求的等待时间。

### 用户感知
用户觉得："哇这个平台连这个冷门标签都有，太牛了"  
实际是刚生成的，但用户体验上是**无缝的**——他不知道是现做的，只觉得自己搜到了。

### 跟搜索页缺失标签的关系
搜索页缺失标签也是看广告生成，两者逻辑相同，都是搜索页触发的缺失场景。后端共用同一套 Coze 生成服务

## 3. 产品本质定位：用户画像引擎

**提出时间**：2026-05-11 02:34  
**来源**：先生深夜大脑异常活跃，突发奇想  
**状态**：☑️ 已确认，但不动架构，作为后续演进的坐标系

### 核心洞察

剥开所有包装——确诊文学、实体隐喻、烤肠冰箱、社恐等级测试——底层每一个工具都在回答同一个问题：

> **"我是谁？我在别人眼里是什么样的？"**

所以它不是"工具集"，是**自我画像生成器**。

### 全链路画像逻辑

```
search      →  "搜点啥，万一有呢..."     →  找自己
quiz-home   →  浏览标签池               →  "这说的是我吗？"
answer-quiz →  答题                     →  "是的我承认"
result      →  "你被确诊为XX"           →  得到一个身份
```

每步都是用户在确认或发现自己的某种画像。确诊文学的本质就是用好笑的壳装严肃的问题。

### 架构统一语言

| 原概念 | 画像引擎视角 |
|-------|------------|
| 标签 | 画像的入口（"你属于哪个分类"） |
| 维度（dimensions） | 画像的轴（从哪些角度衡量一个人） |
| 题目（questions） | 采样手段（每个轴上采几个数据点） |
| 结果类型（resultTypes） | 画像模板（得分组合对应哪个原型） |

整个架构可以统一命名为"画像引擎"。

### 未来扩展方向（非现在动，是留着日后想）

- **综合画像**：用户答了N份问卷→系统给出一个综合画像。"你这根肠适合放进哪个冰箱里？"
- **跨标签关联**：以前测过"社恐晚期"，现在测"冰箱人格"→结果页说"你最好的保鲜方式是独处"
- **画像演变**：保留历史结果对比，看用户画像是否随时间变化
- **画像沉淀**：同一用户的多个问卷结果可组合成一份"个人画像档案"

### ⚠️ 当前结论：给产品定位提供坐标系，但不急着重构

这个发现的意义：
1. 产品定位一下子清晰了——"工具集"太泛，"画像引擎"才是特异性
2. 为以后做架构决策提供了统一语言
3. 但不影响当前开发节奏，先把手头的烤肠/冰箱做完再说
