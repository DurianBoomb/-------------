# 叙事文本组合设计 — 混合版方案（草稿）

## 一、核心决策：纯扩 vs 混合

| 维度 | A. 纯扩池 | C. 混合版（选定） |
|------|---------|-----------------|
| 核心思路 | 三个池全量扩到 L4 刚好用完，填充基本不触发 | 扩池到合理上限 + 调高填充权重 |
| 审核池 | 36 → **100** | 36 → **80** |
| 质检池 | 63 → **145** | 63 → **120** |
| 推送池 | 32 → **64** | 32 → **55** |
| 池文本总量 | 309 | **255** |
| 需扩量 | 178 条 | **124 条（省 54 条）** |
| 填充间隔 | 2s | **3s**（和审核同节奏） |
| 插入比 | 1:3（每 3 池 + 1 填） | **1:2（每 2 池 + 1 填）** |
| L4 总行数 | ~419 行 | ~383 行 |
| L4 总时间 | ~25 分钟 | **~24.5 分钟** |

---

## 二、为什么纯填充补不上缺口

前提：填充 2s 间隔，池文本平均 ~4s，插入比 1:3。填充贡献的时间权重约 1/7。

L4 需要 ~1481s。砍掉 30% 池文本，填充只能补回不到 5%——缺口巨大。

**结论**：填充文本在保守参数下是"调味料"不是"主菜"。必须拉高填充权重才能让它真正扛时间。

## 四、L3 超额问题

L3 时间超标的根因：填充比例从 1:3 → 1:2 后，L3 也得到了更多的填充文本（202×0.5=101 条），而 L3 的池文本数本来就接近池容量极限。

**方案 A：L4 和 L3 用不同的填充插入比**

| 级别 | 池文本 | 填充插入比 | 填充数量 | 填充间隔 | 总时间 |
|------|--------|-----------|---------|---------|--------|
| L3 | 202 | 1:3 | ~67 | 3s | 963s ≈ 16.1 分钟 ✓ |
| L4 | 255 | 1:2 | ~128 | 3s | 1468s ≈ 24.5 分钟 ✓ |

**方案 B：L3 池文本下调**

将 L3 的 N、M、K 各砍 ~15%，然后用填充补时间，保持 1:2 插入比。需要重新算。

## 五、待定决策

1. **L3 时间超额**：接受（19 分钟）还是调参（16 分钟）？
2. **填充循环感知风险**：30 条填充 L4 循环 ~4.3 次。如果用户认真看，可能注意到重复——但概率很低（刷 383 行没人会对比第 100 行和第 220 行）。接受这个风险吗？
3. **填充间隔 3s vs 2s**：3s 和审核池同节奏更自然，但会让总时间更依赖填充。确认用 3s？
4. **池文本占比**：67% 活人吐槽 vs 33% 系统填充——会不会让老用户觉得"掺水"？目前纯扩方案池文本占比 ~95%。

## 七、叙事文本写作设计 —— 随机拼装下的可信度原则

### 7.1 核心矛盾

文本最终是由终端**随机从池中抽取、随机排列**的。每条吐槽文本在生成时，**不知道前后文是谁**。这就决定了：如果文本之间存在引用、呼应、递进关系，随机排列后必然出现逻辑断裂。

解决方案不是"让排列更聪明"，而是**让每条文本在不知道邻居是谁的前提下，和任何邻居都不打架**。

### 7.2 五条铁律

#### 铁律一：原子化 —— 禁止跨语句引用

每条吐槽文本是一个**闭合的独立观察**。不引用上文、不建立因果链、不假设下文。

```
❌ "刚才那个我也看到了"           → 引用了"刚才"，需要上文存在
❌ "而且这道题还有个隐藏的雷"      → "而且"假设前面有人说了什么
❌ "说到这个我突然想起来…"        → 同上
❌ "同意楼上，我也觉得有问题"      → 直接应答，最坏的类型

✅ "选项分布挺均匀的，没有一边倒"   → 独立陈述，放哪都通顺
✅ "有几道题的措辞稍微啰嗦了点"     → 不依赖上下文
```

审核员之间不对话、不应答。三个审核员各自对问卷发表独立观察，像三个同事在同一个 Slack 频道里**各说各的**，而不是在互相接话。

#### 铁律二：阶段氛围一致，位置无关

同一阶段（审核/质检/推送）内的所有文本，共享同一种语气基调。审核池的文本全部是"快速扫读、第一印象、随口点评"的语感；质检池全部是"坐下来细读、深度思考"的语感。

同阶段内，文本 A 和文本 Z 的语气不打架。**不存在"早期审核"vs"晚期审核"之分**——每条审核文本放在审核阶段的任何位置（第一个、中间、最后一个）都成立。

#### 铁律三：禁止问卷细节指向

这是随机拼装模型下最容易翻车的陷阱。一旦文本指向具体题号、选项措辞、问卷结构，而用户实际提交的问卷没有这些特征，可信度就会瞬间崩塌。

```
❌ "第三题的选项设计有问题"       → 假设了题号
❌ "这个量表用了Likert五点计分"   → 假设了量表类型
❌ "多选题的互斥逻辑没做好"       → 假设了题目类型
❌ "第三题的'其他'选项有人真填了'我想回家'"  → 双重灾难：假设了选项+假设了填写行为
❌ "填'我想回家'的那位，你是被辅导员抓来的吗" → 更糟：还引用了上文

✅ "有几道题的选项梯度拉得不错"   → 模糊评价，什么问卷都适用
✅ "标题写得挺有意思"             → 对标题的通用评价
✅ "选项整体没什么毛病，四平八稳"   → 不假设结构
```

**原则**：所有评价指向问卷的**感觉、整体印象、通用维度**（标题好坏、题量、措辞风格、填答体验），不指向具体结构。

#### 铁律四：角色性格固定但不建立关系

每个角色有固定的人设（审核员A毒舌、审核员B温和、审核员C挑剔……），但角色之间**不建立对话关系**。每个人对着问卷自言自语。

这条的关键：
- 角色性格是**叙事风格的锚点**，让文本池整体有性格层次
- 但不关系化——一旦A和B开始对话，"A的文本在B的文本之前"就成了隐含假设

#### 铁律五：系统填充文本天然适配随机排列

`[系统]` 类填充文本（"正在交叉比对…""含梗量校准…""选项逻辑校验中…"）本身就不带个性、不参与对话、不评价问卷内容。它插在任何位置都不违和——是随机拼装模型下的天然胶水。

### 7.3 修正后的参考片段（约20条）

演示吐槽文本（骨）和系统文本（肉）的穿插节奏，同时全部遵守五条铁律。

```
[系统] ════ 排队等候 ════
[系统] 你的问卷已进入处理队列
[系统] 正在分配处理节点... 节点已就绪

[审核] ════ 内容审核 ════

审核员A：标题起得还行，至少不是那种一眼劝退的类型
[系统] 标题合规标记：PASS
审核员B：选项整体没什么毛病，四平八稳
审核员A：有几道题的措辞稍微啰嗦了点，但不影响理解
[系统] 选项逻辑校验中… 无冲突项
审核员C：整体内容质量过关，没什么敏感的东西
审核员B：属于那种不会出错的问卷，稳的
审核员A：快速扫了一遍，感觉作废不了
[系统] 内容审核阶段标记：通过

[审核] 审核意见记录完毕

[质检] ════ 质量检测 ════

质检员M：有几道题我觉得填的人会认真想一想
质检员K：题量控制得不错，不至于让人中途跑路
[系统] 填答时长预估中… 基准值 4.2 分钟
```

**为什么这个片段能通过随机排列测试？**

| 测试 | 验证 |
|------|------|
| 任意打乱审核员A/B/C的文本顺序 | 每条独立观察，不引用前文，不打架 |
| 在任意位置插入系统填充行 | 系统文本不参与对话，插哪都不违和 |
| 删除任意一条吐槽文本 | 不产生断裂——没有链条需要它支撑 |
| 将片段中的问卷替换为任意问卷 | 所有评价都是通用维度，不会指向不存在的结构 |
| 审核员和质检员文本混合排列 | 语气不同（审核快/质检慢），但无逻辑冲突 |

### 7.4 三个审核员的叙事设计

这是我实际写作中涌现的设计——不只是"三个角色轮流发言"，而是：

**形式上**：审核员A、B、C 各自有独立人设（一个偏毒舌直评，一个偏温和审视，一个偏挑剔严苛），为文本池注入性格层次。

**结构上**：他们之间不对话。三人各自对着同一份问卷发表**独立的、不互相引用的**第一印象。读者感受到的是"三个有性格的人各自在审核这份问卷"，而不是"三个人在开会讨论"。

**效果上**：
- 比单审核员多了**性格层次的丰富感**——同一份问卷被三个不同性格的人从不同角度打量
- 比"对话模式"多了**随机拼装的安全性**——不对话就没有引用链，没有引用链就不会断
- 三个人的文本可以任意数量、任意顺序排列，始终成立

这个设计同时解决了"单调"和"安全"两个问题。

### 7.5 片段的理论特征分析

以 7.3 参考片段为对象，从叙事理论角度逐层解剖其有效性来源。

---

#### 7.5.1 双声部正交复调

片段运行着两条**互相平行、互不交叠**的叙事声部：

| 声部 | 载体 | 特征 |
|------|------|------|
| 人声声部 | 审核员/质检员吐槽 | 主观、有性格、口语化、评价性 |
| 系统声部 | `[系统]` 填充行 | 客观、机械化、去个性化、过程性 |

两条声部交替出现，但**从不互相应答**。系统不说"审核员说得对"，审核员不说"系统检测到啥了"——它们运行在同一时间轴上，但分属两个互不感知的信号频道。

这不是巴赫金意义上的"复调"（复调强调不同意识之间的对话和冲突），而是**正交复调**：两个声部互为垂直维度，各自独立推进，读者在自己的认知中完成两者的并置。系统声部提供前进感（线性时间），人声声部提供纵深（多角度观察），合在一起产生一种"在真正运行的系统中有人在说话"的错觉。

#### 7.5.2 骨架-血肉-呼吸三层结构

片段中存在三种功能截然不同的文本类型：

```
[═══ 排队等候 ═══]          ← 结构骨架：零叙事内容，纯建筑功能
[你的问卷已进入处理队列]      ← 呼吸间隙：叙事节奏调节，无评价
审核员A：标题起得还行...      ← 叙事血肉：主观评价，携带个性
```

| 层级 | 标签特征 | 叙事功能 | 时间属性 |
|------|----------|----------|----------|
| 骨架 | `═══ XXXX ═══` | 标记阶段边界，类似乐章间的终止式 | 固定 2s，不参与随机 |
| 血肉 | `角色名：内容` | 携带观点、性格、态度 | 审核 3s / 质检 5s，随机抽取 |
| 呼吸 | `[系统] 内容` | 模拟后台运算，制造自然间隔 | 2-3s，循环填充 |

这种三分结构解决了一个关键问题：纯血肉文本连续排列会产生"这不可能是真实聊天，真人不会这样不间断地说话"的虚假感。**呼吸层的存在不是因为时间不够需要填充——而是因为真实沟通天然有间隔，去掉间隔就等于宣告"这是假的"。**

#### 7.5.3 指示抽象化 —— 可信度的来源恰恰是"不说具体"

片段中所有评价都使用了**系统性模糊指代**：

```
"有几道题的措辞稍微啰嗦了点"
"属于那种不会出错的问卷"
"整体内容质量过关"
"标题起得还行，至少不是那种一眼劝退的类型"
```

从语用学角度看，这些表达**刻意违反了格莱斯合作原则中的"量准则"**（使你的话语如所要求的那样信息充分）。正常沟通中人们倾向于精确——题号、选项、具体问题。这里却主动模糊化。

**但这恰恰是可信度的来源**。在随机拼装模型中：

- 精确表述 = 可证伪表述。一旦文本声称"第三题有问题"而用户问卷根本没有第三题的对应结构，信任瞬间崩塌。
- 模糊表述 = 不可证伪表述。"有几道题措辞啰嗦"在任何问卷中都可能成立——因为总有可以被认为"啰嗦"的题，也总有可以不被认为啰嗦的题。这是一种**全称适用的评价壳**。

这不是语言学上的"偷懒"，而是在不确定问卷结构的约束下，**唯一一种可以保证逻辑成立的评价策略**。

#### 7.5.4 单人独白 × 多视角 = 阅读者的群聊幻觉

片段中审核员A、B、C 各自只对着问卷说话，互相不应答：

```
审核员A：标题起得还行...        ← 独白，对象是问卷
审核员B：选项整体没什么毛病...   ← 独白，对象是问卷
审核员A：有几道题的措辞...       ← 独白，对象是问卷
```

但读者体验到的却是"多个人在从不同角度看同一份问卷"——一种群聊感。

这个效果的机制是：

1. **对象同一性**（所有人都在看同一份问卷）→ 观众自动将不同视角并置对比
2. **角色标记**（A/B/C）→ 激活读者对"多人参与"的认知图式
3. **读者端的完形加工** → 读者自己在脑中把独立独白缝合为多声部对话

**群聊感是读者端涌现的属性，不是文本端的结构属性。** 这个区分至关重要——因为文本端没有对话结构，所以随机排列不破坏任何东西；但读者端会自己产生群聊幻觉，所以读感丰富。

电影类比：这不是对话场景（双人正反打），而是**反应镜头蒙太奇**——A 看问卷（切）、B 看问卷（切）、C 看问卷（切）。观众自己把这些独立镜头合成为一个完整的"评审现场"。

#### 7.5.5 时间双螺旋 —— 进程感与纵深感的并置

系统中每一条都在推进过程状态：

```
"正在分配处理节点... 节点已就绪"  → 状态跃迁
"标题合规标记：PASS"              → 判定产出
"选项逻辑校验中… 无冲突项"        → 校验完成
"内容审核阶段标记：通过"          → 阶段闭合
```

这是**水平时间轴**——从进入→排队→审核→通过，线性不可逆。

而吐槽文本完全不参与这个时间线。审核员A的"标题起得还行"放在审核阶段的第1条或最后1条，对过程状态没有任何改变——它提供的是**垂直纵深**。

两条轴交织形成的不是单线叙事，而是**时间双螺旋**：

```
时间 →
系统：排队→分配→审核中→PASS→校验→通过→记录完毕
      ｜    ｜     ｜      ｜    ｜    ｜
吐槽：     A评标题  B评选项  A评措辞 C评整体 B评稳健 A总结
```

系统轴让读者知道"事情在往前走"，吐槽轴让读者"在每个时间点都有东西可看"。两者独立运作，合在一起远比单一维度有沉浸感。

#### 7.5.6 阈下世界建构 —— 不写世界观，但是世界在

片段从未用任何一句话描述"审核系统的组织架构"或"工作流程"。但以下信息全部通过**指向隐含世界的指示词**自然传递：

| 文本片段 | 暗示的世界信息 |
|----------|---------------|
| "排队等候" | 存在队列机制，有并发处理 |
| "分配处理节点" | 存在分布式基础设施 |
| "审核员A/B/C" | 存在人类审核团队，有角色分工 |
| "PASS" / "通过" | 存在判定标准和审批流程 |
| "审核意见记录完毕" | 存在归档制度 |
| "质检员M/K" | 审核和质检是两个独立部门 |

这是托尔金所说的"深度感"（the sense of depth）——读者感受到文本背后有一个比他看到的更大的世界，不是因为文本描述了那个世界，而是因为文本以那个世界为不言自明的前提在说话。什么都不解释，反而最可信——因为真实世界的内部沟通从来不需要向参与者解释组织架构。

#### 7.5.7 总结：可信度的六层模型

将以上分析归纳为一个分层模型，从上到下每一层都在为"终端看起来像真的"贡献一个维度：

```
层级 6：阈下世界建构      → "这背后有一套机制在运转"
层级 5：时间双螺旋        → "事情在往前走，而且有东西可看"
层级 4：读者端群聊幻觉    → "多个人在认真看我的问卷"
层级 3：指示抽象化        → "他们说的东西我的问卷确实可能有"
层级 2：骨架-血肉-呼吸    → "这节奏像真实的异步沟通"
层级 1：正交复调          → "两条独立频道，合在一起很丰富"
```

这六层中，1-3 是**生成时就写死在文本结构里的**（通过原子化、模糊指代、双声部交替），4 是**读者认知加工的涌现属性**（文本不主动制造，但文本创造条件让它发生），5-6 是**系统运作在阅读过程中逐渐展现的**（累积效应而非单条效应）。

## 八、AI 生成提示词指南 —— 教其他 AI 生成此类文本

### 8.1 角色设定

```
你是"终端叙事吐槽文本生成器"。你的任务是生成问卷审核/质检/推送阶段中，
由虚构的审核员、质检员、推送员说出的吐槽文本，以及穿插其间的系统填充文本。

你的生成模型：每条文本是独立的原子单元，最终会放入一个文本池中，
由终端随机抽取并随机排列。因此你的每一条输出都必须满足：
"在不知道前后文是谁的前提下，和任何邻居都不打架。"
```

### 8.2 审核池生成指令

```
【审核池 · 文本生成规范】

阶段定位：内容审核——快速扫读、第一印象、随口点评
节奏参数：每条 3 秒，语气轻快
角色池：审核员A（毒舌直评）、审核员B（温和审视）、审核员C（挑剔严苛）

生成规则：
1. 每条文本是一个完整的、独立的槽点或评价。不需要前文铺垫，不需要后文承接。
2. 禁止引用其他审核员的发言。不说"刚才那个""同意""我也觉得"。
3. 禁止指具体题号。用"有几道题""选项方面""整体来看"这类模糊指代。
4. 禁止描述问卷的具体结构（量表类型、题型、选项措辞）。
5. 允许的评价维度：标题吸引力、题量感受、措辞风格、是否有明显漏洞、整体"过得去/过不去"的判断。
6. 三个角色的性格分布在整批生成中要均匀，不要某个角色的文本明显多于其他角色。
7. 标签格式："审核员A：文本内容" / "审核员B：文本内容" / "审核员C：文本内容"

禁止清单：
- ❌ 引用任何题号（"第一题""第三题的选项"）
- ❌ 假设题型（"这个多选题""那个量表"）
- ❌ 描述填写者行为（"有人填了""填表的人会…"）
- ❌ 对话性标记（"我也""而且""说到这个"）
- ❌ 假设审核在讨论中（"同意""不同意""补充一点"）

合格示例：
✅ 审核员A：标题写得还行，至少看完想点进去
✅ 审核员B：整体结构没什么大毛病，中规中矩
✅ 审核员C：有几道题的措辞能再打磨一下就好了
✅ 审核员A：扫了一遍，没有发现劝退点
✅ 审核员B：属于正常发挥的问卷，给过
✅ 审核员C：选项安排得挺清楚，不至于让人困惑

不合格示例：
❌ 审核员A：第三题的选项有问题              → 指了题号
❌ 审核员B：同意楼上的观点，我也觉得          → 对话引用
❌ 审核员C：这个Likert量表设计得还行          → 假设题型
❌ 审核员A：刚才你说到标题，我补充一个点       → 上下文依赖
```

### 8.3 质检池生成指令

```
【质检池 · 文本生成规范】

阶段定位：质量检测——细读深思、深度评价、被戳中或没被戳中
节奏参数：每条 5 秒，语气沉稳
角色池：质检员M（严谨认真）、质检员K（感性直觉）、质检员N（数据思维）

生成规则：
1. 同审核池的原子化原则，所有规则一致。
2. 质检的语调比审核更深一层：审核是"能不能用"，质检是"好不好用、填的人会不会认真填"。
3. 允许的评价维度：题目质量深度、逻辑流畅度、填答体验预估、题量是否合理、有没有让人想中途放弃的隐患点。
4. 可以比审核文本更"走心"——质检员是真正在替未来的填写者感受这份问卷。
5. 标签格式："质检员M：文本内容" / "质检员K：文本内容" / "质检员N：文本内容"

禁止清单 = 审核池禁止清单（全域适用）

合格示例：
✅ 质检员M：有几道题我觉得填的人会停下来好好想一想
✅ 质检员K：题量控制得不错，不会让人觉得填不完
✅ 质检员N：整体逻辑是顺的，从易到难的递进感有
✅ 质检员M：没有发现那种让人想跳过的题
✅ 质检员K：有些题的措辞，能感觉到出题人是花了心思的
```

### 8.4 推送池生成指令

```
【推送池 · 文本生成规范】

阶段定位：推送分发——匹配投放渠道、预估传播效果
节奏参数：每条 4 秒，语气带有运营视角
角色池：推送员P（精准匹配）、推送员Q（传播达人）、推送员R（风险控制）

生成规则：
1. 同审核/质检的原子化原则。
2. 推送视角是"这份问卷推给谁最适合、怎么推效果好"。
3. 允许的评价维度：目标人群匹配度、传播潜力、渠道适配、是否有容易被截胡的风险点。
4. 可以带一点运营语境下的点评——"这只问卷的受众其实挺明确的"。
5. 标签格式："推送员P：文本内容" / "推送员Q：文本内容" / "推送员R：文本内容"

合格示例：
✅ 推送员P：受众画像挺清晰的，不需要额外筛选
✅ 推送员Q：标题传播性还行，但转发峰值可能不会太高
✅ 推送员R：没什么争议性内容，投放风险低
```

### 8.5 系统填充文本生成指令

```
【系统填充 · 文本生成规范】

定位：穿插在吐槽之间的背景噪声，模拟系统后台运算
节奏参数：每条 2-3 秒
标签格式："[系统] 文本内容"

生成规则：
1. 不参与任何对话，不带任何个性，纯系统腔。
2. 内容方向：数据校验、算法运行、合规检查、进度汇报。
3. 枯燥但不假——要有技术感但不能太科幻。
4. 可以适当加点微小的技术细节（"含梗量 0.74""方差 1.83"），这些数值不追求真实意义。

合格示例：
✅ [系统] 正在交叉比对选项逻辑…
✅ [系统] 含梗量预计算中… 当前阈值 0.62
✅ [系统] 选项离散度校验完成，方差 1.83
✅ [系统] 内容合规标记：PASS
✅ [系统] 填答时长预估中… 基准值 4.2 分钟

不合格示例：
❌ [系统] 检测到政治敏感词            → 不能出现"政治"二字
❌ [系统] 第三题存在逻辑矛盾          → 指向了具体题号
```

### 8.6 生成质量自检清单

批量生成后，对每条文本逐条检查：

- [ ] 删除前后所有邻居，这句话还通顺吗？
- [ ] 这句话假设了问卷有任何特定的结构特征吗？（题型、题号、量表类型）
- [ ] 这句话和别人对话了吗？（"也""而且""同意""刚才"）
- [ ] 这句话中出现了"政治"二字吗？（零容忍）
- [ ] 这句话放到同阶段的任何位置（第一个/中间/最后一个）都成立吗？

全部通过，才能入池。
