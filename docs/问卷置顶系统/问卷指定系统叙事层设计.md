# 问卷置顶系统·叙事层设计

> 置顶系统不仅仅是一套技术架构，它同时构建了一个完整的虚构世界观。用户在置顶过程中的所有交互——从点击广告到收到战绩单——都被包裹在这个世界观里。本文档定义这个虚构世界的所有叙事元素。

---

## 1. 世界观总览

### 1.1 核心设定

置顶系统的叙事层基于两个虚构机构，形成完整的用户旅程闭环：

| 环节 | 虚构机构 | 角色 | 视觉风格 |
|------|---------|------|---------|
| 置顶前 | **系统监控中心** | 处理问卷的终端系统 | 黑底绿字，等宽字体终端 |
| 置顶后 | **15分钟名气管理局** | 签发名人档案的发证机构 | 白底黑字红章，公文档案 |

**叙事主线**：用户请求置顶 → 监控中心接收并处理（候场区）→ 加入置顶池曝光 → 名气管理局签发名人档案（战绩单）。同一套语言体系，同一个虚构世界观，首尾呼应。

### 1.2 用户旅程

```
看广告 → 进入监控终端处理（可截图） → 进入置顶池 → 15分钟后收到名人档案（可截图分享）
                                  ↓
                      两个传播节点，两次社交货币
```

### 1.3 设计原则

- 保持一致的公文语气和冷峻荒诞感
- 所有数据数值经过艺术加工，档案末尾附免责声明
- 不做虚假数字承诺（如"超越了 XX 人"）
- 底层技术逻辑与叙事层分离，叙事层仅影响文案和视觉

## 2. 候场区——系统监控终端

### 2.1 设定

候场区被包装为一个虚构的"系统监控终端"界面。用户提交置顶请求后，进入一个黑底绿字的等宽字体终端屏幕，旁观系统对自己的问卷进行"含梗量检测""舆情预测""推送分发"等一本正经的荒诞处理。

每一行滚动的日志就是进度本身——日志滚完意味着处理完毕，问卷进入置顶池。

对内，候场区是一个不维护全局真实队列顺序的"黑盒"表演系统。用户看到的排队人数、跳过人数、处理阶段均由算法基于其个人状态参数实时生成，不与任何真实队列精确挂钩。

### 2.2 日志阶段与内容

候场进度分为四个阶段，依次推进：

#### queuing（排队中）

```
[系统] 当前置顶池已满，你已进入候场区
[系统] 预计等待时间：约一首歌的时间
[系统] 你可以等待自然入场，或者看广告加速（最多3次）
[系统] 已进入候场区，正在排队...
[系统] 你的问卷已进入处理队列
[系统] 当前队列状态：等待分配处理节点
```

#### inspecting（质检中）

```
[系统] 正在对问卷进行质量检测...
[质检] 含梗量检测：通过 ✓
[质检] 内容合规性审查：通过 ✓
[质检] 趣味指数评估：优秀
```

#### pushing（推送中）

```
[系统] 正在推送至推荐系统...
[推送] 分配初始曝光权重...
[推送] 加入候选推荐列表 ✓
```

#### ready（就绪）

```
[系统] → 你的问卷已进入置顶池，开始曝光！
[系统] 你将收到本次曝光战绩单，敬请查收
```

### 2.3 广告加速的日志叙事

用户点击加速按钮后，日志中插入 VIP 加速日志，随后快速推进：

```
[VIP] 检测到加速请求，正在开启绿色通道...
[VIP] 绿色通道已开启，正在加速处理你的问卷...
```

第三次加速必定完成，显示：

```
[系统] → 你的问卷已进入置顶池，开始曝光！
```

**设计原则**：MVP 阶段不展示具体跳过人数（避免假数字被质疑），后续可扩展为基于操作频率的生成算法。

### 2.4 助力推广场景的候场提示

| 视角 | 文案 |
|------|------|
| **推广者** 自己置顶 | "你的问卷正在排队..." |
| **推广者** 助力推广 | "你推广的问卷正在排队..." |
| **问卷所有者** 被他人推广 | "你的问卷正在排队..."（与主动置顶一致，无需感知推广者） |

### 2.5 新人绿色通道动画

**占位 UI**：亮绿色虚线框，居中文字"🟢 小绿人进场动画 · 待设计"。触发逻辑：曝光资历 Lv.0 的用户看完广告后直接入池，展示约 1-2 秒的绿色通道动画作为入池确认反馈。

## 3. 战绩单——15分钟名气管理局档案

### 3.1 设定

战绩单是置顶体验的情绪闭环，由虚构机构"**15分钟名气管理局**"颁发。用户在 15 分钟置顶结束时，收到一份正经到离谱的官方档案——用公文格式认证了用户在过去 15 分钟内"被看见"的事实。

### 3.2 档案弹窗

| 元素 | 内容 |
|------|------|
| 弹窗标题 | "15分钟名气管理局" |
| 档案摘要 | 荣誉称号 + 核心数据精简版 |
| 操作按钮 | "查看档案" → 跳转档案详情页 |
| 关闭选项 | 可关闭弹窗 |
| 多未读 | 当前档案关闭后自动弹出下一条 |

### 3.3 分享长图（竖版公文档案式）

**视觉风格**：
- 模拟"终端打印出来的红头文件"：白底或暖白底，黑色正文，红色公章，等宽字体标题
- 纸质纹理/轻微做旧感
- 与候场区黑底绿字的终端界面形成视觉反差（屏幕里的系统 vs 屏幕里吐出的纸质文件）

**自上而下的布局**：

1. **机构抬头**：`15分钟名气管理局 · 临时名人档案`（红头文件风格）
2. **档案编号**：`ZW-年份-序号`（如 ZW-2026-01847）
3. **发证日期与有效期**："发证日期：2026年5月16日 23:14" / "有效期：本档案自签发之日起永久有效"
4. **档案主体信息**：用户昵称、本次身份（如"纯正淀粉肠"）、身份照片位（emoji 展示位）
5. **鉴定正文**："经本局鉴定，上述人员在 [时间段] 期间，因发布问卷《[问卷标题]》而获得以下注视："
6. **三项核心数据**："驻足注视 XXXX 人次 / 好奇打开 XXXX 人次 / 决定存档 XX 人次"
7. **荣誉称号**："基于以上数据，本局授予以下荣誉：🏅 [荣誉称号]"
8. **授予理由**（简短一句话）
9. **档案附注**（系统点评）
10. **底部公章**："15分钟名气管理局 档案专用"
11. **小程序码 + 引导文案**："扫码生成你的15分钟名人档案"

### 3.4 战绩单文案区分（二期·助力功能）

| 场景 | 标题 |
|------|------|
| 自己置顶 | "你的置顶战绩" |
| 助力推广 | "你的推广战绩" |

## 4. 数据产品化命名

原始技术数据在上层以文绉绉的公文用语呈现：

| 原术语 | 档案用词 |
|--------|---------|
| 曝光量 | **驻足注视** |
| 点击量 | **好奇打开** |
| 收藏量 | **决定存档** |
| 趣味头衔 | **荣誉称号** |
| 一句话评价 | **档案附注（系统点评）** |
| 数据暴击 | **破格授予（罕见荣誉）** |

### 4.1 数据一致性原则

三项数据须始终满足：
- 好奇打开 ≤ 驻足注视
- 决定存档 ≤ 好奇打开
- 所有数值为正整数，有零有整（如 2847 而非 2800）

### 4.2 数据暴击（破格授予）

- **触发概率**：约 15%（新人略高）
- **效果**：选中一个数据维度（优先驻足注视），乘以 1.5~2 倍
- **联动**：暴击触发后荣誉称号和附注同步升级，使用"破格授予"类措辞
- **视觉**：历史档案列表中暴击记录底色微亮，附"破格授予"标注

## 7. 历史档案页叙事

### 7.1 视觉风格

延续名气管理局的公文档案美学，偏向"档案室查阅"的体验：
- 整体色调沉稳，暖白底，深色文字
- 列表项模拟档案盒标签或卷宗封面样式
- 主标签展示问卷标题 + 累计置顶次数，像档案盒脊背上的标签
- 子标签展示签发日期 + 荣誉称号 + 核心数据，像卷宗目录

### 7.2 特殊标记

| 标记 | 条件 | 视觉 |
|------|------|------|
| **首秀** | `careerNumber === 1` | 微弱角标或金色小圆点 |
| **破格授予** | 触发数据暴击 | 底色微亮或标题加粗 |
| **推广** | `pinType === 'promote'`（二期新增） | 蓝色标签 |

### 7.3 置顶生涯综述卡片

以"名气管理局档案室"的口吻呈现：

> 本档案室共收录置顶记录：XX 次
> 累计驻足注视：XX 人次
> 累计好奇打开：XX 人次
> 累计决定存档：XX 人次
> 获得最多荣誉称号类型：XX
>
> 一句话综述：
> "你的问卷累计被世界注视过 XX 次，相当于一场小型演唱会的观众人数。本局对此表示认可。"

### 7.4 空状态

> "本档案室暂无你的记录。看个广告，让你的问卷被世界看见，生成第一份名人档案。"

## 9. 附：数据生成规则（叙事层视角）

### careerNumber（认证次数）

`careerNumber = senioritySnapshot + 1`。使用入池时的资历快照值，**不可用**实时 `exposureCount`（防止多问卷并发时计数错误）。`careerNumber === 1` 即"首次认证"。

### archiveNumber（档案编号）

格式 `ZW-年份-序号`（如 ZW-2026-01847），由全局计数器 `careerArchiveSeq` 自增生成，仅用于展示，不参与业务逻辑。

### 反向补偿在叙事层的体现

| 资历档位 | 叙事表现 |
|---------|---------|
| Lv.0（新人） | 数据浮动取上限概率高，荣誉称号更容易匹配稀有版本，有首秀专属称号 |
| Lv.1~Lv.2（偶发者/常客） | 正常数据浮动区间 |
| Lv.3（老面孔） | 数据浮动偏下行，逆向激励探索"新玩法"的真实感受 |
