## 一、背景

问卷数据库中有个 `status` 字段，最初来源于 Coze 问卷生成流程的状态报告字段。上线后它一直"活着但没用"：

- 所有导入的问卷默认写 `"active"`，从未被改为 `"disabled"`
- 没有任何业务逻辑读取它来做过滤
- 唯一引用它的 `getSurveyByTag` 传入 `status: 'active'`，但因为全部都是 active，这个条件纯属冗余
- 还因此建了两个索引（`tagName_status`、`status_create_date`），白白占用索引空间

说人话：一个从 Coze 泄露进来的字段，从未真正使用过，一直在吃资源。

## 四、踩坑记录

### 坑 1：PowerShell 正则替换不一致

第一批清理 `surveys.init_data.json` 时，PowerShell 的 `-replace` 操作符在部分文件上处理了但结果异常（编码问题）。后来改用 **Node.js 写脚本** 处理所有文件，一次性搞定。

**教训**：在 Windows 环境下处理包含中文的 JSON 文件，优先用 Node.js 而非 PowerShell 做正则替换，避免编码/转义不一致。

### 坑 2：存在两组数据文件

一开始以为数据文件只有 `上传到服务器/` 里的 8 个批次，先生提醒后发现 `database/surveys_batches/` 下还有 16+ 个 ndjson 文件也需要清理。这批文件的格式是 ndjson（每行一个 JSON 对象），正则替换逻辑一样，但需要确认路径覆盖完整。

**教训**：清理前先跑一遍 `grep -r "status"` 确认所有残留位置，再列计划。这次是先生提示才补上了第二批，下次应该自己先搜全。

### 坑 3：`01_标签全部.json` 有同名不同义的 status

`01_标签全部.json` 也有 `"status": "published"` / `"draft"`，看起来和问卷的 `status` 长一个样，但语义完全不同——那是标签的发布状态，是真正的业务字段。清理时不能一刀切替换。

验证环节排查后确认没误伤，只删了问卷文件中的 `"status":"active"` / `"status":"success"`。

## 五、经验沉淀

### 1. 数据模型中的"僵尸字段"要尽早识别

一个字段如果满足以下条件，就要警惕了：
- 所有记录的值都一样（全员 "active"）
- 没有逻辑把它改成其他值
- 业务代码没有条件分支依赖它
- 但它在数据库里占了一列，还建了索引

这种字段越早清理越好，拖久了只会让后续接手的人迷惑："status 到底是干嘛用的？"

### 2. Coze 集成要做好字段隔离

本次 `status` 字段的来源是 Coze 问卷生成流程的内部状态报告。它在导入时应该被彻底剥离干净——实际上 `importSurveys` 有 `{ _status, _error, prompt_version, ...record }` 的解构剥离，但 `_status` 剥离后又被重新赋值为 `status`，相当于"从后门又放了进来"。

以后在 Coze 导入流程中，所有以 `_` 开头的字段（Coze 内部字段）应该直接丢弃，不能再映射到业务字段。

### 3. 文件的排查顺序要系统化

清理涉及的文件分布比较广（代码 + schema + init_data + 多组数据文件），如果按"想到一个改一个"的方式做，很容易漏。这次的做法——先 grep 搜全、列计划、按优先级执行——是正确的节奏，以后大范围数据清理保持这个流程。

### 4. 先生的角色

清理中间先生提醒了 `surveys_batches/` 目录下还有文件需要处理。他的"全貌记忆"比我强——他知道所有数据文件都在哪，这是长期维护积累的直觉。我的角色是在知道范围后把执行干透、不留尾巴。

## 六、收益量化

| 指标 | 清理前 | 清理后 |
|------|--------|--------|
| schema 字段数 | 20+ 含 status | 不再有 status |
| 索引数 | 含 2 个无用索引 | 不含 status 相关索引 |
| 数据文件冗余字段 | 每条有 status | 零残留 |
| 代码复杂度 | `status: 'active'` 冗余条件 + 默认赋值 | 干净 |
| 新人理解成本 | "status 是干嘛的？" | 不用问这个问题 |

清理 `status` 本身不会让小程序跑得更快（数据量小，索引差异可忽略），但它让数据模型 **干净了、正确了**。以后任何人看 schema 不会对着 status 发愣，这就是收益。
