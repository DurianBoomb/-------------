# 雷达图优化方案

## 问题

问卷题目数量少（每个维度 3 道题），raw 数据容易出现极端值（0 或 100），直接画雷达图形态怪异。

## 解决思路

**真实数据只用来匹配结果类型，匹配完后用一套"好看"的假数据画雷达图。**

这是个游戏，可以"造假"。

## 造假数据的三个要求

1. **好看**：大部分数据在 40%-70%，符合正态分布，小部分可在此范围外
2. **准确**：结果类型对应的维度得分最高，且至少比其他维度高 20 个百分点
3. **稳定**：同一种结果类型 + 相近的 raw 得分，每次造假数据尽量一致

## 新 goResult() 流程

```
1. 算 raw（0-100）
2. raw → 匹配结果类型
3. raw + 结果类型 → 生成种子 → 造假数据
4. 造假数据 → 雷达图展示（scores 变量）
5. raw → 数据库存真实分（dimensionScores 字段改为 raw）
```

## 种子设计

### 种子构成

```
种子字符串 = 结果类型name + raw加权和分桶编号
```

### 分桶

raw 的 5 个维度取值 0-100，加权和范围 0-500，每 20 一档：

```
分桶编号 = floor(加权和 / 20)
```

最多 25 个桶。同一结果类型下，大部分人的加权和会落在相邻几个桶内。

### 为什么用分桶而不是直接 hash(raw)

- 完全相同的 raw → 完全相同的雷达图（太死板，没解释空间）
- 分桶后：同桶内 raw 不同但雷达图相同，不同桶有细微差异（3-5%）
- 对外解释："做题时的反应速度也会纳入考量"

### 示例

```
用户 A：结果"社交达人"，raw = [82, 35, 60, 28, 70]，加权和 = 275，分桶 = 13
种子字符串 = "社交达人_13"
哈希 → 1849203875

用户 B：结果"社交达人"，raw = [78, 40, 55, 32, 72]，加权和 = 277，分桶 = 13
种子字符串 = "社交达人_13"  ← 相同
哈希 → 1849203875           ← 相同
雷达图完全相同

用户 C：结果"社交达人"，raw = [50, 20, 40, 15, 30]，加权和 = 155，分桶 = 7
种子字符串 = "社交达人_7"   ← 不同
哈希 → 73829104             ← 不同
雷达图形状相似但细节有 3-5% 差异
```

## 造假数据生成算法

### 完整流程

```javascript
generateFakeScores(raw, resultType, dims) {
  // 1. 构建种子
  const rawSum = raw.reduce((a, b) => a + b, 0)
  const bucket = Math.floor(rawSum / 20)
  const seedStr = resultType.name + '_' + bucket
  const seed = hashString(seedStr) // 字符串哈希为 32 位整数

  // 2. 用种子初始化伪随机数生成器
  const rng = createSeededRNG(seed)

  // 3. 生成 5 个维度的正态分布初始值
  //    ~N(55, 12), clamp [20, 70]
  const fake = dims.map(() => {
    const val = boxMuller(rng, 55, 12)
    return Math.max(20, Math.min(70, Math.round(val)))
  })

  // 4. 确定主维度（match 字段对应的维度索引）
  const mainIdx = dims.indexOf(resultType.match)

  // 5. 用种子 + 主维度标记生成 75-85 的主维度值
  const mainRng = createSeededRNG(seed ^ 0x5A77) // XOR 偏移确保独立序列
  const mainVal = 75 + Math.floor(mainRng() * 11) // 75-85

  // 6. 设置主维度
  fake[mainIdx] = mainVal

  // 7. 修正：确保主维度至少比其他人高 20
  const threshold = mainVal - 20
  for (let i = 0; i < fake.length; i++) {
    if (i !== mainIdx && fake[i] >= threshold) {
      fake[i] = threshold - 1
    }
  }

  // 8. 兜底：如果主维度不是最高的（理论上不会，但防守）
  const maxOther = Math.max(...fake.filter((_, i) => i !== mainIdx))
  if (fake[mainIdx] <= maxOther) {
    fake[mainIdx] = maxOther + 21
  }

  return fake
}
```

### 步骤说明

| 步骤 | 说明 |
|------|------|
| 1-2 | 种子 → 确定性随机数生成器 |
| 3 | 正态分布生成初值，大部分在 40-70 |
| 4 | 从 resultType.match 拿主维度 |
| 5 | 主维度固定 75-85，保证突出 |
| 6-7 | 替换主维度 + 压超标项 |
| 8 | 兜底检查 |

### 效果

- 雷达图：四个维度在 40-70 自然分布，一个维度在 75-85 突出
- 同一结果类型 + 同一分桶：完全相同的雷达图
- 同一结果类型 + 不同分桶：形状相似，细微差异

### 种子确定性实现

```javascript
// 简单的字符串哈希（djb2 算法）
hashString(str) {
  let hash = 5381
  for (let i = 0; i < str.length; i++) {
    hash = ((hash << 5) + hash + str.charCodeAt(i)) | 0
  }
  return hash >>> 0
}

// 基于种子的简易 PRNG（mulberry32 算法）
createSeededRNG(seed) {
  let s = seed | 0
  return function() {
    s |= 0
    s = s + 0x6D2B79F5 | 0
    let t = Math.imul(s ^ s >>> 15, 1 | s)
    t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t
    return ((t ^ t >>> 14) >>> 0) / 4294967296
  }
}

// Box-Muller 正态分布生成
boxMuller(rng, mean, stddev) {
  let u1, u2
  do { u1 = rng() } while (u1 === 0)
  u2 = rng()
  const z = Math.sqrt(-2 * Math.log(u1)) * Math.cos(2 * Math.PI * u2)
  return mean + z * stddev
}
```

## 现有 raw 计算公式详解

```javascript
// answer-quiz.vue line 613
const raw = dims.map(d => cnts[d] ? ((sums[d] / cnts[d] - 1) / 2) * 100 : 50)
```

### 分步拆解

| 步骤 | 公式 | 值域 | 说明 |
|------|------|------|------|
| 单题得分 | `score ∈ {1, 2, 3}` | 1-3 | 每个维度 3 道题 |
| 维度总和 | `sums[d] = score1 + score2 + score3` | 3-9 | |
| 维度均分 | `avg = sums[d] / cnts[d]` | 1-3 | cnts[d] 固定为 3 |
| 归一化 | `normalized = (avg - 1) / 2` | 0-1 | 线性映射 |
| 放大 | `raw = normalized * 100` | 0-100 | |

### 为什么选这个归一化方式

`(avg - 1) / 2 * 100` 将 1-3 的均值**线性映射**到 0-100：

- avg=1 → raw=0（全选"绝非如此"）
- avg=2 → raw=50（中间值）
- avg=3 → raw=100（全选"被看穿了"）

这是线性变换，不改变排名关系。即使用 sum(3-9) 直接比大小，结果也一样。

### 极值问题

因为每个维度只有 3 道题，离散度极大：

- 全选 1 → raw=0（掉到 0 底）
- 全选 3 → raw=100（顶到天花板）
- 两题 3 + 一题 2 → raw≈91.7
- 一题 3 + 两题 2 → raw≈83.3

raw 数组常见的形态：`[0, 50, 100, 16.7, 83.3]`，雷达图上呈现为尖锐的三角刺，毫无美感。

## 统计学分析：N(55, 12) 的选择理由

### 正态分布参数

使用正态分布 `~N(55, 12)` 生成非主维度的假数据，理由如下：

| 参数 | 值 | 理由 |
|------|-----|------|
| 均值 μ | 55 | 在 40-70 区间中心偏上，视觉上"饱满" |
| 标准差 σ | 12 | 68% 数据落在 [43, 67]，95% 落在 [31, 79] |

### 68-95-99.7 规则下的分布

```
μ = 55, σ = 12

±1σ (68%):  [43, 67]   ← 大部分数据在这，内部区域
±2σ (95%):  [31, 79]   ← 几乎全部，偶尔出界
±3σ (99.7%): [19, 91]  ← 理论范围，但被 clamp [20, 70] 截断
```

### clamp [20, 70] 的影响

clamp 主要截断 ±2σ 以外的尾部分布（约 5% 的概率会被截断）：

- 低于 20 的概率：`P(X < 20)` ≈ 0.002（几乎不会出现）
- 高于 70 的概率：`P(X > 70)` ≈ 0.106（约 11% 会被压低到 70）

这意味着约 **11% 的非主维度会触及 clamp 上限 70**，视觉上表现为偶尔有几个维度接近但不超过 70，增加了自然感。

### 主维度 75-85 与 clamp 70 的关系

```
主维度 [75, 85] vs 其他维度最大值 70

gap_min = 75 - 70 = 5   ← 如果其他维度全被 clamp 到 70，差异仅 5%
gap_max = 85 - 20 = 65  ← 如果其他维度全在 20，差异 65%
期望 gap = 80 - 55 = 25  ← 正常情况
```

实际运行时步骤 7 的修正机制（`threshold = mainVal - 20`）保证 gap 始终 ≥ 20，所以视觉上主维度会明显突出。

## 分桶粒度深入分析

### 为什么选 20

| 分桶宽度 | 桶数 (0-500) | 同一结果类型下可能的桶数 | 效果 |
|----------|-------------|------------------------|------|
| 10 | 50 | ~15 个桶 | 差异太多，不稳定 |
| **20** | **25** | **~6-8 个桶** | **平衡稳定性和变化** |
| 50 | 10 | ~2-3 个桶 | 过于死板 |

raw 每维度 5 种可能（0, 16.7, 33.3, 50, 66.7, 83.3, 91.7, 100），5 个维度加权和通常集中在 150-350，20 一档在此范围内产生约 10 个桶，同一结果类型实际使用 6-8 个。

### 分桶对主维度的影响

分桶只决定种子，主维度值 75-85 是独立序列生成的（`seed ^ 0x5A77`）。但同一结果类型下，不同分桶的主维度会不同，这是预期行为——毕竟加权和不同，说明答题特征确实有差异。

## PRNG 算法选择：mulberry32

### 为什么不用 Math.random()

`Math.random()` 不可设置种子，每次调用不可复现，无法保证"同一结果类型 → 相同雷达图"。

### mulberry32 的特点

```javascript
createSeededRNG(seed) {
  let s = seed | 0
  return function() {
    s |= 0; s = s + 0x6D2B79F5 | 0
    let t = Math.imul(s ^ s >>> 15, 1 | s)
    t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t
    return ((t ^ t >>> 14) >>> 0) / 4294967296
  }
}
```

| 特性 | 值 |
|------|-----|
| 周期 | 2^32（约 43 亿次调用） |
| 输出范围 | [0, 1) |
| 均匀性 | 通过 PractRand 测试 |
| 性能 | 每个数 ~15 次位运算，无浮点除法 |
| 状态大小 | 仅一个 32 位整数 |

32 位种子完全够用：分桶编号最大 25，结果类型名哈希到 32 位后组合，碰撞概率可忽略。

### 为什么主维度用独立序列（seed ^ 0x5A77）

如果不偏移，主维度值会和非主维度共享同一个 rng 序列。虽然代码顺序是先消费非主维度再消费主维度，但耦合了序列消费顺序。用 XOR 偏移可以独立生成主维度序列，更清晰也不容易因为代码顺序变动而出 bug。

`0x5A77` 无特殊含义，仅是任意一个非零常量，确保主维度序列与非主维度序列不同。

## djb2 哈希算法详解

```javascript
hashString(str) {
  let hash = 5381
  for (let i = 0; i < str.length; i++) {
    hash = ((hash << 5) + hash + str.charCodeAt(i)) | 0
  }
  return hash >>> 0
}
```

### 选择理由

| 需求 | djb2 表现 |
|------|----------|
| 相同输入 → 相同输出 | ✓ 确定性 |
| 输入微小变化 → 输出巨大变化 | ✓ 雪崩效应好 |
| 性能 | O(n)，仅位移+加法，极快 |
| JS 兼容 | |0 模拟 32 位溢出，>>>0 转无符号 |
| 分布均匀 | ✓ 广泛验证 |

### 种子字符串格式

```
"社交达人_13"
```

- 结果类型名不同 → hash 完全不同（雪崩效应）
- 分桶编号不同 → hash 完全不同
- 同类型同分桶 → hash 完全一致

## 数据流全链路

```
答题页 answer-quiz.vue
  │
  ├─[用户答题] → ans[] 累积
  │
  ├─[最后一题确认] → goResult()
  │    │
  │    ├─ raw = 每个维度的 (avg-1)/2*100 → [0-100] × 5
  │    │
  │    ├─ topDim = raw 最大值所在的维度
  │    │
  │    ├─ result = survey.resultTypes.find(match === topDim)
  │    │
  │    ├─ scores = generateFakeScores(raw, result, dims)
  │    │      │
  │    │      └─ 种子(result.name + rawSumBucket)
  │    │           └─ 假雷达图数据 [20-70]×4 + [75-85]×1
  │    │
  │    ├─ dimensionScores = raw（真实分，存数据库）
  │    │
  │    ├─ submitAnswer({ dimensionScores, ... })
  │    │
  │    └─ redirectTo → result.vue
  │         │
  │         ├─ scores → 雷达图渲染
  │         └─ rname/rdesc/emoji → 结果卡片
  │
  └─[数据库] dimensionScores 字段存的是 raw（真实分）
```

### 关键：数据库存什么

| 字段 | 旧值 | 新值 | 理由 |
|------|------|------|------|
| `dimensionScores` | raw + 随机抖动 | raw（纯真实分） | 后续数据分析需要真实值 |
| 雷达图展示 | raw + 随机抖动 | fakeScores | 用户只看假数据 |

## 边界情况

| 边界 | 处理方式 |
|------|---------|
| rawSum = 0（全选 1） | bucket = 0，种子 = "结果名_0"，正常生成 |
| rawSum = 500（全选 3） | bucket = 25，种子 = "结果名_25"，正常生成 |
| dims.length ≠ 5 | 代码逻辑通用，不依赖固定数量 |
| resultType.match 不在 dims 中 | `indexOf` 返回 -1，`fake[-1] = mainVal` 添加新属性 → 应加防御：`if (mainIdx === -1) return dims.map(() => 50)` |
| 多个维度同时为最高分（同分） | `reduce` 取第一个，不影响结果（任意一个最高即可） |
| 旧数据兼容 | 数据库已有记录的 `dimensionScores` 是旧格式（带抖动），新产生的记录是 pure raw。分析时需标记区分或全量迁移 |
