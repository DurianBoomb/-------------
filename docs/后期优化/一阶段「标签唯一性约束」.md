# 一阶段：标签唯一性约束

> 规则：**严格禁止同名标签**，1 个标签名 = 1 个问卷。不再允许随机抽选。
>
> 当前 `getSurveyByTag` 遇到同名标签时用 `Math.random()` 随机选一个。这本质上是数据脏了之后的补丁——正确做法是不让它脏。

---

## 改动范围

| # | 文件 | 改动 |
|---|------|------|
| 1 | 数据迁移 | 查 `surveys` 中是否存在重复 `tagName`，有则手动清理 |
| 2 | `uniCloud-alipay/database/surveys.schema.json` | `tagName` 加 `"unique": true` 索引 |
| 3 | `uniCloud-alipay/cloudfunctions/survey/index.obj.js` | `generateFromCoze` 入库前加同名检查：同用户 → 放行（删旧建新），其他用户 → 返回 `TAG_ALREADY_EXISTS` |
| 4 | 同上 | `getSurveyByTag` 改为 `findOne`，删除 `Math.random` 随机逻辑 |
| 5 | `pages-tools/search/search-page.vue` | 生成回调新增 `TAG_ALREADY_EXISTS` 的 Modal |
| 6 | `pages-tools/survey-preview/survey-preview.vue` | 重新生成回调新增 `TAG_ALREADY_EXISTS` 的 Modal |

**执行顺序**：步骤 1（查重清理）→ 步骤 2（加唯一索引）→ 步骤 3~6（代码改动）。

---

## 步骤 1：数据迁移

在 uniCloud 控制台或通过云函数执行：

```javascript
// 查重复 tagName
const db = uniCloud.database()
const res = await db.collection('surveys').aggregate()
  .group({ _id: '$tagName', count: { $sum: 1 }, ids: { $addToSet: '$_id' } })
  .match({ count: { $gt: 1 } })
  .end()
```

如果有多条同名记录，手动决定保留哪条（建议保留 `create_date` 最早的），删除其余。

如果当前无重复数据，直接跳过步骤 1。

## 步骤 2：Schema 加唯一索引

**`uniCloud-alipay/database/surveys.schema.json`** — 在 `indexes` 数组中新增：

```json
{
  "name": "tagName_unique",
  "unique": true,
  "fields": [
    {
      "name": "tagName",
      "direction": "asc"
    }
  ]
}
```

完整 `indexes` 数组最终为：

```json
"indexes": [
  { "name": "creatorId", "fields": [{ "name": "creatorId", "direction": "asc" }] },
  { "name": "tagName_unique", "unique": true, "fields": [{ "name": "tagName", "direction": "asc" }] }
]
```

## 步骤 3：`generateFromCoze` 加入同名检查

**文件**：`uniCloud-alipay/cloudfunctions/survey/index.obj.js`
**位置**：`generateFromCoze` 方法中，在 `validateQuestionnaire` 通过之后、`surveysCol.add` 之前（当前第 501 行附近）。

**当前代码**（第 494-508 行）：
```javascript
const cleaned = deepTrim(questionnaire)
const validation = validateQuestionnaire(cleaned, tagName)
if (!validation.valid) {
  console.error('[generateFromCoze] 校验失败, errors:', JSON.stringify(validation.errors))
  console.error('[generateFromCoze] cleaned:', JSON.stringify(cleaned).slice(0, 1500))
  return { errCode: 'VALIDATE_ERROR', errMsg: 'AI 生成的内容格式有误，请修改标签名后重试', data: { errors: validation.errors } }
}

const surveyRes = await surveysCol.add({
  tagName, tagDesc: tagDesc || '',
  title: cleaned.title, dims: cleaned.dims,
  qs: cleaned.qs, resultTypes: cleaned.resultTypes,
  creatorId: uid, source: 'coze',
  status: 'active', create_date: Date.now()
})
```

**改为**（含「同用户重新生成」逻辑）：

```javascript
const cleaned = deepTrim(questionnaire)
const validation = validateQuestionnaire(cleaned, tagName)
if (!validation.valid) {
  console.error('[generateFromCoze] 校验失败, errors:', JSON.stringify(validation.errors))
  console.error('[generateFromCoze] cleaned:', JSON.stringify(cleaned).slice(0, 1500))
  return { errCode: 'VALIDATE_ERROR', errMsg: 'AI 生成的内容格式有误，请修改标签名后重试', data: { errors: validation.errors } }
}

// 检查标签名是否已被占用
const existing = await surveysCol.where({ tagName }).limit(1).get()
if (existing.data && existing.data.length > 0) {
  const existingSurvey = existing.data[0]
  // 同用户重新生成 → 先删旧再建新（放行）
  if (existingSurvey.creatorId === uid) {
    await surveysCol.doc(existingSurvey._id).remove()
    console.log('[generateFromCoze] 重新生成，已删除旧问卷:', existingSurvey._id)
    // 继续往下走
  } else {
    // 已被其他用户占用 → 拒绝
    return { errCode: 'TAG_ALREADY_EXISTS', errMsg: '该标签已存在问卷，请换一个标签名' }
  }
}

const surveyRes = await surveysCol.add({
  tagName, tagDesc: tagDesc || '',
  title: cleaned.title, dims: cleaned.dims,
  qs: cleaned.qs, resultTypes: cleaned.resultTypes,
  creatorId: uid, source: 'coze',
  status: 'active', create_date: Date.now()
})
```

> **为什么需要「同用户放行」逻辑？** `survey-preview.vue` 的「重新生成」按钮会用相同的 `tagName` 再次调用 `generateFromCoze`。如果不做放行，唯一性约束会阻止用户重新生成自己的问卷。同用户 = 允许覆盖（先删后建），其他用户 = 拒绝。

**并发竞态说明**：云函数层面检查与数据库插入之间存在 TOCTOU 窗口。唯一索引（步骤 2）是最终防线——即使两个请求同时通过应用层检查，数据库也会因唯一索引而拒绝第二个插入。应用层检查的作用是提供明确的错误码和用户提示，避免让用户看到数据库抛出的原始异常。

## 步骤 4：`getSurveyByTag` 改为 `findOne`

**文件**：`uniCloud-alipay/cloudfunctions/survey/index.obj.js`
**位置**：`getSurveyByTag` 方法（当前第 413-432 行）。

**当前代码**：
```javascript
async getSurveyByTag(params) {
  if (!params || !params.tagName) {
    return { errCode: 'PARAM_ERROR', errMsg: '标签名不能为空' }
  }
  try {
    const res = await surveysCol.where({
      tagName: params.tagName
    }).get()

    const list = res.data || []
    if (list.length === 0) {
      return { errCode: 'NOT_FOUND', errMsg: '未找到该标签的问卷' }
    }

    const survey = list[Math.floor(Math.random() * list.length)]
    return { errCode: 0, data: survey }
  } catch (e) {
    return { errCode: 'DB_ERROR', errMsg: '问卷查询失败' }
  }
},
```

**改为**：

```javascript
async getSurveyByTag(params) {
  if (!params || !params.tagName) {
    return { errCode: 'PARAM_ERROR', errMsg: '标签名不能为空' }
  }
  try {
    const res = await surveysCol.where({
      tagName: params.tagName
    }).limit(1).get()

    const list = res.data || []
    if (list.length === 0) {
      return { errCode: 'NOT_FOUND', errMsg: '未找到该标签的问卷' }
    }

    // 标签唯一性约束下，至多一条记录，直接取第一条
    return { errCode: 0, data: list[0] }
  } catch (e) {
    return { errCode: 'DB_ERROR', errMsg: '问卷查询失败' }
  }
},
```

改动点：
- 删掉 `Math.floor(Math.random() * list.length)` 随机逻辑
- 添加 `.limit(1)` 优化查询
- `list[0]` 直接取第一条（等于唯一一条）

## 附带清理 & 注意事项

### `findExistingTags` 死代码

`index.obj.js` 第 97-100 行有一个 `findExistingTags` 辅助函数，它查的是 `survey-tags`（标签目录）而非 `surveys`（问卷表），且**从未被任何方法调用**。

实施步骤 3 时有两个选择：
- **删除它**（推荐）：唯一性检查逻辑直接在 `generateFromCoze` 内用 `surveysCol.where({ tagName }).limit(1).get()` 即可，不需要这个辅助函数。
- **改造成 `isTagNameTaken`**：如果觉得复用价值大，可以改成查 `surveys` 并返回布尔值。但就一行查询而言，内联足够清晰。

### `importSurveys` 不受影响

管理员的 `importSurveys` 方法（第 364-389 行）也是逐条 `surveysCol.add`，无去重检查。但加了唯一索引后，导入重复 `tagName` 时数据库会直接报错。因为这是管理员工具，不需要前置检查——等数据库抛异常即可。

### `answer-quiz.vue` 的调用方

`getSurveyByTag` 的唯一前端调用方是 `pages-tools/answer-quiz/answer-quiz.vue`（第 571 行）：
```javascript
const res = await survey.getSurveyByTag({ tagName: this.tag })
```
改为 `list[0]`（即唯一一条）后，行为完全兼容，不需要改动前端代码。

### 标签名的大小写问题

当前 `tagName` 是原始字符串，无统一处理。"ABC" 和 "abc" 会被视为两个不同标签。如果后续发现这是个问题，可以在入库前统一 `.toLowerCase()`。现阶段不处理，属于产品决策而非技术缺陷。

---

## 验收标准

- `surveys.tagName` 存在唯一索引，尝试插入重复 tagName 时报错
- 生成问卷时使用已存在的标签名 → 返回 `TAG_ALREADY_EXISTS`
- 前端两个页面（搜索页、预览页）收到 `TAG_ALREADY_EXISTS` 时弹出 Modal 提示
- `getSurveyByTag` 返回确定的一份问卷，不再随机
- 阶段二的热度计数（likeSurvey/dislikeSurvey/shareCount 等）可安全依赖 "一个 tagName = 一个 surveyId"
