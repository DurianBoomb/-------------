## 阶段三：核心逻辑（2 小时）

**前置依赖**：阶段二完成

### 3.1 热度算法

| # | 文件 | 改动内容 |
|---|------|----------|
| 1 | `uniCloud-alipay/cloudfunctions/survey/index.obj.js` | 新增 `computeHeat({ surveyId })`：读取 5 个计数字段 → 加权求和 → 更新 `totalHeat` + 检测稀有度升级 |
| 2 | `uniCloud-alipay/cloudfunctions/survey/index.obj.js` | 新增 `computeDailyHeat()`：遍历所有问卷，`dailyHeat = 当天各指标增量 × 权重` |
| 3 | `uniCloud-alipay/cloudfunctions/survey/index.obj.js` | 新增 `getDailyHotSurveys({ limit })`：按 `dailyHeat` 降序取前 N |

**公式**：
```
totalHeat = shareCount×1.0 + likeCount×0.5 + clickCount×0.3 + favCount×0.4 - dislikeCount×0.2
dailyHeat = dailyShareCount×1.0 + dailyLikeCount×0.5 + dailyClickCount×0.3 + dailyFavCount×0.4 - dailyDislikeCount×0.2
```
- 结果不低于 0
- 每次任一热度指标变更后调用 `computeHeat`
- `computeDailyHeat` 由定时任务每日 00:00 触发

- 根据当前稀有度找下一级阈值

## 风险备忘

| 风险 | 影响 | 应对 |
|------|------|------|
| `computeDailyHeat` 定时任务触发机制未定 | 阶段三阻塞 | 先用 `unifiedId` 定时触发，后续再优化 |
| 每日热度增量需要存储「当日增量」还是「全量差值」 | 方案选择影响数据库设计 | 建议用**全量计数字段 + 每日零点快照**：每日零点记录各字段快照值，`dailyHeat` = 当前值 - 快照值，加权计算 |
| HBuilderX 热更新缓存问题 | 调试耗时 | 每次改动后删 `unpackage` 再运行 |
