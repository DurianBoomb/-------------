## 三、云函数单元测试

### 3.1 `recordClick`

| # | 场景 | 操作 | 预期 |
|---|------|------|------|
| 1 | 首次点击（当日无答题记录） | 调用 `recordClick({ surveyId })` | 返回 `{ counted: true }`，`surveys.clickCount +1`，`dailyClickCount +1` |
| 2 | 重复点击（当日已有答题记录） | 同一个用户再调用一次 | 返回 `{ counted: false }`，计数不再增加 |
| 3 | 跨日点击（隔天答题后点击） | 新的一天调用 | 返回 `{ counted: true }`，计数各 +1 |
| 4 | 匿名用户（无 token） | 不传 token 调用 | fire-and-forget 场景，不应报错阻塞；不计入计数 |

### 3.2 `recordShare`

| # | 场景 | 操作 | 预期 |
|---|------|------|------|
| 1 | 首次分享 | 调用 `recordShare({ surveyId })` | `shareCount +1`，`dailyShareCount +1` |
| 2 | shareCount < 100 | 分享到第 50 次 | 不触发公开逻辑 |
| 3 | shareCount 达到 100 | 分享推进到 100 | 自动在 `survey-tags` 创建/更新记录，rarity ≥ handmade1 |
| 4 | shareCount 达到 100 且 tags 已有 handmade1+ | 再次触发 | 不降级 rarity，不重复创建 |
| 5 | shareCount 超过 100（101+） | 继续分享 | 计数正常递增，不重复触发公开逻辑 |

### 3.3 `likeSurvey` / `dislikeSurvey`

| # | 场景 | 操作 | 预期 |
|---|------|------|------|
| 1 | 首次点赞 | 调用 `likeSurvey` | `hasLiked: true`，`likeCount +1`，`dailyLikeCount +1` |
| 2 | 再次点赞（取消） | 调用 `likeSurvey` | `hasLiked: false`，`likeCount -1` |
| 3 | 先点踩再点赞（切换） | dislike → like | `hasLiked: true`，`likeCount +1`，`dislikeCount -1`，daily 同步 |
| 4 | 先点赞再点踩（切换） | like → dislike | `hasDisliked: true`，`dislikeCount +1`，`likeCount -1` |
| 5 | 切换后再点踩（取消） | dislike → 取消 | `hasDisliked: false`，`dislikeCount -1` |
| 6 | 并发竞态（快速连点） | 连续调用 3 次 likeSurvey | 最终状态正确（不出现计数为负或重复计数） |

### 3.4 `toggleFavoriteSurvey`

| # | 场景 | 操作 | 预期 |
|---|------|------|------|
| 1 | 首次收藏 | 调用 `toggleFavoriteSurvey` | `favorited: true`，`favCount +1`，`dailyFavCount +1` |
| 2 | 取消收藏 | 再调用一次 | `favorited: false`，`favCount -1` |
| 3 | 重复收藏 | 收藏后再次收藏 | 切换为取消，`favCount -1` |

### 3.5 `getSurveyDetail` 扩展

| # | 场景 | 预期 |
|---|------|------|
| 1 | 已登录用户查询 | 返回 `likeCount`/`dislikeCount`/`clickCount`/`favCount`/`shareCount` + `hasLiked`/`hasDisliked`/`hasFavorited` |
| 2 | 未登录用户查询 | 计数正常返回，用户状态字段为 `false`/`null` |

## 五、端到端完整流程

按以下顺序走一遍完整用户路径：

```
用户A 进入首页 → 点击某个问卷标签
    → 答题页加载（触发 recordClick，clickCount +1）
    → 答完所有题 → 跳转结果页
    → 查看结果 → 点👍（likeCount +1）
    → 点收藏（favCount +1）
    → 点击分享（shareCount +1，微信分享）
    → 用户B 通过分享链接进入
    → 答题页加载（触发 recordClick，clickCount +1）
    → 答完 → 结果页 → 点👎（dislikeCount +1）
```

确认：两个用户的操作在数据库层面计数各自独立、不互相覆盖。

## 六、数据完整性检查

| # | 检查项 | 方法 |
|---|--------|------|
| 1 | 总量与日量一致性 | `dailyLikeCount` ≤ `likeCount`（因为只能增） |
| 2 | 收藏与 fav-records 一致性 | `favCount` 应等于 `survey-fav-records` 中对应 `surveyId` 的文档数 |
| 3 | 点赞/点踩互斥 | 同一用户对同一问卷，`survey-heat-records` 中应只有 0 或 1 条记录 |
| 4 | 负数检查 | 所有计数字段不能为负（取消操作的边界） |
